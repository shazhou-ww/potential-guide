# 数据域事件序号与查询 Revision

本契约统一事件顺序、查询水位与订阅续读位置，避免查询和实时观察之间遗漏变化。

关联 [职责入口](../task-engine-responsibilities.md)：B1–B5、C1–C5 的查询与订阅，以及 A1、A2 产生的变更。

## 事件序号

1. revision 标识数据域内的一条事件记录；所有已接纳事件使用统一、唯一、严格递增的序号，跨 Engine 重启延续。
2. 序号允许有缺口，不依赖墙钟时间；具体编码另定。
3. 公布水位 R 后，不得再提交 revision 小于或等于 R 的新事件。
4. TaskEvent、RunEvent 及集合概况事件均携带对应的 revision；同一事实在不同观察入口的表达不重复分配新序号。
5. eligible、timeout 的时间推算不产生事件，也不推进 revision。

## 事件事实与派生状态

1. 事件记录是事实来源；Task 状态根据相关事件及时间边界计算，不是另一份需要事务性更新的权威状态。
2. 一条 Run 事件可以改变多个 Task 的计算结果，不为每个受影响 Task 再生成事实事件或分配 revision。
3. 状态缓存仅用于加速计算，应与其覆盖的事件水位一致；不能以缓存更新代替事件事实。
4. 集合的加入、摘要更新和移出是事件的派生输出，不是额外的数据域事实记录。

## 查询水位

1. 状态查询返回快照及 revision，二者来自同一事实边界。
2. 集合查询返回整轮冻结视图的 revision，各续页保持相同水位；空集合也有 revision。
3. 查询 revision 表示已覆盖的数据域事件位置，不是单个实体最近一次变更的时间或编号。
4. 查询结果的时间派生状态按观察时间计算，不用 revision 代替当前时间。

## 保留与恢复

1. revision 跟踪不要求永久保存每个查询快照，但补读需要保留事件及重建变更前后筛选结果与摘要所需的信息。
2. 仅保留计数器不能恢复历史；无法补齐时明确报告过期或缺失，不能跳到最新位置。
3. revision 只在所属数据域内有意义，不跨域续读。
