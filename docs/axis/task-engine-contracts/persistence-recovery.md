# 持久化与重启后的行为

本契约约束实例更换前后的事实与处理连续性，避免重启丢失已受理 Task、改变时间约定或自动重演未知副作用。

关联 [职责入口](../task-engine-responsibilities.md)：operations A1、A2 的已生效承诺，以及 operations B1–B5、C1–C5 在重启后的可观察事实。

1. 按数据域持久保存描述 Task、Run 及匹配依据的事件事实，保持历史含义与归属一致；历史包括尚未结束的实体已经发生的事件。
2. 存储实现可以外置，保留期限另定，不意味着无限保留全部数据。
3. 初始化时根据该域的持久事件事实重建状态与匹配关系，不重新计算已受理 Task 的生效时间和超时期限；状态缓存不是另一份权威事实。
4. 尚未生效的有效 Task 在重启后仍应按原时间生效；已生效且仍需处理的 Task 继续进行匹配与调度判断，并处理已到达的超时条件。
5. 已有可靠终结事实的 Run 恢复相应状态。
6. Run 已开始但无可靠终结事实时，重启后统一按 `stopped` 处理，不自动重演或复用。
   “已开始执行”即 Run 已开始；准备、等待资源等属于 Run 内部过程，恢复规则不作区分。
7. 这里的 `stopped` 表示 Engine 已失去对旧执行的跟踪，按已被终止处理；即使无法确认旧 Worker 是否真的退出，也不继续视为运行中。
8. 此恢复裁决不证明旧 Worker 已被杀掉、资源已释放或副作用未发生，这些物理事实仍保持未知。
9. 已匹配该 Run 的 Task，其 stage 相应恢复为 `stopped`，取消与时间状态保持各自语义。
10. Run 开始顺序在数据域内跨重启保持唯一、严格递增；恢复或历史清理不得使既有 Task 改为匹配其他 Run。
11. 数据域事件 revision 及已公布水位跨重启保持一致，不重用旧序号或在既有水位之前补插事件，见[数据域事件序号与查询 Revision](./revision.md)。

## 资格观测与匹配依据

1. 持久保留证明匹配的真实源事实，以及必要的 domain qualification-time-observed 见证；
   见证领域载荷仅有 observedAt，其源序位置与相关 Task 受理、Run 开始、取消及停止边界共同决定资格。
2. 按源顺序及当时事实前后边界重放，选择唯一最早匹配；后来受理/开始的对象不借用旧见证，
   已进入停止流程的 Run 不因后来见证重新开放匹配。
3. 已成立的匹配不因重启时 now 回拨或后续终结墙钟回拨而被撤销或换选；
   时间维度仍按当前 now，不能用匹配资格的历史时间冻结 pending/eligible/timeout。
4. 缓存必须能由保留的事实与见证重建；只留所选 Run、Task 权威快照、最大 observedAt 或计数器不构成充分依据。
   无法完整补读或重建时明确失败，不能按 Run 当前状态重新配对。
5. 见证不证明 Run 已退出或资源已回收；已开始但无可靠终结事实的 Run 仍按 stopped 恢复且不重演，
   已匹配 Task 保留原关系并跟随该恢复裁决。

## Request 幂等窗口与清理

1. 持久保留 ULID 可受理下界，使其跨重启不倒退，避免已清理凭据的旧 ID 再次被受理。
2. 幂等凭据必须覆盖对应 ID 的整个可受理窗口；Task 详情清理不能提前撤销该保证。
3. 窗口外的 ID 一律拒绝，不依赖旧凭据是否仍保留；窗口过期不影响已受理 Task 的继续处理。

窗口及凭据规则见[Request 受理与幂等处理](./request-admission.md)。

## 保留配置与不支持的旧格式

既有显式回收的 retentionMs 默认 86,400,000ms，是可回收记录的年龄门槛，不是到龄必删，
也不新增自动清理产品。活动对象、唯一匹配与恢复所需依据、水位、准入下界和仍在窗口内的幂等凭据继续保留；
配置缩小不能撤销这些保证。补读所需前后事实不足时明确报告历史过期/缺失。

新版本在取得域独占后、开放受理和 listener 前校验格式及必要事实；不能可靠解释的旧格式明确拒绝，
报告原域身份与不支持格式，不先改写原库，不自动迁移、删除或重跑。
需要新域时由宿主/操作者显式指定不同的新域位置与身份；旧库原样留存。
新域不是原域连续重启，不能复用旧域身份、水位或游标，也不导入/重演旧 Run。
可支持的新格式缺少补读历史与旧格式不支持分别报错，不能靠静默切域隐藏。
