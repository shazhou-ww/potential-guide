# 数据域归属与运行实例独占绑定

本契约界定 Task、Run 的数据归属与实例管理权，确保跨重启归属稳定，并避免多个实例同时管理同一数据域。

关联 [职责入口](../task-engine-responsibilities.md)：operations A1–A2、B1–B5、C1–C5，约束全部操作的数据范围与管理权。

1. Task、Run 及其匹配关系和历史归属于明确的数据域；域不随运行实例退出或重启而改变。
2. 每个 Task Engine 运行实例初始化时指定一个数据域，整个生命周期只绑定该域，不切换、不同时绑定多个域。
3. 同一数据域在任一时刻最多被一个有效运行实例独占绑定；无法获得独占管理权则初始化失败，不开始受理或管理该域的 Task 与 Run。
4. 旧实例释放绑定或被确认失去管理权后，新实例才能接管。独占机制不限定为具体的锁，也不限定域绑定设备、目录或数据库。

例如，一种常见部署是：一个运行实例对应一个 Task Engine 进程，一个数据域对应一台设备。
此时，该设备同一时刻只能有一个有效的 Task Engine 进程；第二个进程无法获得该域的独占管理权，初始化失败。
原进程退出并释放管理权后，新进程可以绑定同一数据域，继续处理该设备原有的 Task、Run 与历史。
这里“运行实例”指本次启动的实例，不是设备或持久数据本身；设备级数据域只是部署示例，不是强制限制。
