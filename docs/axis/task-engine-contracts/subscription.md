# 订阅句柄与订阅生命周期

本契约界定订阅的使用与解除方式，使外部参与者能够管理自己的订阅，而不影响被观察实体的生命周期。

关联 [职责入口](../task-engine-responsibilities.md)：operations B3、B5、C3、C5，单体与集合订阅。

本契约中的 fromRevision、源封装和预算针对生命周期订阅。
C7 的独立日志订阅使用 Run 日志 sequence、独立容量和缺口状态；
其补读、关闭与错误语义见[Run 诊断日志](./run-logs.md#查询与实时续接)，不混用两类锚点。

1. 句柄提供对应单个实体的变更事件流，或集合的概况事件流。
2. 通过句柄取消订阅，解除对应订阅，不取消 Task 或 Run。
3. 句柄是逻辑接口，其跨进程通信形式另行定义。
4. 单体事件流与历史查询使用同一 TaskEvent / RunEvent 模型；eligible、timeout 到点不生成事件，客户端依据时间边界推算相应状态。
5. 实际协调资格观测与独立时间标签推算区分：需要持久见证的新匹配按
   [匹配契约](./run-matching.md)产生源事实及派生变化，不新增另一套时间通知流。

## 起始锚点与增量衔接

1. 订阅指定 `fromRevision`，补读该位置之后的匹配事件，不重复包含锚点本身。
2. 历史补读与实时事件流无缝衔接，不能遗漏建立订阅期间发生的事件。
3. 每个源事件携带 revision，外部参与者可从最后完整处理的源事件位置重新订阅；允许重投，不承诺 exactly-once。
4. 锚点跨域、无效或超出可补读范围时明确失败，不静默从最新位置继续。
5. 集合订阅沿用原查询的筛选条件，从整轮视图的 revision 后补发加入、摘要更新和移出事件；不为每组条件永久维护独立历史。
6. 首次加载集合时，外部参与者需合并完整分页基线，再按序应用水位后的事件；提前订阅可暂存事件，不将增量与不完整基线混用。

revision 的含义见[数据域事件序号与查询 Revision](./revision.md)；分页 cursor 不直接作为订阅锚点。

集合补读与实时观察均覆盖域内相关变更，不限于已有成员，按变更前后是否符合条件生成事件。
同一源事件可能产生多个成员的派生变化；每次交付是该源事件对当前订阅的完整变化封装，
包含源 revision 和全部成员的加入/更新/移出。成员带稳定实体标识，同一封装内唯一且顺序稳定；
加入/更新携带新摘要，移出携带标识。不为封装分配第二个 revision，不要求对 Task 状态进行事务性更新。
消费者完整应用封装后才推进 fromRevision；中断时允许重投整个封装，不能仅处理一个成员就按 revision 丢弃其余成员。
无匹配变化的源事件不必交付；更晚的完整封装仍可作为续读锚点。
与重新查询的一致性及时间筛选限制见[Task 与 Run 的查询范围及订阅粒度](./observation.md)。

资格见证属于正常的补读范围。若查询基线水位为 S，协调器随后提交见证 W，
则从 S 补读必须完整交付 W 引起的所有相关匹配/集合变化，包括原来不在基线中的成员；
不能把这些变化追加到已消费的 S。消费完整 W 后才可将续读锚点推进到 W，
此后从 W 续读排除 W 本身；中途断线仍按最后完整处理的位置重投。
GET 不触发见证，也不以临时查询结果或当前 Run 状态替代重放当时的资格边界。

## 容量与断流

默认每实例最多 128 个订阅；单个源封装最多 1,000 项变化且编码后不超过 65,536 字节；
每订阅待消费缓冲最多 64 个源封装且不超过 1,048,576 字节。以上预算可独立配置为正整数，字节以 UTF-8 传输编码计量。
补读与实时使用同一规则；超限在交付该源事件的任何部分之前显式断流，报告容量错误与最后完整交付位置，
不以截断的成功封装、空结果或静默跳到最新水位代替。
消费者仍以自己最后完整处理的位置恢复；服务最后交付的位置不证明客户端已经应用。
单一源事件本身超过预算时，应调整配置、缩小事实筛选范围或重新取得完整分页基线，
不能承诺相同预算下重连会成功，也不能将超限事件标成已消费。
取消订阅及 HTTP 断开只释放观察资源；长流不套用普通请求的总时长限制。
