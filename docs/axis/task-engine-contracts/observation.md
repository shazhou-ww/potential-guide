# Task 与 Run 的查询范围及订阅粒度

本契约区分单体与集合、当前状态与历史及后续变化，避免查询与订阅承担不明确或过量的数据范围。

关联 [职责入口](../task-engine-responsibilities.md)：operations B1–B5、C1–C5，Task 与 Run 的查询和订阅。

1. 单个实体的当前状态与变更历史分别查询：前者返回当前状态快照，不默认包含历史；后者返回不可变变更记录，可独立分页。订阅提供后续变更事件。
2. 集合查询提供绑定数据域内符合条件的完整实体列表，以摘要呈现；集合订阅提供加入、摘要更新和移出事件，不包含每个实体的全部详情变化。
3. 两个层级均覆盖仍在进行和已经结束的实体；整体概况不是多个单体详情订阅的简单合并，也不预先要求统计聚合。
4. 每个层级分别提供查询和订阅操作。订阅成功返回订阅句柄（subscription handle），包含事件流及取消订阅能力；取消订阅由句柄提供，不另列为 Engine 顶层操作。
5. 具体摘要字段、事件范围及查询、订阅的接口形状另行定义。
6. 单体历史查询与订阅统一使用 TaskEvent / RunEvent：历史读取已保存的事件，订阅读取后续的同类事件，不另设通知模型。
7. eligible、timeout 是时间派生状态，时间越过边界本身不产生事件，也不重复进入历史或订阅流。
8. 当前状态由已知事实与观察时间共同确定；客户端可依据生效时间和超时期限自行推算，时钟差可能带来展示差异，不依赖到点事件刷新。
9. 时间状态按当下时间推算，不因取消或 Run 终结而冻结；UI 聚合标签不作为 Engine 的逻辑判断依据，详见[Task 生命周期与三维状态](./task-lifecycle.md)。
10. 状态快照与集合查询均返回一致的 revision；订阅从该水位之后补历史并接续实时事件，见[数据域事件序号与查询 Revision](./revision.md)和[订阅句柄与订阅生命周期](./subscription.md)。

历史和集合查询的分页输入及返回页遵守[历史与集合查询的分页契约](./pagination.md)。

## 集合事件

对每条事件，计算其前后实体是否符合 query，再生成集合的派生输出；不要求先对 Task 状态做事务性修改。

| 变更前 | 变更后 | 集合事件 |
| --- | --- | --- |
| 不符合 | 符合 | 加入，携带实体标识及摘要 |
| 符合 | 符合 | 摘要变化时发送更新，携带实体标识及新摘要 |
| 符合 | 不符合 | 移出，携带实体标识 |
| 不符合 | 不符合 | 不发送 |

1. 移出仅表示不再属于该查询结果集，不取消 Task 或停止 Run。
2. 观察范围覆盖数据域内相关变更，不限于首次查询返回的成员；原先不符合条件的实体变化后可以加入。
3. 历史补读按事件当时的变更前后事实判断，不用实体现在的状态代替，也不为每组 query 穷举保存独立历史。
4. 同一条事实事件可以使多个成员发生变化，这些派生输出沿用源事件的 revision；具体输出形状另行定义。

## 与重新查询的一致性

1. 同一数据域、同一 query 下，完整查询基线加上按序应用的集合事件，应与相同 revision 的重新查询得到的成员及摘要一致。
2. 基线须包含全部分页；revision 标识源事件，不能把同一源事件对不同成员的影响误当作重复而丢弃。
3. 实时流尚未追上查询水位时允许暂时落后，不将这种延迟当作结果不一致。
4. 涉及时间派生状态时，还需对齐观察时间；纯时间流逝不产生 eligible 或 timeout 事件。
5. 按时间派生状态筛选的集合，不能只靠事件流保证一致；需明确客户端时间计算方案，或将这类条件排除在事件驱动的集合订阅范围外，具体支持范围待定。
