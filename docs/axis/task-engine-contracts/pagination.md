# 历史与集合查询的分页

本契约统一历史与集合查询的分页输入、返回页和续读语义，在限制单次成本的同时保证查询结果完整且不被静默拼接。

关联 [职责入口](../task-engine-responsibilities.md)：B2、B4、C2、C4。

## 分页输入

以下为逻辑接口草案，分页参数纳入各 operation 的 query；不要求与现有代码参数拆分方式相同。

```ts
interface PaginationQuery {
  cursor?: string;
  limit?: number;
}
```

1. 首次查询不传 `cursor`，同时指定相应的筛选、排序条件及可选 `limit`。
2. `limit` 是请求的页大小，必须为正整数；省略时使用明确的服务默认值，服务上限与超限处理应公开，不静默接受非法参数。
3. 续页使用上一页返回的 `next` 作为 `cursor`，保持原筛选和排序条件，不用页码或时间戳推算读取位置。
4. 游标是不透明的续读令牌，绑定数据域、查询种类、条件、顺序、查询视图及已读位置，不能跨 Task/Run、历史/集合查询混用。
5. 续页是否允许调整 `limit`、默认值和上限的具体数值另行明确；不影响同一查询视图的完整性要求。

## 返回页

```ts
interface Page<Item> {
  items: Item[];
  revision: Revision;
  next?: string;
}
```

1. `items` 为本页数据，`next` 存在表示仍需续读，缺失表示本轮查询结束，不再另设可能矛盾的结束标志。
2. `revision` 表示本轮固定的查询水位，不是本页最后一项的事件位置；冻结集合页还需表达观察时间和查询有效期，具体字段随各查询契约定义。
3. 完整集合可以通过多页获得，不要求单次返回全部数据；不能用单页、缓存或已观察到的事件冒充完整集合。

## 顺序与一致性

1. 历史查询首次捕获一致水位，按持久提交顺序读取不超过该水位的记录，不以墙钟时间排序或去重；后续新事件不混入本轮历史分页。
2. 集合查询固定本轮成员、顺序和摘要；并发创建、更新在重新查询时纳入，不将不同轮次的页拼成同一完整结果。
3. 在有效视图内连续读取应无遗漏、无跨页重复；重试同一页可以重复返回该页，不承诺传输层 exactly-once。
4. 权限撤销与数据清理及时生效，不能为了维持冻结视图继续暴露不可访问或已清理的数据；无法保持完整视图时明确失败。

## Revision 与 Cursor

1. revision 是数据域事件位置或查询水位；cursor 是继续查询所需的上下文，两者不等同。
2. 按事件顺序增量补读时，最后处理的事件 revision 可作为续读位置。
3. 固定历史分页还需保存本轮上界 revision；cursor 同时确定上界、过滤条件与已读位置。
4. 集合分页的 cursor 还需确定排序和成员位置，不能只用事件 revision 代替。
5. revision 不自动提供冻结分页能力；实现必须能重建该水位的视图，或在有效期内保留该轮视图。

Revision 为[数据域事件序号与查询 Revision](./revision.md)中的逻辑类型，具体编码另定。

## 有界性与失效

1. 页大小、扫描成本及查询视图占用均需有界；无法满足预算时明确失败，不返回成功形的截断结果。
2. 非法、条件不符、跨域、过期或失效游标明确失败，不回到第一页、不切换到新视图，也不以空页掩盖错误。
3. 历史超出保留范围明确报告历史过期；集合视图过期需重新发起查询，不承诺跨实例重启继续使用集合游标。
4. 空结果表示在有效查询范围内确实没有匹配项，不代表历史缺失、服务失败或订阅断流。
