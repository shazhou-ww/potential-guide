# Implementation

本文件是准备阶段的轻量实施种子，不表示开始实施。
前置 Idea `task-engine-contract-refactor` 完成前不执行下列步骤。
范围和验收场景见 [Axis 变更影响](ideal/Axis-deltas.md)，开工时以其实际交付重新核对差异。

## Steps

### I-S01: 核对前置交付并落实标准制品与 SDK

记录前置 Idea 的完成状态与交付提交，核对实际增量，再落实 Bundle 声明、离线 Schema、
内容校验和 Task SDK 构建/运行入口；不把上一轮已经实现的 Worker 隔离重做一遍。

### I-S02: 贯通异步受理与匹配增量

落实 preparation 共享、持久恢复、requestId 跟踪、幂等和保留边界，
以及额外输入字段判等、终结回拨失配巡检和完整观察链路；适配直接消费者，不改业务描述契约。

### I-S03: 验证边界与切换方案

补足影响文档 V01–V10 的定向测试，运行相关构建、打包验证和 `pnpm check`，
明确旧格式拒绝/数据保留与消费端切换方式，不自动迁移或重跑。

## Acceptance criteria

### I-AC01: 标准制品独立可执行

以 V01–V02 的构建与消费测试证明无作者依赖安装、完整 Digest 校验及离线 Schema 解析，
并记录前置交付核对结果。

### I-AC02: 受理与匹配事实一致

以 V03–V09 的并发、重启、窗口、回拨、清理及补读场景证明不重复创建、不伪造结果、
不越过 eligible/取消约束；前置轮反例按本轮明确增量更新。

### I-AC03: 直接链路与质量检查通过

以 V10 及相关测试证明 HTTP/client/UI/直接适配器行为一致，
通过 `pnpm check` 并保存验证结果；旧数据不被静默改写或替换。
