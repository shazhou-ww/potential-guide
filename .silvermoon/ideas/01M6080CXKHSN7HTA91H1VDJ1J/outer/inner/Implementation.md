# Implementation

## Steps

### I-S01: 迁移内置内容与消费声明

盘点并迁移内置 Check、Objective、References 和仓库声明，建立新旧来源的明确处置方式，不改变历史记录。

### I-S02: 建立 Release 构建与发布入口

调整 CI、制品命名和发布触发，按依赖顺序生成可验证的 Release assets；退出业务包 npm 发布路径，保留工具发布。

### I-S03: 更新作者与消费者体验

更新脚手架、构建验证和文档，测试生成产物、完整引用及迁移后的工具使用方式。

## Acceptance criteria

### I-AC01: 内置内容完整迁移

以盘点清单与验证脚本证明现有内置内容及其消费声明已迁移，References 和等级行为保持预期。

### I-AC02: 发布候选依赖完整

CI 或等价集成测试证明产物存在、digest 匹配且 Objective 只引用可交付的准确 Check；工具 npm 发布配置不受破坏。

### I-AC03: 开发与迁移路径一致

脚手架产物可构建并消费；文档和自动检查确认生成 bundle 不入库，业务制品不再要求 npm 发布，旧证据不被转换。
