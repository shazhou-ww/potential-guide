# Deployment

本阶段以已接受 implementationRevision `e94a791d179cd0aaf03ced4789efaa9999680b50` 的本地构建 CLI/库产物进行受控试用，不发布 npm，不迁移、切换当前工程或 Silvermoon 的真实 Objective。契约先同步 primary，再针对该准确部署 revision 执行并记录结果；原始命令、运行记录和固定版本证据保留在实施会话的独立证据目录，仓库内提供脱敏结果与复现索引。

## Steps

### D-S01: 验证实际跨目标治理

在受控试用环境以新版示例运行中间依赖，观察交接、外部治理与原目标恢复，记录可复现证据。

创建并提交本次独占的两个临时 Git 来源：消费者首层正常通过，在中间层动态请求提供者的明确最低层级；提供者以独立 subject 指定本次临时标记文件。使用构建产物的实际 `probe`、`regulate` 和 `supervise` CLI，及受控本地 ACP 规划/执行适配器跑闭环。执行器只允许写本次试用标记，不接入真实用户 Agent 或项目；日志可断言哪一个 Objective 收到执行请求。记录全部 subject、来源完整 commit、原始 stdout/stderr、Agent 调用和独立重观察。结束后清理独占 Git 来源、状态、标记和探针缓存，只保留明确的证据文件及复现程序。

### D-S02: 确认手动迁移前置条件

只读核实当前工程与 Silvermoon 工程真实定义的协议状态和固定版本，不改其定义、探针或派生产物。真实接入必须有之后单独手动迁移完成的证据；本次尚未完成时记录为阻塞真实切换，不将其混为受控试用失败，也不代做迁移或添加兼容层。

在隔离试用来源独立执行旧 prerequisite 字段、旧问题输出的拒绝，以及不含已删除字段的合法 schemaVersion:1 定义可用性。明确保留实施阶段已复现的 monorepo 两项、setup 一项真实旧输出集成阻塞，说明恢复条件。本阶段只证明试用与切换边界，不授权生产接入。

## Acceptance criteria

### D-AC01: 真实交接与恢复可观察

试用记录证明原目标 Agent 不代为治理依赖，外部目标达标后原目标重新观察并能继续。

成功证据应包含：中间层之前的检查已通过；consumer current 仍属 consumer；`regulate` 返回 dependency-required、iterations=0 且执行器未接收 consumer 修复；`supervise` 按交接版本治理 provider；provider 标记由受控执行器真实写入并重新检查达标；consumer 后续独立 observation 达到 terminal。未达成或来源版本不一致应保留失败，不以实施测试结果替代本次实际运行。

### D-AC02: 切换边界可辨识

记录新问题协议成功、旧 prerequisite 字段及旧问题输出明确拒绝的结果；未变化的合法 Manifest 不应仅因历史存在而被拒绝。真实工程接入必须有单独手动迁移完成的证据，不能将样例成功当作两工程已迁移。

适用本次 outer 的完成证明是受控试用和**真实切换仍被阻塞**的可核查记录，而不是要求代做用户明确排除的迁移。原始 CLI 错误、两工程现存旧协议位置/固定来源、三项实施集成阻塞及手动恢复条件均需有证据；若无法证明该边界则保留本项未完成并报告父会话。验收由父会话独立决定，实施方只 submitOuter，不 acceptOuter。
