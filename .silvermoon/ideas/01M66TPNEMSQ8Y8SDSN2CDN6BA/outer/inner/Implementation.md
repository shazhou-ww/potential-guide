# Implementation

准备阶段的可调整种子，不是开工授权。范围见[构想](ideal/Idea.md)与[调研](ideal/Research.md)。

## Steps

### I-S01: 收敛查询与兼容契约

获准实施后核对当前 Task/Schema/终结语义，落实创建时间与更新时间（包含新进度）的查询、更新归属、摘要、权限、排序与分页一致性规则；不复制业务校验或扩展治理范围。

### I-S02: 接入只读目录能力

在通用协议、Engine 和 HTTP/Server 组装中实现受控查询，复用权威事实并维护可恢复的最近更新时间；验证有界稳定查询视图，只有经规模验证确有必要时再增加派生索引，并保持事务/恢复一致。

### I-S03: 验证边界并更新文档

覆盖类型/时间过滤、同刻排序、权限、并发新增/清理、页与响应限额、恢复和旧契约回归；更新公开使用文档并运行 pnpm check。

## Acceptance criteria

### I-AC01: 查询与详情对应

以不同客户端/类型/创建与更新时间的测试证明目录覆盖授权保留记录，只将影响该 Task 的新进度计入更新而读取不制造更新；摘要可连接已有任务和原请求查询，同轮成员、顺序和摘要不受并发新增/更新影响，重新查询反映变化，不暴露 Prepared 或大型业务载荷。

### I-AC02: 权限与资源边界有效

以跨 scope、拒绝权限、翻页授权变化、成员清理、非法/过期/重启失效 cursor 和容量边界测试证明无越权枚举或成功形状的错误兜底，不能保持完整稳定视图时明确失败，扫描、返回和查询视图总资源成本有可复核边界。

### I-AC03: 原有协议与恢复保持正确

以已有 Task/Request/事件查询、幂等、旧版本和重启回归证明未破坏现有行为，查询没有执行/清理副作用；pnpm check 通过。
