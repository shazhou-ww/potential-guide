# 按类型和时间查询 Endpoint 的任务历史目录

## 问题

服务已持久化任务与原请求，但公开协议只能按已知 ID 查任务或事件，使用者无法发现其他客户端提交过的任务，也不能按类型和时间查找历史。

## 结果

提供受权限与资源限制约束的任务目录查询，按类型和时间筛选、分页，并从结果进入现有详情及原参数查询，为独立消费者和 Web UI 的历史重做提供依据。来源与能力缺口见[调研](Research.md)。

## 边界

1. 只返回当前可信 Caller scope 下获授权且仍保留的任务，不限提交工具；不新增跨 scope 管理员权限或绕过历史契约绑定。
2. 复用服务的任务事实，不把 UI 本机记录当历史，不默认另建历史仓库；查询不触发任务执行或历史清理。
3. 不实现 Web UI、Schema 发现、资产管理、高级 Input 搜索、全局事件流或自动清理治理；这些不作为本条完成前置。

## 验收标准

1. 通过公开能力按类型及服务接收时间找到来自不同客户端的保留任务，不因尚未运行或最终失败排除记录；结果具备进入任务详情和原参数查询所需的身份。
2. 权限隔离、稳定排序、分页和并发变动/清理后的行为明确可验证；非法查询和失效游标不伪装成完整成功结果。
3. 列表大小与响应成本有边界，原请求/事件查询、存储恢复和旧契约校验保持正确，不要求已有 Task 类型提供新的业务执行器。

## 下一步

收敛最小摘要与分页一致性契约，再形成可评审候选；用户当前仅授权独立准备研究与讨论，不开始实现、验收、部署或发布，不记录 submit/accept。
