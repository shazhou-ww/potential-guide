# Deployment

准备阶段的可调整种子；尚未实施或部署，不构成验收或发布授权。

## Steps

### D-S01: 准备独立消费环境

通过打包产物在专属端口和临时 Store 启动服务，准备不同客户端、类型、时间和 scope 的任务，不复用客户或其他 session 的数据。

### D-S02: 验证真实查询与恢复

从独立客户端使用公开接口查询、翻页并打开详情/原请求；验证选定的并发/失效语义和服务重启，不以 UI 或直接读 SQLite 代替公开消费。

### D-S03: 记录证据并回收资源

记录候选与查询结果，仅清理验证拥有的进程、连接和临时数据；如需验证已清理历史，仅使用该临时 Store 的明确治理动作，不新增自动清理功能或发布包。

## Acceptance criteria

### D-AC01: 独立客户端可查到正确历史

以打包消费和真实 HTTP 记录证明同 scope 的跨客户端任务可查询，类型、创建时间、含新进度的更新时间与分页有效，单纯读取不制造更新，另一 scope 不可见，结果可进入现有详情与原参数入口。

### D-AC02: 恢复与验证隔离可核验

以重启前后查询、失败路径及退出检查证明既有数据/契约语义保持一致，查询无执行/清理副作用，其他工作树、服务及数据不受影响。
