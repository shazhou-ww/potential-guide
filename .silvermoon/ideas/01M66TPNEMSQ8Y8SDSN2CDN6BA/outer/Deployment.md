# Deployment

实施已通过主 Agent 受托 gate 审查；本阶段验证打包产物的独立消费结果，
不发布 npm、不变更客户环境、不改写已接受的实现。subagent 执行，
主 Agent 对准确 outer 修订审查并审批；授权依据见[调研](inner/ideal/Research.md)。

## Steps

### D-S01: 准备独立消费环境

从已接受实施提交打包协议、Engine、HTTP、SQLite 和 Server 的所需依赖闭包，
在操作自有的临时 consumer 中安装本地 tarball，不引用 workspace 源文件。
使用 127.0.0.1 专属动态端口、临时 SQLite 与可信测试身份，准备不同客户端、
类型、时间和 scope 的任务；记录产物摘要、源码提交及本契约 revision，
不复用客户或其他 session 的数据。

### D-S02: 验证真实查询与恢复

通过真实 HTTP 查询双时间交集、翻页并打开详情/原请求，验证 Schema 发现并存、
原请求不注入版本以及新身份提交。通过专属测试执行器控制新进度、取消和完成，
证明本轮成员/顺序/摘要稳定、重查反映变化，已取消任务不跟随共享进度。
验证拒绝授权、翻页撤权、非法/过期游标、受控清理使旧页失效以及服务重启；
不得用直接读 SQLite 或同进程 handler 调用代替对外结果。

### D-S03: 记录证据并回收资源

以同世界验证记录保存命令、关键请求/响应断言、退出与资源回收证据；
记录约束或失败而非以空结果兜底。仅清理本次持有的进程、连接和临时数据，
以进程退出、端口不可连接及目录回收验证收尾；显式 collect 仅限专属临时 Store，
不新增自动清理功能或发布包。

## Acceptance criteria

### D-AC01: 独立客户端可查到正确历史

以打包消费和真实 HTTP 记录证明同 scope 的跨客户端任务可查询，类型、创建时间和含自身新进度的最近更新时间筛选有效；并发新增/更新不改变本轮结果，重新查询反映变化，单纯读取不制造更新，另一 scope 不可见，结果可进入现有详情与原参数入口。

### D-AC02: 恢复与验证隔离可核验

以重启前后新查询、翻页授权变化、清理或查询上下文失效的明确失败路径及退出检查证明既有数据/契约语义保持一致，查询无执行/清理副作用，其他工作树、服务及数据不受影响。
