# 实现统一请求与周期后继

本文为准备阶段的实施初版，构想验收不表示已实施或接受最终 API。语义依据为[构想及配套原则](./ideal/Idea.md)。

## Steps

### I-S01: 调整请求事实与生命周期

盘点当前新版及 legacy 边界，定义固定 eligibleAt、可选 recurrence、后继来源、派发与显式撤销事实；更新输入校验、纯重放及必要的版本兼容规则，不悄悄重解释旧记录。

### I-S02: 接入可恢复调度与统一事件

让初始派发与后继生成共同持久化，接入到期唤醒、恢复、同 Target 仲裁、依赖续接及周期停止；结构化记录耗尽并提供可去重的外部观察路径，不自动追加投入。

### I-S03: 更新关联视图与验证

更新直接关联的公共类型、视图、文档和测试，明确旧入口迁移及 Supervisor helper 依赖边界；不顺带实现上层 Agent、MCP server 或跨 Host 一致性。

## Acceptance criteria

### I-AC01: 不可变派发与恢复成立

通过受控时钟、reducer / restore 和崩溃窗口测试，证明请求不可变、初始派发唯一、后继唯一、到期可恢复，长 Run 与离线不产生重叠或积累补跑。

### I-AC02: 事件与共存边界成立

通过集成测试证明一次性及周期请求耗尽均可重读、不自动续跑；额外请求与周期链共存、Target 互斥、显式停止有效，依赖续接不重复生成后继或刷新额度。

### I-AC03: 公共接口与仓库行为一致

通过类型消费者及相关视图测试、文档示例和 pnpm check 证明公共行为与约定一致，既有一次性能力及明确保留的兼容入口未被意外改变。
