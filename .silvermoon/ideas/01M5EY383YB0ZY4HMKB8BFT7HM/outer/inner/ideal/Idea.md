# 减少 probe 重复工作并明确超时

## 问题

本项目 monorepo-standard probe 需约 110-124 秒，默认 30 秒观察预算会中断且丢失超时原因；实测主要开销是重复依赖观察、进程初始化和全仓扫描，见 [Optimization.md](./Optimization.md)。

## 结果

在保持检查覆盖与可信证据的前提下，减少单次 probe 的重复工作，并让各层预算与超时原因可配置、可诊断。

## 边界

- 不跨修复、独立 probe 或 Regulation 轮次复用目标状态；固定规则提交不等于目标工作区不可变。
- 保留完整观察、独立包入口、层级顺序、来源证据与进程隔离，不以跳检查或单纯延长超时冒充优化。
- worker 复用与有界并发仅在前期优化实测后决定；不扩展为发布、远程部署或 command 简化。

## 验收标准

- 同等环境和输入的前后对比证明重复观察、扫描或进程工作减少且耗时下降，结果和问题归属一致；同时报告冷、热运行及具体计数。
- 目标变化、修复及新轮次不会误用旧结果；异常、取消和依赖证据反例通过。
- CLI 可区分并配置来源准备、整次观察与单 check 预算，超时显示可定位的原因，不再仅报通用 fiber 中断。
