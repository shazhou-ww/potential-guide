# 以观察任务语义重构 Check Host v2

## 问题

调用方自行准备制品和指定本地目录，使版本、缓存和执行生命周期分散。一次检查请求需要表达满足时间条件的观察，而不应直接等同于启动一次 worker 调用。

## 结果

Host 统一获取和管理 Check 制品，以 URL、可选 digest 和 freshness 受理独立 Task，由可复用 worker pool 提供可共享的 Execution；v2 API 与对象式 SDK 支持观察、批量订阅及协作取消。

## 边界

- 基于已完成的 Check/Objective 制品能力；Host 管理制品，执行内核不理解下载或 Objective 语义，历史契约与证据不改写。
- Task 不合并，匹配与时限由统一状态机仲裁；Worker 同时只运行一个 Execution，跨时复用且并发隔离。
- 本项打通现有调用方并明确 v1 兼容或退出方式；不承担正式 Release、内置内容全量迁移或跨重启透明执行恢复。

## 验收标准

- 普通客户端无需本地制品路径即可运行浮动或固定版本，来源更新不替换正在执行的内容。
- 两种 freshness、共享匹配、独立期限及取消在竞争条件下保持正确，超时和清理不伪造成功。
- 单/多 Task 使用同一事件入口，CheckTask SDK 和实际业务调用链可验证使用并保留准确证据。

设计入口与支持文档见[设计逻辑](./design-rationale.md)。
