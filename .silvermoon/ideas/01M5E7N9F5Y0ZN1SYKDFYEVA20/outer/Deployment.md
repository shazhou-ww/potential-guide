# Regulation Coordinator 单一目标命令隔离消费

本文件是修订构想的轻量部署初版，实施完成后再细化。现有 verification 目录及证据仅证明上一版已验收交付，不能作为本次单一命令的通过记录；历史接受事件保持不变。

## Steps

### D-S01 — 固定新实现并准备隔离产物

固定本次被接受的实现及先行 level 协议版本，生成真实本地 tarballs，在独立消费目录安装；核对入口与依赖解析不借用源工作区，不发布 npm 或改动设备配置。

### D-S02 — 以新命令验证真实包消费

从公开包入口验证目标设置、同对象覆盖、priority 调整、initial 撤销、终结后同值新尝试及自主依赖调用；验证 pending/blocked 区分、实际终止和总预算不重置。更新或替换历史五命令 fixture 后重新取证。

### D-S03 — 记录证据并确认清理

记录精确版本、产物身份、实际运行结果和隔离目录清理；明确测试 runner 与真实 Agent/process 的证明边界，保留旧服务兼容 smoke，不以历史证据代替新验证。

## Acceptance criteria

### D-AC01 — 新契约包可独立消费

新 tarballs 的安装、公开 ESM 入口与声明类型检查通过，实际解析路径在隔离 consumer 内；版本和产物摘要能关联到本次接受的实现。

### D-AC02 — 单目标调度结果正确

隔离运行证明单一命令全部关键行为及依赖编排成立；initial 无额外执行、blocked 不恢复旧调用、撤销不提前释放资源，可信总预算保持有效。

### D-AC03 — 新证据完整且清理可核对

新证据明确各项结果和旧证据边界，旧服务 smoke 行为不变，进程/订阅/lease 收支及隔离目录清理可核对；无 npm 发布、全局入口或设备配置变更。
