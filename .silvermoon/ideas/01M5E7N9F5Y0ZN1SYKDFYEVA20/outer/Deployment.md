# Regulation Coordinator 双意图与恢复隔离消费

本文件是修订构想的轻量部署初版，实施完成后再细化。现有 verification 目录及证据仅证明上一版已验收交付，不能作为本次单一命令的通过记录；历史接受事件保持不变。

## Steps

### D-S01 — 固定新实现并准备隔离产物

固定本次被接受的实现及先行 level 协议版本，生成真实本地 tarballs，在独立消费目录安装；核对入口与依赖解析不借用源工作区，不发布 npm 或改动设备配置。

### D-S02 — 以新命令验证真实包消费

从公开包入口验证目标与资源分配意图、priority、initial、同值新尝试及依赖；验证 no-resource 初值与切换、期望并发缩减不等于已停止、binding 和实际占用分别可追踪、资源侧拒绝不经 harness 自建审批。捕获完整事件前缀并由独立 reducer 归约，保存目标/状态后重启 consumer；采用日志时由持久化适配层关联一致处理位置，核实无重放副作用、无重复执行或预算重置。更新历史 fixture 后重新取证。

### D-S03 — 记录证据并确认清理

记录精确版本、产物身份、实际运行结果和隔离目录清理；明确测试 runner 与真实 Agent/process 的证明边界，保留旧服务兼容 smoke，不以历史证据代替新验证。

从隔离消费获得的基础状态按已接受的 SELECT 定义重算视图，与同版本的事件增量结果及重启后的结果比较，保留输入前缀、查询结果与版本证据。

## Acceptance criteria

### D-AC01 — 新契约包可独立消费

新 tarballs 的安装、公开 ESM 入口与声明类型检查通过，实际解析路径在隔离 consumer 内；版本和产物摘要能关联到本次接受的实现。

### D-AC02 — 双意图调度及恢复结果正确

隔离运行证明两个意图输入、纯归约、资源侧授权和有限依赖成立；期望不冒充实际占用，initial 无额外业务执行，输入通道结束不撤销意图或自动关闭服务。调用确认结束后从当前切片移除，终结记录 Collection 保留可查询结果；当前工作及依赖不丢失，对象集合的最近 Probe 聚合区分未知、失败及过期结果，查询分页不改变完整领域状态。重启证据核对 singleton、各个 collections 及适配层接续元数据的一致性、已终结意图不重跑、历史记录不重复写入或错误回退对象聚合、未知运行须核实、预算不重置及存储错误不静默清空；所用初值和事件前缀可复查，不宣称实时 Stream 已有历史重放。

### D-AC03 — 新证据完整且清理可核对

新证据明确各项结果和旧证据边界，旧服务 smoke 行为不变，进程/订阅/lease 收支及隔离目录清理可核对；无 npm 发布、全局入口或设备配置变更。

证据可核对实体/视图版本及增量维护与完整重算的一致性，不把不同 appliedRevision 的查询页拼成一致快照，也不以准备阶段的 SQL fixture 作为部署验证。
