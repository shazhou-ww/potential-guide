# Regulation Coordinator 隔离消费验证

本文件只保留可行性初版，待修订构想与实现被接受后细化。旧 verification 和历史接受事件仅对应此前交付，不能证明本次设计已完成。

## Steps

### D-S01 — 固定版本并准备隔离产物

固定被接受的实现与先行协议版本，在独立消费目录安装真实本地 tarballs；不借用源工作区解析，不发布 npm 或更改设备配置。

### D-S02 — 验证公开契约与观察结果

从包公开入口验证双意图、实体引用与已接受的观察需求；以明确输入和事实核对状态及恢复结果，不用历史 fixture 或尚未确认的 SQL 代替取证。

### D-S03 — 记录证据并清理

记录精确版本、产物身份、实际结果、证明范围与清理情况，保留旧服务兼容 smoke，不以测试 runner 证据冒充真实外部执行。

## Acceptance criteria

### D-AC01 — 包可独立消费

隔离安装、公开入口及声明类型检查通过，解析路径和产物摘要能够关联被接受的实现。

### D-AC02 — 行为与观察可核对

隔离运行证明意图、执行与展示边界一致，状态来源及版本可追溯；接受的恢复反例通过，不重做副作用、不虚报退出或请求满足，故障明确呈现。

### D-AC03 — 证据与清理完整

结果、旧证据边界、兼容 smoke 和进程/订阅/隔离目录清理均可复查，无 npm 发布、全局入口或设备配置变更。
