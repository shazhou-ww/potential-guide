# 将 Task Schema 编译前移到构建阶段

## 问题

默认 init Echo task 的 Worker 已压缩仍有 167,151 字节，其中 Ajv 及传递依赖约占 80%。业务代码极少，也必须携带完整 Schema 编译器。

## 结果

在构建阶段完成 Schema 检查和校验器编译，Worker 仅携带预生成校验函数及必要的小型辅助代码，不再携带完整 Ajv。

## 边界

- 前移的是校验器生成，不是取消运行时数据校验；输入、结果、消息仍须执行等价校验。
- 保持现有 Schema 支持范围、错误行为、输入投影和独立运行的 Bundle 交付约束。
- 本构想不包含 CID 精简、共享外部运行时或取消校验来换体积。

## 验收标准

- 默认构建产物不包含 Ajv 通用编译器及其 URI 解析依赖，且 Worker 启动不再编译 Schema。
- 有效和无效数据、受支持 Schema 及错误契约的回归测试证明行为一致。
- 按相同构建配置复测 init 模板，记录前后字节数及依赖归因，证明体积下降。
