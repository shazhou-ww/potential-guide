# Implementation

## Steps

### I-S01: 确认预编译边界

梳理构建入口、Worker 数据校验及 Schema 输入投影语义，评估 Ajv standalone 或等价预生成方案，区分构建期依赖与运行期必要辅助代码。

### I-S02: 接入构建期校验器生成

在 Task 构建链中预生成所需校验器，并让 Worker 消费生成结果；处理协议模块初始化等间接引入编译器的路径，保持所有非内置运行代码随包交付。

### I-S03: 补齐回归和体积证据

补充语义及依赖图回归测试，复测默认 init 模板并更新直接相关文档。

## Acceptance criteria

### I-AC01: 运行产物没有完整编译器

通过 esbuild metafile 和 Worker 执行测试证明默认产物不包含 Ajv 通用编译器、fast-uri，且启动不再执行 Schema 编译；允许必要的小型校验辅助代码。

### I-AC02: 校验语义与现有行为一致

覆盖输入、结果、消息的有效与无效数据、受支持 Schema、错误输出及输入投影；非法契约在构建时明确失败，既有合法任务继续运行。定向测试及 pnpm check 通过。

### I-AC03: 默认模板体积可复现下降

使用实际 init 模板及相同构建参数，记录改动前后的 Worker 字节数、依赖贡献和测量环境；验证分析产物与正式构建产物一致，且未依赖外部非内置模块缩小产物。
