# Deployment

## Steps

### D-S01: 验证独立消费环境

从已同步的实现提交生成实际包产物，在仓库外临时消费项目中通过公开 CLI/API 执行 init、author check、build 和 artifact check，不使用 workspace 链接、源码入口或仓库 node_modules。构建环境允许安装 Ajv 等构建依赖。

检查生成入口从实际安装的公开 Task SDK 显式导入并调用 runTask，且包清单声明所需 SDK 依赖；执行消费者自己的 TypeScript 类型检查。再通过消费者本地的自定义委托封装替换该调用，使用同一构建配置验证可替换性，不依赖尚未发布的 runCheck/runProbe。

将完整 Bundle 复制到另一个执行目录，通过真实 Task Engine/Worker 协议运行；该目录不得依赖作者源码、contract 模块、构建依赖或全局 Ajv。在执行阶段断网，验证所需代码和资源均已随 Bundle 交付，不把“构建工具中没有 Ajv”作为验收目标。

### D-S02: 验证真实任务与支持环境

在声明的最低支持 Node.js 和当前受支持开发运行环境验证默认 Echo 与一个包含组合约束、共享引用的代表性任务，记录成功运行及非法输入、结果、消息的拒绝结果。验证构建结果与实施阶段证据一致，不在部署阶段重新修改实现来迁就验证结果。

分别验证仅使用 contract 类型的默认入口与作者主动导入运行时 validator 的入口；后者允许增加体积，但其验证逻辑必须真实执行且依赖仍自包含。不能用主动导入 validator 的样例替代默认轻量模板的体积验收。

### D-S03: 固化来源和验证结论

记录包文件及摘要、来源提交、Node 环境、完整复现命令、隔离条件、文件字节数和任务结果。证据使用同层支持文件并在本契约中链接，不把执行日志写入 ledger。如需正式发布，单独遵循既有授权和流程；本构想不默认触发 npm 发布、服务部署或新增 IPFS 基础设施。

## Acceptance criteria

### D-AC01: 真实包可消费且产物可隔离运行

仓库外项目仅通过实际包产物及其声明依赖完成初始化、契约检查、构建和产物检查。复制出的 Bundle 在无作者源码、无构建工具依赖且断网的执行环境中，通过真实协议完成任务，并可重新启动运行；以包来源、命令、目录隔离方式及运行结果证明。执行宿主自身的已声明依赖不等于 Worker 可借用的隐式依赖，必须证明 Worker 仅依赖 Bundle 内容和 Node 内置模块。

生成源码可直接定位 SDK 导入与 runTask 调用，所需 SDK 依赖通过消费者安装正常解析，类型检查通过。默认入口和替换后的本地封装均只启动一次 Worker 协议处理，构建器不需要识别封装名称或替作者再套 runTask。记录消费者入口源码及实际包版本作为证据；未来高级封装 API 的正式实现不在本次部署验收范围。

### D-AC02: 消费侧校验与支持环境有效

在最低支持 Node.js 和当前受支持开发环境中，真实 Worker 对合法数据成功返回，对非法输入在回调前拒绝，对非法结果和消息产生与既有协议一致的失败；代表性任务的共享引用和组合约束实际生效。记录各案例的期望与实际结果，不能用 artifact check 成功、进程退出码为零或单个 Echo 成功代替数据校验验收。

作者仅 import type 的默认案例不带入 contract 的运行时代码；显式导入 validator 的案例确实执行作者选择的完整校验，非法业务数据被拒绝。记录两者依赖与体积差异，不把作者显式依赖误报为 SDK 固定开销，也不能因此掩盖 SDK 的间接编译器依赖。

### D-AC03: 消费侧体积与交付证据可追溯

独立消费者默认模板的 Worker 及 Bundle 文件总字节数低于同环境旧包基线，不借外置文件或外部依赖转移体积。包内构建路径的依赖图满足 [Implementation.md 的 I-AC01](inner/Implementation.md#i-ac01-显式入口与运行期依赖隔离)，并与消费者实际输出对应；记录包摘要、提交和环境差异，解释与实施阶段测量的偏差。不能把仓库内测试或 gzip 数字当成消费侧验收结果，也不要求对所有业务任务作统一体积承诺。
