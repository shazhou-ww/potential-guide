# Implementation

本契约为轻量实施种子；具体文件结构与覆盖规则在构想阶段确认，不依赖 JSONC 主配置提前实施。

## Steps

### I-S01: 抽离资源契约和加载边界

按确认的 URI、文件结构及作用域建立独立 Agent 定义读取和校验，复用 profile 类型及规范化逻辑，保持普通设置与资源分离。

### I-S02: 统一管理与执行消费

新增 pguide agents，更新默认分发、诊断、治理、监督和相关工具消费；明确旧 config Agent 操作的退出及显式迁移，不双轨维护校验器。

### I-S03: 验证写入和升级

覆盖作用域、同名定义、默认名称、协议选择、凭据引用及错误写入；迁移验证原子性与保留原始数据，更新相关文档和交付检查。

## Acceptance criteria

### I-AC01: 独立管理可用

单元和集成测试证明有效 Agent 文件的校验、选择及约定管理操作一致，旧配置不会被静默合并使用。

### I-AC02: 消费与作用域一致

通过用户/项目覆盖、来源展示、未知默认名称、ACP/AHP 等场景，证明管理、诊断与执行使用同一有效 profile。

### I-AC03: 升级不损坏或泄密

迁移和非法输入测试证明确切报错、失败不替换原文件、凭据只保留引用且输出脱敏；执行仓库相关检查。
