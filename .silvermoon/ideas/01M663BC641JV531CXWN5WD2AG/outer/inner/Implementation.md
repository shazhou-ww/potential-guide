# Implementation

准备阶段的三轮迭代计划，2026-10-31。用户已要求按可试用增量整理范围与完成标准；本次不是开工或构想验收授权。需求见[构想](ideal/Idea.md)、[需求确认稿](ideal/Requirements.md)与[交互设计](ideal/Design.md)。

按 I-S01 → I-S02 → I-S03 形成增量，每轮交付可运行的完整流程，不按“先全部后端、再全部页面”划分。迭代不是额外生命周期或 gate：每轮可进行实现阶段的本地集成试用并吸收体验反馈，但不提前勾选 [Deployment](../Deployment.md) 的外部结果；正式阶段转换仍遵循本 idea 的独立流程。

共同完成条件适用于每轮，而非拖到第三轮：

- 从第一轮具备可信 Endpoint 配置、凭据保护、访问控制、受限代理、目标隔离、提交幂等和连接/资源释放。错误、旧数据和提交结果未知显式呈现，不以关闭 UI 或断流取消任务。
- 直接相关的自动化测试与文档对应实际行为，pnpm check 通过；有可复核的运行方式和可试用增量，不以静态草图、测试替身或仅成功路径当作功能完成。
- 保持中文、键盘与焦点可用、Task/Execution 分区，以及窄屏可操作；不要求用户逐项审 UX 草图。只操作本轮拥有的验证资源，不修改其他会话服务或发布 npm 包。
- 首版只含 US-01 至 US-06、US-10、US-11，不恢复资产管理、高级 Input 查询、全局遥测或 UI 治理配置。当前不估工期，不预先展开详细任务树或选技术栈。

## Steps

### I-S01: 迭代一单任务闭环

获准实施后，交付“选择 Endpoint → 按类型填表 → 快捷创建单条任务栏批次 → 提交 → 观察 Task 与关联 Execution → 查看事件/结果或显式取消”的完整路径，覆盖 US-01、US-02、US-04、US-06 的基础能力。

建立始终存在的任务栏与统一提交身份/回执处理，后续多条、收藏、重做复用它。表单只消费公开 Task 输入 Schema，自由对象提供通用编辑；不下载制品、不猜业务字段。凭据、目标隔离及失败/未知处理与这条闭环同时交付。

### I-S02: 迭代二多任务调度实验

在 I-S01 的提交流程与观察能力上，增加同一 Endpoint 的多条草稿、提交排序、逐条回执和多 Task/Execution 对照，覆盖 US-03、US-05，并深化 US-04、US-06 的排队、共享、取消和超时实验。

失败或结果未知不阻塞后续条目，快捷单条不误发多条草稿。补齐多任务情况下的事件分页/SSE 断流恢复、目标切换和迟到响应隔离；只展示服务能证明的执行关联与回收事实，不增加并发度/调度策略控制或全局资源图。

### I-S03: 迭代三历史与复用

在 I-S01/I-S02 的创建与观察路径上，交付同机持久收藏、Endpoint 历史类型/时间查询与分页，以及直接或编辑确认后重做，覆盖 US-10、US-11。

收藏保存完整原参数及目标关联，UI 重启后可继续使用；具体本机存储方式在实现前收敛，不引入账号同步。历史来自公开服务目录，包含其他客户端提交的获授权且仍保留的任务。两种复用都走统一提交模型，不自动补锁、解锁或改写 URL；保留与清理由 Service 治理。

## Acceptance criteria

### I-AC01: 单任务可试用且边界可靠

- 以发现/表单测试证明至少两种不同输入结构按真实契约呈现，不硬编码业务类型，也不依赖资产接口。
- 以提交与故障测试证明单条快捷只创建单条批次，回执可进入真实 Task/Execution；重复点击、同次重试与主动再做一次身份正确，结果未知不冒充失败或偷偷新建请求。
- 以状态/事件与本地集成验证证明输入、阶段、取消、超时、公开事件、结果/故障有明确位置，业务否定结果不误标系统执行失败；Task 取消不被解释为 Execution 已回收。
- 以目标切换、授权、受限代理和退出测试证明不串数据或凭据，UI/流关闭不取消后端任务；可运行说明及每轮共同完成条件均满足。

### I-AC02: 多任务实验可观察且不误提交

- 以至少三条输入的批次测试证明提交按排列先后发起，不等待前一任务完成；中间条目失败/未知后仍继续后项，成功项不会被含糊的整批重试重复创建。
- 以单条快捷与待发多条共存测试证明草稿及请求身份隔离；目标切换、迟到回执和连接恢复不向错误 Endpoint 执行操作。
- 在服务已配置的受限资源及可匹配条件下，以公开绑定/执行事件证明两个 Task 关联同一 Execution、另一 Task 等待，以及共享任务取消/超时后的独立事实；不以相同输入或结果自行认定共享。
- 以分页、断流/重连与历史过期测试证明顺序和去重遵循公开契约，缺口或旧数据明确标识，不因断流重提任务；I-AC01 及每轮共同条件继续通过。

### I-AC03: 历史与原参数复用完整

- 以目录集成测试证明其他客户端创建的授权保留任务可按类型和约定时间范围查到，分页针对服务范围而非当前加载页；另一 scope、失效游标和已清理详情按契约明确处理。
- 以同机重启测试证明收藏及 Endpoint 关联保留且不含后端凭据；目标被移除或类型/Schema 不兼容时明确说明，不静默改投、猜字段或改写输入。
- 以直接/编辑后复用测试证明完整参数可作为模板、原收藏不被派生操作修改；原来未锁仍未锁、已锁仍保留，新提交不复用原 requestId，原请求不可取得时不以空输入冒充重做。
- I-AC01、I-AC02 及共同条件继续通过；US-07 至 US-09、高级 Input 筛选与 UI 历史治理不进入交付，形成覆盖首版有效故事的可运行版本。
