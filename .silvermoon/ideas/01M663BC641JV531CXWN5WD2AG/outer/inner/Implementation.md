## 实现期细化

- 应用位于 `apps/task-engine-web-ui`，使用现有 Node/TypeScript、esbuild、Biome 与 tsx/Node test runner；DOM 表单测试使用 catalog 中的 linkedom。应用为 private，没有 npm 发布入口。按本仓库标准补充工作区、工具层及 package-owned objectives；`apps` 下的独立 Node 服务采用明确单路径布局例外，不改通用检查规则。
- UI Server 仅提供固定静态资源、受控 HTTP 转发与本机收藏。运行入口不导入/启动 Engine；Task Server 仅由显式 fixture 和集成测试启动。凭据来自服务端环境变量，配置目标的 URL/身份绑定生成不可逆指纹。只监听 loopback，校验 Host/Origin/跨站请求和会话 token，限制路径/方法/头、请求与响应大小、并发、流与超时，拒绝重定向。
- 创建、批次、收藏与历史重做共用提交模型。原参数、quoted revision 和新 ULID 身份分开，未知提交保留原身份/guard；原身份重试和主动新做分开。类型表单只消费公开输入 Schema，不使用 Equals、不下载输入引用。
- Task 与 Execution 各自观察；目录 next、历史 next 与 SSE cursor 独立。历史页与受限实时事件窗口分开保留，断流/过期/截断明确显示。目录保持冻结摘要与原查询，重做只取原请求，不注入摘要版本。
- 收藏是操作员指定位置的受限 JSON 文件，以原子替换持久化；不引入数据库、账号或同步。目标缺失/显式重新绑定时阻止快捷改投。未提交表单和本次回执不宣称跨重启持久，收藏与后端目录承担原需求中的复用与历史职责。

**依赖前置已满足；本次实施使用本 UI 自身的 acceptIdeal#4，不继承依赖的 gate 授权。** 在主线 `0b0a25fba63ef57065540fbc7c42e53bd92a729f`，已通过 Silvermoon 核实 `task-type-schema-discovery`、`task-history-query`、`terminated-after-eligible` 均为 `completed`，并对照源码确认公开契约。接入基线见[当前接口核对](ideal/Research.md#当前接口核对)。启动 I-S01 时已再次确认本 idea 为 implementing，并直接核对实际 DTO、HTTP handler 与协议文档。

## Steps

### I-S01: 双 Tab 与弹窗提交闭环

主界面只保留任务/执行两个 Tab，任务页整合真实目录与详情；创建/编辑重做使用可访问弹窗，任务栏保持常驻入口。切换、关闭/重开弹窗及返回详情不丢本次输入、筛选与选中对象；以中文主状态优先呈现结果。

确认 Schema idea 已完成并满足本 UI 自身开工条件后，交付“选择 Endpoint → 按类型填表 → 快捷创建单条任务栏批次 → 提交 → 观察 Task 与关联 Execution → 查看事件/结果或显式取消”的完整路径，覆盖 US-01、US-02、US-04、US-06 的基础能力。

建立始终存在的任务栏与统一提交身份/回执处理，后续多条、收藏、重做复用它。表单只消费公开 Task 输入 Schema，自由对象提供通用编辑；不下载制品、不猜业务字段。新提交使用当前发现 revision 的 If-Match，契约变化保留草稿并显式处理；Idempotency-Key 独立于 revision，结果未知后不能通过去掉 guard 或新建身份静默再发。凭据、目标隔离及失败/未知处理与这条闭环同时交付。

### I-S02: 执行目录与观察收尾

补齐真实 Endpoint 执行目录与 UI 接入，包含跨客户端、scope/授权、去重、冻结分页/独立游标、保留及重启证据。明确已完成与观察通道；终结/回收证据充分后自动停止流，停止观察不取消任务，不使历史分页失效；未知回收不能猜测为已结束。

在 I-S01 的提交流程与观察能力上，增加同一 Endpoint 的多条草稿、提交排序、逐条回执和多 Task/Execution 对照，覆盖 US-03、US-05，并深化 US-04、US-06 的排队、共享、取消和超时实验。

失败或结果未知不阻塞后续条目，快捷单条不误发多条草稿。补齐多任务情况下的事件分页/SSE 断流恢复、目标切换和迟到响应隔离；只展示服务能证明的执行关联与回收事实，不增加并发度/调度策略控制或全局资源图。

### I-S03: 任务星标与历史复用

收藏改为任务行/详情的星标与任务页过滤，覆盖全部本机星标而非当前页；保留 Task 身份、Endpoint 和完整原参数，源记录清理后仍有明确标注的模板。兼容旧收藏文件，不能静默丢弃或伪造旧模板的 Task 身份。

在 I-S01/I-S02 的创建与观察路径上，交付同机持久收藏、Endpoint 历史类型/时间查询与分页，以及直接或编辑确认后重做，覆盖 US-10、US-11。

收藏保存完整原参数及目标关联，沿用操作员指定的同机 JSON 文件并兼容旧模板，UI 重启后可继续使用；不引入账号同步或跟随服务历史自动淘汰收藏。历史来自公开目录，包含其他客户端提交的获授权保留任务；只以 GET `/requests/:requestId` 返回的原参数重做，不把列表摘要的 version 塞进业务请求。两种复用都走统一提交模型，不自动补锁、解锁或改写 URL；保留与清理由 Service 治理。

## Acceptance criteria

### I-AC01: 单任务可试用且边界可靠

- 任务/执行列表打开详情前后宽度相同，覆盖抽屉贴右且不参与列表布局；关闭、Escape、焦点返回、筛选/分页/滚动位置及关联跳转正确，窄屏抽屉内部滚动且无全页溢出。
- 顶栏与 Tabs 在宽屏同一导航层；实际 shadcn 组件参与渲染、许可与 catalog 依赖可追溯，生产静态构建可离线加载。组件引入不破坏 CSP、焦点/模态边界或既有 Schema、收藏竞态、提交身份及观察收尾回归。

- 真实 browser entry 与浏览器证明仅两个主 Tab、弹窗创建/编辑、焦点返回和 Tab/草稿状态保留；提交成功定位任务详情，任务栏入口持续可用。

- 以发现/表单测试证明至少两种不同输入结构按真实契约呈现，不硬编码业务类型，也不依赖资产接口。
- 以 412/contract_revision_mismatch 场景证明表单不会按失效契约悄悄提交；若此前提交结果未知，当前 412 不能被视为原任务必然不存在，保留原身份并明确核对。
- 以提交与故障测试证明单条快捷只创建单条批次，回执可进入真实 Task/Execution；重复点击、同次重试与主动再做一次身份正确，结果未知不冒充失败或偷偷新建请求。
- 以状态/事件与本地集成验证证明输入、阶段、取消、超时、公开事件、结果/故障有明确位置，业务否定结果不误标系统执行失败；Task 取消不被解释为 Execution 已回收。
- 以目标切换、授权、受限代理和退出测试证明不串数据或凭据，UI/流关闭不取消后端任务；可运行说明及每轮共同完成条件均满足。

### I-AC02: 多任务实验可观察且不误提交

- 执行目录覆盖其他客户端记录且共享执行去重；Memory/SQLite、重启、跨 scope/授权、冻结分页/失效和混用游标负向测试通过，摘要不泄漏业务载荷或无权限关联。
- 任务完成与执行回收后 Observation 收尾；取消/超时/失败/未知回收不被混同，停止后历史分页与重新观察仍可用，所有因果回归保留。

- 以至少三条输入的批次测试证明提交按排列先后发起，不等待前一任务完成；中间条目失败/未知后仍继续后项，成功项不会被含糊的整批重试重复创建。
- 以单条快捷与待发多条共存测试证明草稿及请求身份隔离；目标切换、迟到回执和连接恢复不向错误 Endpoint 执行操作。
- 在服务已配置的受限资源及可匹配条件下，以公开绑定/执行事件证明两个 Task 关联同一 Execution、另一 Task 等待，以及共享任务取消/超时后的独立事实；不以相同输入或结果自行认定共享。
- 以分页、断流/重连与历史过期测试证明顺序和去重遵循公开契约，缺口或旧数据明确标识，不因断流重提任务；I-AC01 及每轮共同条件继续通过。

### I-AC03: 历史与原参数复用完整

- 标星/取消星标幂等，“只看收藏”包含未加载页中的全部本机星标；跨 Endpoint、源记录清理、旧格式收藏与服务重启均不静默丢数据或改投。

- 以目录集成测试证明跨客户端授权任务可按类型和 receivedAt 的含下界/不含上界范围查到；分页成员、顺序及摘要固定，详情为另一次读取，不能把实时事件覆盖进冻结列表。用 query_expired、invalid_cursor、401/403、413/429 验证错误不冒充空结果或部分成功。
- 以同机重启测试证明收藏及 Endpoint 关联保留且不含后端凭据；目标被移除或类型/Schema 不兼容时明确说明，不静默改投、猜字段或改写输入。
- 以直接/编辑后复用测试证明完整参数可作为模板、原收藏不被派生操作修改；原来未锁仍未锁、已锁仍保留，新提交不复用原 requestId，原请求不可取得时不以空输入冒充重做。
- I-AC01、I-AC02 及共同条件继续通过；US-07 至 US-09、高级 Input 筛选与 UI 历史治理不进入交付，形成覆盖首版有效故事的可运行版本。
