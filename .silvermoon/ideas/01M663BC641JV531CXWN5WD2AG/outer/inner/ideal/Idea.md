# 为通用任务服务提供可选调试 Web UI

## 问题

客户已有 Task Engine Server，需要直观尝试其能力；每次通过命令行或代码发送 HTTP 请求不够直观。同时需要观察多个任务的资源分配，以及取消、超时等边界情况下的实际调度行为。

## 结果

提供按类型填表的任务操作面板，日常单条提交、偶尔批量发送，观察调度与生命周期。支持资产缓存查看、历史版本选择、手动清理、收藏再发及历史重做；用户故事和验收例子见[需求确认稿](Requirements.md)，访谈依据见[记录](UseCases.md)。

## 边界

1. Web UI Server 与 Task Engine Server 分离；仅依赖公开协议，不内嵌或启动引擎，UI 退出或断流不取消任务。
2. 与 Check、Probe、Regulate 推进顺序独立；资产归任务类型而非通用任务内核管理，不内置业务执行器、不增加上传或本机文件导入、不假装提供服务器全量任务列表。
3. 不暴露后端凭据、不提供任意地址代理；错误与事实如实呈现。缺失的服务能力及需求确认稿列明的未决细节，实施前明确归属和规则，不擅自删减范围。

## 验收标准

1. 能按类型填表、单条或按序批量提交；观察排队、合并、取消、超时、stage、关键过程与事件详情，以需求确认稿 US-01 至 US-06 的场景证明。
2. 能查看类型资产缓存、选历史版本运行、手动清理旧缓存，并收藏再发、模板修改及历史重做，以 US-07 至 US-11 的场景和实施前补齐的规则证明。
3. UI 与后端独立运行；关闭 UI 不取消任务，任务、资产和连接事实不误导，访问与资源边界有效，以独立进程及失败路径验证证明。
