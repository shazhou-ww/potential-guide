# 为通用任务服务提供可选调试 Web UI

## 问题

客户已有 Task Engine Server，需要直观尝试其能力；每次通过命令行或代码发送 HTTP 请求不够直观。同时需要观察多个任务的资源分配，以及取消、超时等边界情况下的实际调度行为。

## 结果

提供按类型填表的任务操作面板，日常单条提交、偶尔批量发送，观察调度与生命周期。支持查看类型资产缓存、选历史 artifact 版本运行、手动清理旧缓存；收藏完整 artifacts 与 subject，原样一键再发或作模板修改后发起，并支持历史任务重做。

## 边界

1. Web UI Server 与 Task Engine Server 分离；仅依赖公开协议，不内嵌或启动引擎，UI 退出或断流不取消任务。
2. 与 Check、Probe、Regulate 推进顺序独立；资产归任务类型而非通用任务内核管理，不内置业务执行器、不增加上传或本机文件导入、不假装提供服务器全量任务列表。
3. 不暴露后端凭据、不提供任意地址代理；访问、资源与故障边界必须明确。连接及部署方案仍属候选，见[需求与用例分析](UseCases.md)。

## 验收标准

以下仅为前一轮 Agent 提出的候选，待访谈后保留、修改或删除，不构成已确认需求或验收：

1. 能对通用 JSON Task 完成提交、幂等重试、按已知 ID 查询及显式取消，新业务类型无需修改 UI。
2. 快照、结果、故障、历史分页与事件恢复忠实反映协议；连接、流、任务状态分离，不把正常业务否定结果误标执行故障。
3. 独立进程验证 UI 可选且不影响后端任务；跨目标隔离、错误可见性与资源限制有可核对证据。
