# 为通用任务服务提供可选调试 Web UI

## 问题

客户已有 Task Engine Server，需要直观尝试其能力；每次通过命令行或代码发送 HTTP 请求不够直观。同时需要观察多个任务的资源分配，以及取消、超时等边界情况下的实际调度行为。

## 结果

提供以“任务 / 执行”两个 Tab 组织的操作面板：任务页整合当前与历史任务，新建使用弹窗，收藏是任务标星及筛选；执行页查询整个 Endpoint 获授权且保留的执行记录。统一提交任务栏保持常驻入口，完成结果与实时观察状态分开呈现并可靠收尾。收藏仍同机保存完整原参数和 Endpoint，不增加账号同步或资产管理。需求和用户试用反馈见[需求确认稿](Requirements.md)。

## 边界

1. Web UI Server 与 Task Engine Server 分离；仅依赖公开协议，不内嵌或启动引擎，UI 退出或断流不取消任务。
2. 与 Check、Probe、Regulate 推进顺序独立；通用 Engine 及 Web UI 不承担资产管理，也不要求 Task 提供通用资产接口。历史保留与清理由 Service 治理；不内置业务执行器、不增加上传或本机文件导入，不以本机已知任务冒充全量历史。
3. 不暴露后端凭据、不提供任意地址代理；错误、列表快照与实时详情如实呈现。本轮明确补齐服务端执行目录及其公开协议，UI 仍只消费公开能力，不遍历事件或本机已见记录来冒充全量执行目录，不改变调度与共享语义。

## 验收标准

1. 两个主 Tab 一次只显示相应任务或执行页面，新建与编辑重做使用弹窗，任务栏入口常驻；完整保留 US-01 至 US-06 的提交、关联、取消、超时与事件能力，切换视图不丢草稿或重提请求。
2. 任务页可标星、查看全部本机星标任务并原参数重做，且具备真实 Endpoint 任务目录；执行页也有覆盖其他客户端记录的真实授权目录。以 US-10 至 US-12 证明，不以当前页或本机已见记录代替完整查询。
3. UI 与后端独立运行；终结与回收证据充分后停止实时观察但保留结果和可分页历史，提供重新观察。任务、执行和连接事实不误导，凭据、权限、游标和资源边界有效。
