# 为通用任务服务提供可选调试 Web UI

## 问题

客户已有 Task Engine Server，需要直观尝试其能力；每次通过命令行或代码发送 HTTP 请求不够直观。同时需要观察多个任务的资源分配，以及取消、超时等边界情况下的实际调度行为。

## 结果

提供按类型填表的任务操作面板，日常单条提交、偶尔批量发送，观察调度与生命周期。首版支持同机收藏再发及 Endpoint 全量历史查询与重做；收藏记住对应 Endpoint，不增加账号体系或跨设备同步，不包含资产管理。用户故事和验收例子见[需求确认稿](Requirements.md)，访谈依据见[记录](UseCases.md)。

## 边界

1. Web UI Server 与 Task Engine Server 分离；仅依赖公开协议，不内嵌或启动引擎，UI 退出或断流不取消任务。
2. 与 Check、Probe、Regulate 推进顺序独立；通用 Engine 及 Web UI 不承担资产管理，也不要求 Task 提供通用资产接口。历史保留与清理由 Service 治理；不内置业务执行器、不增加上传或本机文件导入，不以本机已知任务冒充全量历史。
3. 不暴露后端凭据、不提供任意地址代理；错误、列表快照与实时详情如实呈现。仅消费已交付的公开契约，按需求确定的边界实现，不擅自删减范围或扩大到资产管理。

## 验收标准

1. 能按类型填表，通过统一任务栏快捷单条或按序多条提交；Task 与 Execution 分区且关联清楚，观察排队、合并、取消、超时、stage、过程与事件，以需求确认稿 US-01 至 US-06 的场景证明。
2. 能收藏完整任务参数、直接或编辑后再发，查询 Endpoint 历史并以原参数重做，以 US-10、US-11 及补齐规则证明；URL、digest 等仅作为普通输入保存，不引入资产浏览、选版或清理能力。
3. UI 与后端独立运行；关闭 UI 不取消任务，任务、执行和连接事实不误导，访问与资源边界有效，以独立进程及失败路径验证证明。
