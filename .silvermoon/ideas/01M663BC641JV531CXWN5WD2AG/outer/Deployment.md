## Steps

### D-S01: 准备独立真实验证环境

在明确拥有的临时资源上启动不同端口的 UI 与通用 Task Server，记录 UI、Schema 发现、任务协议及历史查询的实际版本和权限范围；明确 submit/discovery、list、task/request/history 等权限区别。不复用或改动其他会话服务，不以测试替身代替真实服务消费，不发布 npm 包。

### D-S02: 验证浏览器调试流程

本轮以“任务/执行”两个 Tab 验证完整流程，涵盖新建/编辑 Popup、任务星标与全量星标过滤、跨客户端执行目录及页间互相定位；证明停止 Observation 后结果稳定且历史仍可读取。

按三轮流程验证：先完成 Schema 填表、revision/If-Match 失配、单条快捷、Task/Execution 观察与取消；再执行多条排序发送、共享/排队/超时及断流恢复；最后验证同机收藏、Endpoint 冻结目录/失效重查与原参数重做，历史样本包括其他验证客户端提交的任务。进行浏览器实测和截图检查，验证中文、键盘操作与窄屏布局，并记录用户实际试用反馈；不执行资产管理或缓存清理验收。

### D-S03: 验证生命周期并清理

每次试用确认无 UI 与 UI 退出时后端任务仍可运行，随后仅清理本次验证拥有的进程、连接与临时资源；正式验证结束再汇总残留资源和未解决反馈，不把草图评价代替实际使用结果。

## Acceptance criteria

### D-AC01: 服务分离与任务独立

以进程、监听端口及 UI 停止前后的后端查询证据证明独立运行；UI 关闭不取消任务。

### D-AC02: 真实用例可操作

新版实际页面不再纵向堆所有区块；执行目录不是本机子集；星标无独立页面/弹窗；正常 Echo 完成回收后不再持续刷新 Observation。记录桌面/窄屏截图与键盘路径，并提供用户可继续试用的地址。

以真实服务请求/事件、浏览器操作及截图证明 US-01 至 US-06、US-10 至 US-12 和补齐规则有效，结果与 I-AC01 至 I-AC03 的内部验证一致；历史范围遵守 Service 权限和保留策略，新通用类型不要求 UI 硬编码输入或资产接口。真实试用中未解决的问题明确保留，不因迭代计划已写好就视为完成。

### D-AC03: 验证隔离且资源可回收

以验证资源清单与退出检查证明只清理自身资源，其他 checkout、会话工作树与既有服务不受影响。
