# Deployment

准备阶段的轻量种子；尚未实施或部署，不构成验收。进入相应阶段后再细化验证环境与证据。

[实施计划](inner/Implementation.md)的三轮增量各自提供可试用版本。实现阶段的本地试用与自动化结果不提前完成本外部契约；正式验证可按单任务、多任务、历史复用分次进行，但最终证据须对应同一明确候选及其实际依赖版本。每次验证结束都回收自身临时资源，不等待最后一轮才清理。

## Steps

### D-S01: 准备独立真实验证环境

在明确拥有的临时资源上启动不同端口的 UI 与通用 Task Server，记录 UI、Schema 发现、任务协议及历史查询的实际版本和权限范围；不复用或改动其他会话服务，不以测试替身代替真实服务消费，不发布 npm 包。

### D-S02: 验证浏览器调试流程

按三轮流程验证：先完成 Schema 填表、单条快捷、Task/Execution 观察与取消；再执行多条排序发送、共享/排队/超时及断流恢复；最后验证同机收藏、Endpoint 历史和直接/编辑后重做，历史样本包括其他验证客户端提交的任务。进行浏览器实测和截图检查，验证中文、键盘操作与窄屏布局，并记录用户实际试用反馈；不执行资产管理或缓存清理验收。

### D-S03: 验证生命周期并清理

每次试用确认无 UI 与 UI 退出时后端任务仍可运行，随后仅清理本次验证拥有的进程、连接与临时资源；正式验证结束再汇总残留资源和未解决反馈，不把草图评价代替实际使用结果。

## Acceptance criteria

### D-AC01: 服务分离与任务独立

以进程、监听端口及 UI 停止前后的后端查询证据证明独立运行；UI 关闭不取消任务。

### D-AC02: 真实用例可操作

以真实服务请求/事件、浏览器操作及截图证明三轮对应的 US-01 至 US-06、US-10、US-11 和补齐规则有效，结果与 I-AC01 至 I-AC03 的内部验证一致；历史范围遵守 Service 权限和保留策略，新通用类型不要求 UI 硬编码输入或资产接口。真实试用中未解决的问题明确保留，不因迭代计划已写好就视为完成。

### D-AC03: 验证隔离且资源可回收

以验证资源清单与退出检查证明只清理自身资源，其他 checkout、会话工作树与既有服务不受影响。
