# Implementation

本项是第三阶段，实施前置为 Probe 及其依赖的 MVP 已交付并验收。
以下为可调整准备种子，具体接入根据前置包的实际契约细化。
资源与协作采用最新[讨论决定](ideal/Discussion.md)：移除独立治理时间配额与连续停滞限制，
不另设共享 execution 固定总上限，正常阻碍不作执行故障，复用 ACP/AHP Agent 接入；
复用既有治理算法时按这些差异适配，不自动改写未迁移旧调用方。

## Steps

### I-S01: 定义治理类型与职责交接

建立 `regulate-task` 工厂和输入、准备、进展、结果契约，复用现有单次治理算法。
调用方使用准确 Objective 引用、subject、目标和治理参数，不预先提供内部 PilotSpec 或存储键。
Objective 的复用与合流身份按 Digest/Revision 而非 URI 判定，并保留来源证据；
同 subject 和执行环境兼容仍是必要条件，不隐式跨 Digest 升级旧请求。
明确 Task 期限、各笔资源投入、单个 Agent 限额的不同边界；
等待期限只用 Task Deadline，单次 Agent 超时是执行安全限制，不再设置独立治理时间配额。
以实际资源消耗控制继续修复，所有已启用额度必须同时未耗尽，首版不强制 Token 统计。
按投入接纳顺序记账，修复启动前预留、实际启动扣一次且之后不退还，取消撤回未用投入。
支持独立期限、按新观察分别完成及结束后以新 execution 接续，不改写旧结果；
追加协议、参与者超时后的投入处理及执行中退出细节仍待准备期讨论。
梳理 Coordinator 中交还通用引擎的职责和仍保留的跨目标业务策略，不维护两份同一任务真相。

### I-S02: 接入 Probe 与受授权 Agent

通过受信任端口调用 Probe 和 Agent，保留观察、修复、再观察的因果证据。
复用既有 ACP/AHP 命名 profiles、共享客户端和恢复身份，不另建 Agent 配置或传输体系；
以 VS Code Copilot AHP 的实际能力验证接入，不将现有 fixture 等同于真实 Host 验证。
操作权限由 Agent 可信执行环境授予和约束，不属于任务或出资方，
不按投入方拼接权限；Agent 可以申请权限，但不得仅凭请求或检查报告自动扩大授权。
明确阻碍与外部处理信息，区分 Agent 等待交互、已返回正常阻碍和执行故障。
分别约束父治理、子 Probe/Check 与修复资源，验证容量等待、取消与实际退出；
固定副作用执行的身份和兼容规则，不机械复用只读观察共享策略。
业务资源竞争由 Agent/适配器处理，不新增 Regulate 目录锁或统一冲突排队；
引擎仍负责自身 Worker 容量及执行器退出清理边界。

### I-S03: 完成服务接入与恢复验证

提供同一 Server 注册三类 Task 的受控配置、业务结果说明和包导出。
复用通用持久恢复与历史接口，明确修复未知结局的处置；保留原始准确版本与权限边界，
不以服务重启、重复请求或 SDK 重连隐式启动新修复。
可靠证明退出与清理后可自动释放相应执行资源隔离，不能证明则报告阻碍；
核实远端 AHP 停止证据，不能把连接关闭当作远端退出，不停止共享 Host 或无关会话。
保持未迁移旧调用方行为，建立相关回归和打包验证。

## Acceptance criteria

### I-AC01: 治理结果由观察证明

用目标达成、各类资源预算耗尽、动态依赖及 Agent 故障测试证明结果分类准确；
证明未跨 Level 不会单独触发停滞退出，任一已启用资源预算耗尽即禁止该预算支持的后续修复；
证明自身投入额度耗尽仍可受益于已有兼容投入、各请求按新观察分别完成，
以及末次重查后所有现有投入均不可用时未达标请求立即耗尽；
证明先到投入先消耗、启动前撤销不扣轮数、启动后失败或取消不退款且不重复扣账，
持续追加不触发固定 execution 总上限，结束后追加不复活旧请求。
证明等待不重置 Task Deadline，不引入第二个治理计时器；
修复后的真实 Probe 才能证明达标；耗尽与外部阻碍是正常业务结果，
不冒充目标达成，也不被误报为执行故障。

### I-AC02: 授权与副作用边界可靠

用权限不足、跨作用域、并发治理、重复请求、取消和真实执行器退出用例，
证明不扩大权限、不意外共享修复、不伤其他需求；父子资源受限时有界推进或明确失败。
取消撤回未用投入导致其他请求无资源时正常返回耗尽，物理退出与清理前不得复用容量；
投入增减不隐式授予或撤销 Agent 权限。
故障注入和 SQLite 进程重启证明未知修复不自动重跑、原任务身份及历史证据保留，
只有可靠退出和清理证明才能复用相应容量，不冒充拥有业务资源的全局互斥。

### I-AC03: 三类任务闭环可交付

进程内与真实 HTTP/SSE 对照测试证明三类任务协作不需改造通用 Server 内核，
历史中可按授权追溯观察和修复。独立打包消费者、依赖检查及 `pnpm check` 通过，
真实 ACP/AHP 配置复用和 AHP 闭环具有明确验证路径，未迁移的旧治理入口仍符合原契约。
