# Implementation

## Steps

### I-S01: 刷新当前链路与失败分类

以当前 Bundle Engine、TypeSupervisor、Server 和 Check 环境消费者替代旧 Probe 适配测试入口，逐例区分配置/准入拒绝、启动、观察等待和回收未知。保留历史报告的源码与环境绑定，不从重试结果推断根因。

### I-S02: 落实改动与针对性回归

基于现有生命周期事实形成有界诊断投影，对启动阻塞、迟到退出及缺失回收证明分别构建可控入口。关联数据域 revision、Run/generation 和预算；独立日志 sequence 不参与生命周期裁决，不记录秘密或任意业务载荷。

## Acceptance criteria

### I-AC01: 分类与诊断绑定真实事实

以受控故障和配置拒绝测试证明分类指向当前责任组件，诊断能指出最后已知阶段及缺失事实；没有 Task/Run 的准入拒绝不伪造运行身份，无法复现的历史原因不标已修复。

### I-AC02: 回归保持既有保护

注入启动阻塞、迟到退出及缺失确认，核对不提前写 reclaimedAt；正常路径诊断开销有界且不阻塞回收。 适用的仓库检查通过，未降低既有约束。
