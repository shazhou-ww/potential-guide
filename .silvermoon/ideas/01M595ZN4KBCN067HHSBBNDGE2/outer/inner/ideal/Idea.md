# 按项目交付需求验证 pnpm monorepo 合理性

## 问题

仅检查 workspace 或目录模板，无法证明包的组织与配置能支撑项目交付需求；缺少统一的需求依据和可定位的偏离报告。

## 结果

提供两层顺序检查的 Objective：先验证项目结构、全局需求契约及 package 映射，再按每项需求检查相关包的依赖、构建和交付准备。具体范围见[检查范围](./checks.md)。

## 边界

- 不判断项目是否应该采用 monorepo，不以固定包数量或拆分方式代替需求。
- 检查只观察和报告；不自动发布、部署、迁移数据或修改配置，不把交付准备等同于线上验收。
- OIDC 等能力仅按需求适用；不读取秘密值，不把缺少证据或不支持的类型判为通过。

## 验收标准

1. 第一层能定位 layout、必要文件、全局配置 schema 和 workspace 引用的一致性问题，并对不合规范或放错位置的现有文件给出归位建议。
2. 第二层能按需求关联包，并区分公共库、CLI、前端、线上服务及内部共享包的适用检查。
3. 报告能追溯需求、包与证据，区分满足、不满足、未验证和不适用，且不声称未检查的线上结果。
