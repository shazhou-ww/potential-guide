# Deployment

准备阶段的外部验证初版；不包含 npm 发布、撤包或 dist-tag 修改授权。

## Steps

### D-S01: 在隔离消费者中验证新交付

从同步后的确定提交打包并安装通用 SDK 与 Server 到独立目录。
作者构建最小业务无关 Bundle，宿主通过标准 Request 执行；
不使用仓库源码回退、全局 CLI 或两个退役包。

### D-S02: 验证依赖闭包与消费边界

检查真实安装图、包导出和示例入口，确认消费者不安装两个退役包；
记录产物身份、命令、结果及必要环境信息，确认通用执行结果而非只验证导入成功。

### D-S03: 交付退役说明

说明已移除的旧业务入口、仍支持的通用 Bundle 用法与尚未实现的新业务能力。
若外部已有发布版本，仅说明其不受此次仓库删除自动影响；
不隐式执行 npm deprecate、unpublish 或数据迁移。

## Acceptance criteria

### D-AC01: 独立运行不依赖旧包

隔离作者／宿主环境中完成真实 Bundle 构建、受理与结果读取，
提供确定提交及执行证据；安装图不含两个退役包，不依赖工作区路径。

### D-AC02: 消费者不再获得旧执行能力

通过独立安装图、导出核验及退役入口检查证明旧适配器未换名交付；
使用者能够从说明区分旧业务缺失与通用 Engine 可用，不承诺自动迁移。

### D-AC03: 外部变化范围明确

文档与证据可定位到同一确定提交，明确此次未发布 npm、未改变已发布版本、
未重放旧任务；若实际外部环境不可验证，记录阻塞，不用仓库单测冒充部署完成。
