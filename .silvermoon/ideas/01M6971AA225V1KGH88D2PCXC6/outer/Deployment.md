# Deployment

这是准备阶段的轻量初版。仅针对开发环境切换，不包含 npm 发布、生产迁移或本阶段的数据删除。

## Steps

### D-S01: 清空明确的开发数据并切换配置

用户已确认开发阶段旧数据全部可删除。部署时先识别本链路实际数据库、sidecar、owner 文件及由收藏适配负责方确认的收藏数据路径，停止明确的占用进程，再只清除确定归属本次切换的数据文件；不得扩大为目录通配删除或运行时自动清空。配置只注册当前类型，不提供迁移器或旧版本模块。

### D-S02: 验证真实新链路

在清空后的开发环境验证发现、提交、Run 观察、取消及重启；接入另一 session 的收藏适配成果后检查 UI 当前阶段和星标行为。验证使用实际 HTTP、SQLite 和隔离 Worker，不以内存夹具替代。

## Acceptance criteria

### D-AC01: 开发环境无旧数据依赖

用明确路径清单和重新初始化结果证明旧开发数据已清空、当前配置可启动；不导入旧记录、不加载旧版本模块。收藏数据处置与适配负责方一致，且未删除其他项目或用户的数据。

### D-AC02: 端到端行为有效

以真实服务响应、当前数据库重启结果及 UI smoke 证据证明：每种 type 只发现一个当前版本，revision guard、提交幂等、完整 Run、取消/回收和新数据重启行为有效。必要失败显式呈现，不显示成功形状兜底。
