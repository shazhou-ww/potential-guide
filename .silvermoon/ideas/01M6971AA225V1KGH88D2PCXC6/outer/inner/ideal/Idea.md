# 清理通用 Engine 新链路的旧版本支持

## 问题

完整 Run 改造已完成，但新链路仍残留历史元数据回补、旧阶段分支及多版本执行选择，增加当前逻辑的理解和验证成本。实际证据与依赖边界见[分析](./Analysis.md)。

## 结果

新链路只遵循当前契约，每种 type 只注册一个当前版本，不再执行旧版本或修复旧格式；保持当前需求共享、持久化和故障恢复语义。

## 边界

1. 仅限已确认的 8 个 workspace 及直接相关测试、文档、脚本；不清理旧 Host 或独立治理包，共享依赖只做必要联动。
2. 开发阶段旧数据全部可丢弃，不建设兼容层或迁移器；实际清空须限定到明确的数据文件，本阶段不删除数据。
3. 收藏适配由另一 session 负责，本次不重复实施；保留合法 version/revision 身份、幂等、授权、证据复验及物理回收证明。

## 验收标准

1. 当前链路无旧格式回补、旧 Task 阶段或同类型多版本执行支持；旧输入不被静默解释成当前成功。
2. 当前数据重启、共享取消、消息确认和资源回收行为不变；开发数据可按明确清单重新初始化。
3. 8 个 workspace 的相关验证、协议依赖约束及 `pnpm check` 通过，文档与当前契约一致。
