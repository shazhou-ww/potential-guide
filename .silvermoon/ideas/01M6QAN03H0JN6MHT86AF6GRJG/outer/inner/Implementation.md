# Implementation

## Steps

### I-S01: 扩展同快照离线身份

依据[范围与证据](./ideal/Scope-and-evidence.md)细化附加身份类型，复用 readTaskArtifact、checkTaskArtifact 和标准 CAR/DAG 校验，从一次稳定读取输出根、容器哈希、字节数及验证结果；保持目录语义、既有 API/CLI 与 references.json 兼容。

### I-S02: 绑定来源与交付前核验

为 environment 的受控源码构建及准确 npm 包实现上层来源核验，接入构建接受、打包/发布与复制/委派前检查。实际副作用只消费已校验快照，未知来源及矛盾字段显式拒绝，不增加外部上传服务或认证实现。

### I-S03: 固化缓存与字节回归

把准备期隔离复现落实到真实 environment 路径，检查输入/输出追踪并按证据作最小接线修复，使缓存命中也核对所选源码与资源原始字节。补充失败保留、竞态与兼容性回归和相关文档，运行定向检查及 pnpm check。

## Acceptance criteria

### I-AC01: 身份准确且接口兼容

以 API/CLI 契约测试证明原字段、错误规则和公开索引语义未变，CAR 身份来自同次 archive，目录不输出虚假容器身份；既有标准 CAR/DAG、链接和读取中替换拒绝用例保持通过。

### I-AC02: 来源与实际交付字节绑定

用受控源码/实际 tarball 正例及旧 CAR、错根/哈希/大小、未知来源和确定性替换反例，证明与可信期望逐项匹配，错误路径复制/委派/网络写入次数为零。成功路径发送已验字节而非重新读取路径，失败不覆盖已接受 bundles/索引。

### I-AC03: 正常缓存可用且漂移必拒绝

真实接线中的 CRLF/LF、旧输出恢复能报告资源路径并在交付前拒绝；正确冷构建及普通 cache hit 均通过，不依赖 --force。保留可复现测试与工具/配置证据，定向检查及 pnpm check 通过；未复现的历史根因不标为已修。
