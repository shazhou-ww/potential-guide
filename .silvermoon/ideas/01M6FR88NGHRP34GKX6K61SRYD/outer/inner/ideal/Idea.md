# 为 Task Run 提供 Log API 与 Web UI 日志查看

## 问题

Task 执行中的 verbose 信息没有可按 Run 查看、追溯的专用通道，容易被塞入 Result 或 progress。Worker stderr 也不是任务历史的一部分。

## 结果

任务作者通过新增 Log API 输出独立诊断日志，调用方通过查询与实时订阅 API 消费日志；Task Engine Web UI 提供按 Run 查看详细日志的对应界面，覆盖执行中与结束后的历史查看。check 的业务结果仍只表达是否通过及实际问题。

## 边界

- 日志不替代 Result、progress 或 checkpoint，不参与任务匹配、复用与终结判断。
- 输出与保留必须有界；超限、截断或不可用必须可见，不能无限增长或伪装完整。
- 不扩展为交互终端，也不默认转发凭据、环境变量或任意子进程输出。

## 验收标准

- 新增的作者侧 Log API 与消费侧查询、实时订阅 API 连通，同一任务能产生独立日志和精简 Result，二者不会混淆。
- Task Engine Web UI 提供 Run 详细日志界面，能查看实时与历史日志，并区分并发 Run 的输出；仅交付 API 不满足本构想。
- 成功、失败、取消及超限场景的日志可用性清晰，原有任务生命周期语义不变。
