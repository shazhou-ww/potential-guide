# 明确 Execution 终结时间匹配

## 问题

`completed-after-eligible` 未清楚表达完成、失败与取消或超时的层次，
容易混淆请求结束与共享执行结束，影响后到需求加入已有工作的理解。

## 结果

独立推进向 `terminated-after-eligible` 的命名与语义迁移，
明确终结对象、事件时点绑定与一次性破坏升级；[讨论与决定](Discussion.md)保留依据。

## 边界

- `terminated` 指 Execution 成功或失败的逻辑终结，不等于物理退出；取消表示不再需要结果，超时仅表示不再保证结果，仍允许超时成功或超时失败；单个请求退出不代表共享执行结束。
- 不因时间匹配继承未授权副作用或把失败当成成功成果，不在本项实现 Regulate 众筹、预算或 join。
- 仅支持新契约并使用新存储，明确拒绝旧枚举及旧格式，保留旧数据；不兼容旧客户端、不迁移历史、不发布 npm。

## 验收标准

- 同一 Task 类型、相同 Input 的请求按规则匹配，不依赖 Prepared；两种策略分别在 Execution start 与 terminate 时绑定，事件时间允许等于生效时间，终结结果包括成功和失败。
- 成功或失败与超时独立表达，不因超时拒绝迟到结果；新 Task 的生效时间不早于接收时间，并统一作为结果匹配与超时期限的锚点。
- 原始意图、幂等与新格式重启保持一致；旧请求和旧格式被明确拒绝，不静默解释、改写或删除旧数据。
