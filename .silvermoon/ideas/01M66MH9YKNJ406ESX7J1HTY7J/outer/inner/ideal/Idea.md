# 明确 Execution 终结时间匹配

## 问题

`completed-after-eligible` 未清楚表达完成、失败与取消或超时的层次，
容易混淆请求结束与共享执行结束，影响后到需求加入已有工作的理解。

## 结果

独立推进向 `terminated-after-eligible` 的命名与语义迁移，
明确终结对象、时间适用性及旧契约兼容；[背景与未决问题](Discussion.md)保留讨论依据。

## 边界

- `terminated` 指 Execution 成功或失败的逻辑终结，不等于物理退出；取消或超时的 Task 不再需要结果匹配，单个请求退出不代表共享执行结束。
- 不因时间匹配继承未授权副作用或把失败当成成功成果，不在本项实现 Regulate 众筹、预算或 join。
- 保留原始时间与历史事实，迁移策略需先确定；本次只记录，不开始实施、验收或发布。

## 验收标准

- 同一 Task 类型、相同 Input 的请求按规则匹配，不依赖 Prepared；两种策略分别在 Execution start 与 terminate 时绑定，事件时间允许等于生效时间，终结结果包括成功和失败。
- 完成、失败、取消和超时在准确层次上具有可解释、可验证的时间适用规则；新 Task 的生效时间不早于接收时间，并统一作为结果匹配与超时期限的锚点。
- 新旧请求、持久历史与重启后的行为符合明确的兼容约定，不静默改变结果适用性。

## 下一步

明确结果时间恰好等于截止时间时是否仍然有效。
