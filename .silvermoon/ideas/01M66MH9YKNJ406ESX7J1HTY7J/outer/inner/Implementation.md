# Implementation

以下为 preparing 的轻量种子，尚未实施或验收；由用户指定的父代理审查并明确续派。
技术依据、语义矩阵及风险见 [准备说明](Preparation.md)。

## Steps

### I-S01: 升级引擎与协议

先落实 start/terminate 事件时点绑定、Input 等价、统一生效锚点和独立超时，
区分共享需求与结果绑定，保留授权及物理回收边界。

### I-S02: 切断旧存储与适配内部消费者

用显式新格式拒绝旧存储及旧枚举，再对齐 HTTP/server、check、probe 与现有 regulator
使用链路、示例和文档；不建立兼容层、迁移器或业务包自有时间匹配真相。

### I-S03: 补齐回归与制品检查

更新与旧语义冲突的测试，并覆盖竞态、授权、重启及旧格式无损拒绝；
执行相关包检查和仓库 `pnpm check`，为后续独立消费者验证提供准确制品。

## Acceptance criteria

### I-AC01: 时间适用规则一致

通过基于类型与 Input 且不依赖 Prepared 的事件时点绑定、边界时间、
执行失败、Task 取消、超时成功与超时失败及多 owner 用例，
证明接纳、结算和投影使用同一已定义语义，不误终止其他请求的共享执行。

### I-AC02: 破坏升级与重启可证

通过新格式重放、幂等与故障边界测试证明锚点及事件绑定不变；
通过旧枚举、SQLite/投影旧版本拒绝测试证明报错明确且旧数据未改写。

### I-AC03: 内部消费者与制品一致

以 check/probe 授权、Input 等价和 regulator 既有路径回归证明未扩权限，
相关公开调用、打包验证及 `pnpm check` 通过；不声称已经完成外部验收。
