# Docker 验收要求

本文件支持 [Idea.md](./Idea.md)，定义可重复的验证需求，不宣称已存在镜像、Pilot 或测试证据。

## 目的

Docker 是首批验收夹具，也是受支持的 Linux 开发环境之一。它应能低成本重建已知状态，证明健康不误报、故障不漏报，以及修复后恢复；容器通过不能证明宿主或所有 Linux／WSL 环境都健康。

基础夹具需具备专用非 root 用户、用于容器内部管理的非交互 sudo、独立 HOME／工作区和明确工具版本。工具安装发生在夹具准备或 Agent 修复阶段，不在 check 内发生。

## 必须覆盖的场景

| 场景 | 可观察的预期 |
| --- | --- |
| 所有必需条件正常 | 五层中已有足够证据的条件通过；L5 没有足够采样时明确证据不足 |
| 账号错误、root 执行、sudo 缺失或权限不符 | L1 定位实际身份或授权问题，不被管理员会话掩盖 |
| HOME／工作区归属错误 | 定位目录及权限偏离；修复后读写检查恢复 |
| 工具缺失或版本不满足 | L3 定位所选栈的问题；未选栈不阻断、不伪称通过 |
| 命令存在但编译、链接或运行失败 | 不因版本命令成功而通过；能定位失败阶段 |
| 包管理器异常、DNS／必要端点不可达 | 区分系统问题、预期离线策略和调用故障，不自动安装或修复 |
| 受限测试文件系统的空间不足 | L2 在策略边界准确判定；不填满宿主磁盘 |
| 可控的过期残留和测试后台进程 | L4 检出已知残留；正常活动任务、未知文件和未提交工作保持原样 |
| 正常高负载与受控持续增长 | 不把一次繁忙误报为失控；L5 根据多次样本识别已定义的风险 |
| 检查超时、失败或取消 | 有界退出，明确报告故障，并清理自己创建的临时资源 |
| Agent 修复并重新观测 | 原问题消失，累计健康恢复；修复失败不能只凭命令退出码宣告成功 |
| 达标后再次引入故障 | 层级按当前条件退化，不沿用历史就绪结果 |

健康与故障应来自可重复的独立夹具，避免前一个测试的修复污染后一个测试。检查结果需要与已知注入故障对应，不能只断言“有错误”。

## 隔离与验证边界

- 不使用特权容器，不挂载 Docker socket、真实 HOME、真实项目或宿主敏感目录，不授予额外宿主能力。
- 不因容器内 sudo 推导宿主授权；容器不是绝对安全边界。
- 空间／inode 场景使用有明确容量边界的测试资源；资源与增长场景设置上限和截止时间，不耗尽共享设备资源。
- 核对 check 前后持久配置和受保护样本，证明没有偷偷安装、修复或清理已有内容；隔离验证只修改自己的临时资源。
- 需要测试清理行为时，只创建并处理测试专属文件／进程，保存未提交改动和正常活动任务作为保护样本。
- 故障注入、修复和重新观测分开记录；规则层测试可用确定性时间序列，但不能将其充作真实长期运行证据。
- 工具和外部依赖的准备失败、镜像拉取失败、Docker 不可用均应显式暴露，不能跳过后仍声称 Docker 验收通过。

## Docker 之外的补充证明

需至少验证一种明确发行版的原生 Linux 和一种明确版本的 WSL 环境，记录系统、架构、运行身份及适用规则。关注服务管理、实际非交互 PATH、资源来源及内核／重启责任差异；不以容器结果替代这些证据。

持续健康还需要明确时长和采样策略的真实运行观测。构想阶段不要求立即运行这些测试；后续实施与部署阶段分别细化仓库内可重复验证和真实环境验收证据。
