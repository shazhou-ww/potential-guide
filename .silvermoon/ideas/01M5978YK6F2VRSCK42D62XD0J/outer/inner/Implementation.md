# Implementation

本次实施限定为独立的 Linux 开发机健康 Pilot 及本机 Docker 验收矩阵。
用户已委托主 Agent 检查并批准各阶段门禁；需求入口为 [Idea.md](./ideal/Idea.md)，
具体 subject、默认工具版本及阈值见[运行说明](../../../../../objectives/development-machine-health/README.md)。

## Steps

### I-S01: 定义健康观测契约

沿用现有 Pilot manifest／Envelope，不扩张通用协议。五个 advancement 检查身份、
系统、工具链、工作秩序及持续健康；完整观测从首层开始，故障能导致降级。
subject 明确目标容器或本地 Linux、用户、目录、所选栈、可覆盖的最低版本和策略，
以及调用方保存的同目标历史快照。

### I-S02: 实现检查与维护指导

通过 Node 内置模块实现有界执行、隔离构建和清理；Docker 检查只发送源码和非秘密
subject，以指定用户执行，不挂载或转发宿主配置。首版系统包能力为 Debian／Ubuntu
的 dpkg／apt；本地索引新鲜度不等于实时安全公告。提供所有层级、检查和问题的中文指导，
不依赖模型或自动安装，不替代 pguide setup／self-check。

### I-S03: 建立可重复验证

增加真实四栈 Docker 夹具和以固定 Git 提交运行的完整 CLI 验收，覆盖正常、
具体故障、受控恢复、再次退化和数据保护。夹具禁止外网及宿主挂载，使用有容量边界的
tmpfs 注入空间／inode 故障；单元测试覆盖策略临界值和历史、任务登记语义。

## Acceptance criteria

### I-AC01: 五层语义可验证

针对性测试全部通过，证明规范／Wiki 完整、输入和平台拒绝明确、阈值临界值、
历史不足／不匹配和任务登记行为正确；以命令及结果证明，不只做源码检查。

### I-AC02: 工具链与隔离边界有效

本机 Docker 矩阵全部通过，故障断言具体问题 ID、所在层级及必要的目标／数值证据；
四栈实际构建运行、恢复和再次退化成立，检查不破坏正常进程及未提交成果。
保存可复现命令、原始观测和镜像／代码版本。

### I-AC03: 仓库集成通过

Pilot 规范验证、格式／lint／类型检查和本次相关回归通过，执行并记录 `pnpm check`。
若存在未改动范围的既有失败，必须在同一基线源码上复现并明确披露，不能声称全库检查
通过；不以修复无关既有问题替代本次 Docker 交付标准。文档提供准确运行方式，并明确
原生 Linux／WSL 和长期运行未被本次短时 Docker 验证。
