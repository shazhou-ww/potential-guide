# Deployment

本次交付范围按用户明确要求收敛到本机 Docker 的实际验证，不要求原生 Linux／WSL 实机或长期运行验证。验收由主 Agent 按用户委托检查和批准；不能以委托替代测试证据。

## Steps

### D-S01: 验证本机 Docker 场景矩阵

在不挂载宿主数据的专用 Docker 环境执行交付脚本，记录 Docker 版本、镜像身份、
代码版本、账号和完整 Pilot 观测。固定提交的真实 Pilot API／进程 probes 覆盖 33 个
场景，健康场景额外执行真实 CLI 并核对层级和版本。范围含身份与权限、容量与 inode、
网络、包数据库／依赖损坏／仅待升级、四栈、目录秩序、历史证据及增长风险。

### D-S02: 验证持续维护闭环

在同一验收流程内注入有界故障并恢复，验证具体 gap、恢复后的通过及再次退化；确认检查没有损坏未提交成果，结束后清理本次创建的容器和测试资源。

## Acceptance criteria

### D-AC01: Docker 具体 gap 检出

本机实际运行的 33 个场景全部通过且没有跳过；每个故障断言明确的层级、问题 ID
和必要的目标证据，而非仅判断非零退出码。CLI 对照和 API 的层级／版本一致。
报告能够追溯本机 Docker context、镜像和代码版本，不把容器结果冒充宿主或原生
Linux／WSL 证明。代码版本须可从同步后的 primary 到达。

### D-AC02: 恢复与保护有实际证据

实际样本及受控场景证明证据不足不误判通过、恢复后健康、再次故障后降级。未提交成果和正常活动任务保持完好，测试专属容器已清理；报告明确短时验证不等于长期运行健康证明。
