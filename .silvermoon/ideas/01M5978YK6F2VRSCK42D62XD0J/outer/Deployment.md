# Deployment

本次交付范围按用户明确要求收敛到本机 Docker 的实际验证，不要求原生 Linux／WSL 实机或长期运行验证。验收由主 Agent 按用户委托检查和批准；不能以委托替代测试证据。

## Steps

### D-S01: 验证本机 Docker 场景矩阵

在不挂载宿主数据的专用 Docker 环境执行交付脚本，记录 Docker 版本、镜像身份、代码版本、账号和完整 Pilot 观测。覆盖健康、身份与权限、资源、所选工具链、目录秩序、历史证据和增长风险。

### D-S02: 验证持续维护闭环

在同一验收流程内注入有界故障并恢复，验证具体 gap、恢复后的通过及再次退化；确认检查没有损坏未提交成果，结束后清理本次创建的容器和测试资源。

## Acceptance criteria

### D-AC01: Docker 具体 gap 检出

本机实际运行的矩阵全部通过，每个故障断言明确的层级、问题 ID 和目标证据，而非仅判断非零退出码。报告能够追溯 Docker、镜像和代码版本，不把容器结果冒充宿主或原生 Linux／WSL 证明。

### D-AC02: 恢复与保护有实际证据

实际样本及受控场景证明证据不足不误判通过、恢复后健康、再次故障后降级。未提交成果和正常活动任务保持完好，测试专属容器已清理；报告明确短时验证不等于长期运行健康证明。
