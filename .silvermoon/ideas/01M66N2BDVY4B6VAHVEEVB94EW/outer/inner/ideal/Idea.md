# 关闭通用资产管理构想，保留缓存需求讨论

2026-10-31，用户明确认为当前方向属于过度设计，决定先关闭本 idea，后续如何处理留待重新考虑；以 abandon 事件记录，不代表验收或交付。以下保留关闭前的范围与候选标准供历史参考。

## 问题

本 idea 原由任务操作面板的资产查询、选版与清理需求引出。2026-10-31 用户认为通用资产管理是过早抽象，并将其移出 Web UI 首版；资产可能被多个 Task Type 共享，不能从使用关系推导类型所有权。

## 结果

保留本地磁盘持久缓存、重启不失效、仅列出本地缓存版本等具体需求及原讨论，暂停通用接口与 UI 前置依赖的推进。未来仅在用户于本会话明确具体类型或共享资产场景及独立工具边界后重新界定候选，见[讨论依据](Discussion.md)。

## 边界

1. Prepare 准备任务依赖，不赋予 Task Type 资产所有权；不建设通用 TaskType.assets 或插件体系，不把资产管理纳入 Engine 及其 Web UI 的职责。
2. 不上传、导入本机文件、删除远程制品或开放任意路径；不误删执行临时目录、Prepared 或持久化恢复数据。
3. 不作为 Web UI 首版的资产浏览、版本选择器、清理或自动资产元数据前置依赖；暂停不等于 abandon、submit 或 accept，不改变 gate，也不授权实施、验证清理或发布。

## 验收标准

以下保留原候选标准供未来重新界定范围时核对，不是当前必需工作或已就绪的验收候选。

1. 授权消费者可识别资产归属、本地已缓存条目及精确版本，取得对应 subjectSchema；版本列表不承担远端历史版本发现，不存在、不可用与访问失败明确区分。
2. 已缓存的精确制品内容在服务重启后仍可使用，不依赖原来源继续保有该内容；可用历史版本能以精确引用用于新任务，不静默替换内容，无法取得或证明原版本时明确说明，授权与清理边界仍须遵守。
3. 清理仅作用于已确认范围，遵守在用/并发保护规则并逐项报告结果，以隔离验证证明不影响活动任务及恢复数据。

## 下一步

无当前推进动作。本 idea 已按用户决定关闭；未来只有用户明确要求恢复或建立新的具体方向时再处理，不自动恢复设计、实施或提交验收。
