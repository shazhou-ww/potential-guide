# Implementation

准备阶段的可调整种子，不是实施授权；范围见[构想](ideal/Idea.md)与[讨论依据](ideal/Discussion.md)。

## Steps

### I-S01: 确定管理对象与公开契约

获准实施后落实本地磁盘持久化制品缓存目标及已确认的内容范围、权限、版本元数据与清理规则，保持通用 Engine 和类型资产职责分离。

### I-S02: 接入类型资产能力

在资产所有者与可信服务组装边界实现本地已缓存版本查询、精确选版、subject 元数据及受限清理，不增加远端历史版本发现、UI、任意路径访问或业务执行器。

### I-S03: 验证并发与失败语义

覆盖缓存失效、权限变化、在用/并发解析、清理结果及精确版本不可用场景，更新直接相关文档并运行 pnpm check。

## Acceptance criteria

### I-AC01: 元数据与精确内容一致

以接口和类型集成测试证明所列版本、subjectSchema 与实际提交所用内容对应；以服务重启且原来源不再保有旧内容的场景证明已缓存精确内容仍可授权复用，失败不伪装成空列表或自动换版。

### I-AC02: 清理边界有效

以并发和权限测试证明仅处理授权对象，活动执行及恢复数据不受破坏，逐项结果可核对，不开放任意路径。

### I-AC03: 职责与工程质量可复核

以依赖边界、回归测试和使用文档证明未把类型资产职责塞进通用内核；pnpm check 通过。
