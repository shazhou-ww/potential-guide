# 统一 Task Engine 的观察术语与序号边界

## 问题

生命周期观察使用数据域 revision，Run 日志使用独立 sequence，
文档对“事件、历史、订阅、游标”的泛称容易掩盖这两套不同的含义。

## 结果

为新 Task Engine 建立一致的术语定义与字段映射，让读者能区分生命周期观察和诊断日志，
避免把命名相似误认为可以共用序号、分页或续接机制。

## 边界

1. 独立于 IPFS Bundle IDEA，先统一 axis 及直接相关协议说明，不预设代码字段重命名。
2. 不合并 revision 与 sequence，不改变它们的作用域、持久化、排序及订阅语义。
3. 不改变 Task/Run 生命周期；若发现需要调整语义或公共 API，另行明确决定。

## 验收标准

1. [职责入口](../../../../../../docs/axis/task-engine-responsibilities.md)与相关契约使用一致术语，
   明确哪些约束仅属于生命周期、哪些仅属于日志。
2. revision/fromRevision 与 sequence/afterSequence 的作用域及对应关系可直接查阅，
   不能再从“所有订阅”等泛称推导出混用接口。
3. 文档示例与现有公共字段准确对应；未批准的字段重命名或运行行为变更不混入本构想。
