# Implementation

## Steps

### I-S01: 收敛协议与所有权

以 PB 统一入口、CLI 调度及全量替换旧运行协议为前提，细化启动/就绪、准确身份、请求上下文、CLI 受限依赖回调及生命周期契约；保留 schema 不可变和旧输入明确拒绝的边界。收敛取消隔离、远程范围及同服务重入后再进入实现，本契约仍为可调整初版。

### I-S02: 接通服务调度与真实检查器

接通 PB 统一入口与 CLI 调度：独立 probe 或 regulation 前准备已知服务，内层 probe 复用已有实例，动态依赖首次派发前确保服务就绪，顶层结束回收。全量迁移内置 Objective、脚手架、示例、测试、生成物和直接消费面，不保留 run.* 或裸 subject HTTP 回退；逐请求隔离输入与证据，不新增必需的 Pilot 子进程或全局常驻调度器。

### I-S03: 验证失败边界与收益

覆盖启动、重复请求、依赖调度、超时取消、变化后重观察、来源与资源回收；执行针对性测试、冷/热计数比较及 pnpm check，更新直接相关文档。

## Acceptance criteria

### I-AC01: 多请求复用且观察独立

测试与真实调用计数证明独立 probe 和 regulation 均经 PB 入口由 CLI 按需启动服务，同一 regulation 内多次 probe 不重复拉起有效实例；服务可处理多个 check/subject，修复后刷新输入，来源、问题归属及证据正确。

### I-AC02: 生命周期和失败有界

反例证明同身份竞争启动、内层 probe 借用、顶层退出、依赖等待、崩溃、取消和未知结果遵守已确认契约；资源只在确认不再使用后回收，不静默成功或重放。

### I-AC03: 校验和性能证据完整

相关测试、生成物及 pnpm check 通过，旧协议明确拒绝且已发布 schema 与历史证据未改写；固定输入对比证明启动与初始化减少并报告实际延迟，不以跳检查或放宽预算替代。
