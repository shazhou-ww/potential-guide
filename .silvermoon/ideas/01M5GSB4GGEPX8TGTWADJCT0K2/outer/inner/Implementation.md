# Implementation

## Steps

### I-S01: 收敛协议与所有权

在构想问题明确后，细化服务启动/就绪、准确身份、请求上下文、依赖回调及生命周期契约，确定旧入口兼容与 schema 迁移边界。本契约仅为可调整的可行性初版。

### I-S02: 接通服务调度与真实检查器

实现已确认范围的 HTTP 服务绑定和统一管理，迁移 monorepo 根及包级检查入口；使多次 probe/Regulation 观察复用服务且逐请求隔离输入与证据，不新增必需的 Pilot 子进程。

### I-S03: 验证失败边界与收益

覆盖启动、重复请求、依赖调度、超时取消、变化后重观察、来源与资源回收；执行针对性测试、冷/热计数比较及 pnpm check，更新直接相关文档。

## Acceptance criteria

### I-AC01: 多请求复用且观察独立

测试与真实调用计数证明一个 Pilot 服务处理多个 check/subject 和连续观察，来源、视图、问题归属及证据正确；修复或下一轮不会使用旧输入/结果。

### I-AC02: 生命周期和失败有界

反例证明同身份竞争启动、客户端释放、依赖等待、崩溃、取消和未知结果遵守已确认契约；资源只在确认不再使用后回收，不静默成功或重放。

### I-AC03: 校验和性能证据完整

相关测试、生成物及 pnpm check 通过，固定输入对比证明启动与初始化减少并报告实际延迟，不以跳检查或放宽预算替代。
