# Implementation

## Steps

### I-S01: 收敛协议与所有权

按 [MVP 设计](./ideal/Design.md) 定稿自包含产物、worker 消息、七个 HTTP 接口、
响应流依赖往返及本机资源边界。明确容量、任务数退役与预热额度，不建设任务恢复平台。

### I-S02: 接通共享 Host 与检查器

只新增 packages 下的可复用 Host 包，接入现有协议/观察/CLI 链路。
先跑通双 CLI、monorepo 根到包依赖及连续复用，再完成 6 个 Objective、16 个 check、
生成器/脚手架/fixture/消费入口的全量迁移，无旧运行协议回退。

### I-S03: 验证失败边界与收益

验证并发启动、版本冲突、响应断开、依赖容量、取消和清理；
连续混合 subject 的成功/失败/取消负载衡量内存、初始化、任务数退役及简单替补预热。
执行针对性测试和 pnpm check，更新直接相关说明。

## Acceptance criteria

### I-AC01: 多请求复用且观察独立

多个 CLI 共用 Host，连续任务复用线程且全部迁移入口执行正确；
根/包依赖在原观察作用域校验证据，输入刷新、层级和问题归属不变。

### I-AC02: 生命周期和失败有界

队列/线程/消息/去重容量有界，超时及断线取消不误伤他人；
清理失败不回池，不透明重试未知任务。任务数退役与预热不突破额度，
长期复用无请求资源持续累积，不以每请求重建替代清理。

### I-AC03: 校验和性能证据完整

相关测试、生成物及 pnpm check 通过，历史契约和固定证据不变，旧输入明确拒绝。
同环境固定输入比较进程/线程启动、初始化、内存及冷/热耗时，证明实际收益。
