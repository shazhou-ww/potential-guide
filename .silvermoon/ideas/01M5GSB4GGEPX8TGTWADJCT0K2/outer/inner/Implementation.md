# Implementation

## Steps

### I-S01: 收敛协议与所有权

以 [Design.md](./ideal/Design.md) 为审阅起点，定稿调整范围、worker handler/MessagePort 消息、
HTTP 异步任务/事件接口和原观察宿主接线；覆盖 6 个内置 Objective、16 个 check 入口。
定义每请求清理、worker 卸载及 Host 所有权，区分已确认池策略与待审阅接口字段。
保留 Pilot ID 单执行版本和历史契约不变，未决细节收敛后再实现。

### I-S02: 接通共享 Host 与检查器

多个 CLI 共用用户级 Host；Host 维护 Pilot worker 注册、有界队列及可复用线程，
处理不同 regulation object/subject 并隔离请求上下文。全量迁移内置 Objective、
脚手架、示例、测试、生成物和直接消费入口，不保留旧运行协议兼容。
所有 check 通过 worker handler 处理消息，不包装重启旧 check 进程；
将依赖、视图、证据及取消从隐式进程状态迁入请求上下文，建立有界缓存和失败清理。
按兼容 Pilot 版本复用线程，一线程同时一任务；条件退役与同版本替补预热受总体资源额度约束。
特殊一次性 worker 必须显式声明，不作为默认执行路径。

### I-S03: 验证失败边界与收益

覆盖竞争启动、版本切换、依赖容量、跨客户端隔离、取消、崩溃和最后回收；
增加连续多 subject 的成功/失败/取消混合负载，预先定义内存与存活资源验收边界；
比较进程/线程启动、初始化、heap/外部内存、Host RSS 与冷/热延迟，执行针对性测试及 pnpm check，
更新直接相关说明。
补充任务数/时间/内存/空闲退役、替补预热失败与资源峰值、幂等提交/丢响应、
事件重复/ack/过期及依赖响应登记顺序的验证。

## Acceptance criteria

### I-AC01: 多请求复用且观察独立

测试与真实计数证明多个独立 CLI、多个 Pilot 和 subject 共用一个 Host，
worker 连续执行减少加载且请求身份、输入、预算、依赖及证据不混淆；
变化或修复后重新观察，层级顺序和结果正确。
全量入口清单与测试证明每项 check 已使用 worker 消息协议，不遗漏生成物或仍依赖进程退出完成。
异步 HTTP 受理不冒充任务完成，依赖事件泵在父请求等待时仍能推进。

### I-AC02: 生命周期和失败有界

反例验证 Host 启动仲裁、Pilot 单执行版本、线程/依赖容量、客户端退出、
单请求取消、Host 崩溃及结果未知；确认执行停止后才释放资源，不误杀其他任务或透明重放。
连续复用证明请求引用与外部资源在结束后释放、各级缓存有界；清理失败明确可见，
该 worker 不进入空闲复用，不依赖 GC 或逐请求重建掩盖泄漏。
有界退役/预热行为符合策略，同版本替补也计入额度，不产生不同版本并行执行。

### I-AC03: 校验和性能证据完整

相关测试、生成物和 pnpm check 通过，旧运行协议明确拒绝且历史证据未重绑。
固定输入比较同时覆盖 Host/线程初始化及实际耗时，不以逐次线程重建、跳检查或放宽预算代替收益。
