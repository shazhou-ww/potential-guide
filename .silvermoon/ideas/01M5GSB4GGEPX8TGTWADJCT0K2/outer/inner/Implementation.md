# Implementation

## Steps

### I-S01: 收敛协议与所有权

以每个 Pilot 的统一 executable、CLI 进程调度及全量替换旧运行协议为前提，选择 check 指令传输，细化启动/就绪、请求身份、受限依赖回传和生命周期契约；保留历史 schema 不变和旧输入拒绝边界。传输、取消、远程范围与重入收敛后再实现，不预先绑定 HTTP。

### I-S02: 接通服务调度与真实检查器

为每个 Pilot 定义 executable，CLI 按统一协议启动、复用及回收进程；Pilot 自行管理有界 check 队列和线程，处理不同 regulation object/subject。内层 probe 和动态依赖借用已有实例，不为每次 probe/check 新建进程。全量迁移内置 Objective、脚手架、示例、测试、生成物和消费面，不保留旧运行协议，逐请求隔离上下文。

### I-S03: 验证失败边界与收益

覆盖启动、重复请求、依赖调度、超时取消、变化后重观察、来源与资源回收；执行针对性测试、冷/热计数比较及 pnpm check，更新直接相关文档。

## Acceptance criteria

### I-AC01: 多请求复用且观察独立

测试与真实计数证明 Pilot executable 自行排队并分配 check 线程，经选定传输处理不同 regulation object/subject，身份、依赖回传、输入、预算和证据不串请求；连续 probe 不重复拉起有效进程，修复后刷新输入且层级顺序正确。

### I-AC02: 生命周期和失败有界

反例证明同身份竞争启动、线程容量/依赖重入、单请求取消、服务崩溃、顶层退出及未知结果遵守已确认契约；线程和外部任务确认停止后才回收资源，不静默成功或重放。

### I-AC03: 校验和性能证据完整

相关测试、生成物及 pnpm check 通过，旧协议明确拒绝且历史契约未改写；固定输入对比同时统计进程/线程启动、每线程初始化及实际时延，证明重复工作减少，不以新建线程反复重载、跳检查或放宽预算替代。
