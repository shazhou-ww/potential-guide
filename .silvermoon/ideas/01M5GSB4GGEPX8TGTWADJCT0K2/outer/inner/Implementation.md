# Implementation

## Steps

### I-S01: 收敛协议与所有权

以已明确的“check 纳入 PB 统一入口、CLI 负责调度”为前提，细化服务启动/就绪、准确身份、请求上下文、依赖回调及生命周期契约，确定旧入口兼容与 schema 迁移边界。本契约仅为可调整的可行性初版。

### I-S02: 接通服务调度与真实检查器

接通 PB 统一入口与 CLI 服务调度：独立 probe 或 regulation 执行前启动所需服务，内层 probe 复用顶层调度上下文中的已有实例，顶层结束统一回收。迁移 monorepo 根及包级检查入口，逐请求隔离输入与证据，不新增必需的 Pilot 子进程或全局常驻调度器。

### I-S03: 验证失败边界与收益

覆盖启动、重复请求、依赖调度、超时取消、变化后重观察、来源与资源回收；执行针对性测试、冷/热计数比较及 pnpm check，更新直接相关文档。

## Acceptance criteria

### I-AC01: 多请求复用且观察独立

测试与真实调用计数证明独立 probe 和 regulation 均经 PB 入口由 CLI 按需启动服务，同一 regulation 内多次 probe 不重复拉起有效实例；服务可处理多个 check/subject，修复后刷新输入，来源、问题归属及证据正确。

### I-AC02: 生命周期和失败有界

反例证明同身份竞争启动、内层 probe 借用、顶层退出、依赖等待、崩溃、取消和未知结果遵守已确认契约；资源只在确认不再使用后回收，不静默成功或重放。

### I-AC03: 校验和性能证据完整

相关测试、生成物及 pnpm check 通过，固定输入对比证明启动与初始化减少并报告实际延迟，不以跳检查或放宽预算替代。
