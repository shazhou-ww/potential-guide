# Check Host：决定与审阅清单

当前唯一架构为统一 Node、单用户级共享 Check Host、外部 HTTP RPC、内部 MessagePort。
用户已接受有界复用池、条件退役和受控动态预热；不再把永久 worker 或逐请求重建作为通用备选。
具体调整范围、worker 消息及 HTTP 路由集中在 [Design.md](./Design.md)，本文件只维护决定状态，
不重复定义接口。接口草案供审阅，不等于用户逐字段确认或生命周期验收。

## Q01: 调度与 Host 生命周期（职责明确，参数待定）

CLI 发现/协调启动 Host，Host 持有注册、队列和线程池，跨独立 CLI 共用。
退出单个客户端不关闭他人任务。设计稿建议 session 租约、续用、释放及空闲回收；
启动锁、失联恢复、租约时长和关闭权限需要定稿。

## Q02: 迁移与兼容（已明确）

全部现有 check 由进程入口改为 worker handler；HTTP 与线程消息显式传递上下文。
脚手架、示例、生成器、fixture 和直接消费面一起迁移，无旧运行协议回退。
历史 schema/源码/固定证据不改写，旧输入明确拒绝。模块函数可以复用，
不能在新 worker 中继续每请求启动旧重检查进程。

## Q03: 依赖请求与原观察作用域（具体方案待审阅）

设计稿建议 CLI/调用者保留观察及依赖证据权威；worker 发 dependency.request，
Host 通过 session 长轮询事件交给原观察宿主处理，登记证据后提交 dependency.response。
CLI 不需反向监听端口，事件泵必须在父任务等待时持续运行。

待审阅：事件游标/ack、依赖响应幂等、regulation worker 的上下文路由，
以及失联/取消/重启后拒绝旧观察消息。内部 MessagePort 不等于外部 HTTP 自动双向通信。

## Q04: 请求取消与故障隔离（策略方向明确，保证待验证）

每 worker 同时执行一项 check；先协作取消，无法确认停止时隔离并终止线程，
等待退出、回收可管理资源后才补充执行容量。清理失败不回池，不自动重放。
Host 崩溃是共享故障；线程终止不保证原生调用、外部子进程或副作用已结束，
这些资源的清理责任和可验证停止保证仍须具体设计。

## Q05: 信任范围（本机方向，权限细节待定）

本机同用户 Host，明确 loopback、鉴权和来源授权，不默认远程上传 subject/视图。
worker 不是不可信代码安全沙箱。待定允许注册的来源、原生模块/外部工具权限，
以及 HTTP 管理能力和普通执行能力的隔离。

## Q06: 复用、退役、预热与依赖容量（池策略已确认，额度待定）

采用有界复用池，按兼容的 Pilot 准确版本复用 worker，不按 subject/regulation object 拆池；
一个 worker 顺序执行多个任务，并发通过多个 worker。
达到任务数、存活时间或内存条件后排空退役，空闲可缩容；异常/清理失败隔离退役。
同版本替补可动态预热，但预热和退役线程都计入总资源预算，不执行真实 check。

待定：具体阈值、线程亲和性细分、预热触发和依赖容量。等待子请求的父任务仍占实际线程，
必须避免池耗尽死锁，不能只改计数、无限扩容或改变业务层级顺序。
特殊不可安全复用的 check 可显式声明一次性 worker，但不能作为全量默认策略。

## Q07: Pilot ID 与版本切换（唯一原则已确认，切换流程待定）

同一 Pilot ID 只允许一个可执行注册版本，同版本可有多线程。
准确 source 仍用于请求与证据验证；不匹配先明确冲突，不能静默改用当前版本。
旧版本排空/卸载后才能装入新版本，新版本不能借预热与旧版本并存。
切换授权、等待和固定版本恢复流程仍需确定。

## Q08: 请求去重与重试（具体接口待审阅）

设计稿使用客户端 requestId/幂等键与 Host attempt/worker 代际区分提交和实际执行。
同身份不同内容拒绝；丢响应先查询，不透明重放结果未知的任务。
去重和事件记录有界，仍有效身份不能被淘汰后当新请求；不承诺跨 Host 重启 exactly-once。
容量、保留期、超时取消竞争及终态/清理状态需要按设计稿确认。

## Q09: 来源、视图和证据所有权（具体传递待审阅）

Host 持有准确注册源码，不依赖启动 CLI 的临时目录。
设计稿建议按观察上传带摘要的受限视图，Host 返回不透明 inputViewId，
worker 获得只读能力而不是客户端任意路径；无只读声明的检查仍按自己的合法 live 输入执行。
数据大小、流式校验、所有者权限、引用计数与终止后的回收需明确。
Host 日志不代替逐请求证据，也不能共享“当前 subject”或秘密保护集合。

## Q10: HTTP 与 Host 发现（传输已确认，接口草案待审阅）

仅 Host 对外提供本地 HTTP RPC，worker 通过 MessagePort 通信。
设计稿给出了 session、注册、观察/视图、check、依赖响应、事件读取及关闭接口；
异步受理与实际业务结果分离，状态查询不执行 check。
Host 动态端口/用户级发现、身份握手、管理鉴权和错误/负载上限需定稿。

## Q11: Node worker 模块契约（架构已确认，API 待审阅）

统一 runner 处理 MessagePort，业务模块建议提供 initialize、execute、dispose，
RequestContext 提供本地 signal、依赖、视图、证据和清理登记能力。
方法签名、descriptor、允许的 Node 版本及依赖交付方式按设计稿审阅。
模块初始化通常按线程发生，需验证复用收益，不假设所有线程共享 TypeScript 实例。

## Q12: 内存回收（要求已确认，测量边界待定）

区分请求清理、worker 有界缓存和 Host 队列/会话/事件/去重记录。
成功、失败、超时、取消都需清理，请求释放完成后才允许 worker 回池；
代码/编译器可有界保留，目标事实不能跨输入版本误用。强制终止不保证 finally 执行。

退役与预热是防线，不替代清理。具体内存阈值、压力策略、负载规模与回收窗口须在实施前
量化；混合 subject 的成功/失败/取消持续复用需证明保留量有界，并统计初始化次数。
观察 heap、外部内存、Buffer、Host RSS 与存活资源，不要求 GC 后 RSS 精确归零，
不以强制 GC 或逐请求重建掩盖泄漏。
