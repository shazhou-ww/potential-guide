# 共享 Check Host：决定与待定细节

已选定统一 Node、单用户级共享 Check Host、外部本地 HTTP RPC、内部 Worker Threads
消息通信。下列编号保留作为讨论引用，只描述该方向；已确定的架构不再列为备选。
方向确认不等于本 idea 的生命周期验收或实现完成。

## Q01: 谁拥有调度器，服务驻留多久（职责已明确，生命周期细节待定）

多个独立 CLI 发现并使用同一个用户级 Host；CLI 是调用与启动协调入口，
Host 持有 Pilot worker 注册、check 队列及线程调度，不绑定某一个 regulation object。
客户端只释放自己的使用权，不能关闭其他客户端仍使用的 Host 或执行任务。

待定：按需启动的仲裁、客户端存活检测、最后使用者退出后的空闲回收和 Host 异常退出恢复。
建议有限租约结合活动任务计数；具体时长、续租和显式关闭权限尚未确认。

## Q02: 新运行契约与旧契约如何迁移（全量替换已明确）

新运行时统一接受 Node worker 注册与 Host 调用契约，不保留旧一次性 run.* 或
旧裸 subject HTTP check 的运行时兼容。仓库内所有 Objective、脚手架、示例、
测试、生成物及直接消费入口同步迁移；业务规则函数可以复用。

旧输入明确拒绝并给出迁移要求；已发布 schema 的字节/URI 不变，改变契约采用新版本。
历史源码和固定来源证据不重绑。不顺带改变层级与 Regulation 等无关业务语义。
注册 descriptor 和版本化消息字段在后续设计确定。

## Q03: 依赖请求与原观察作用域（归属方向明确，消息闭环待定）

worker 通过 MessagePort 向 Host 请求依赖；请求必须绑定调用者、regulation/观察、
父 check、Pilot 来源及 worker 代际。Host 路由到拥有该观察的宿主逻辑，
继续执行来源绑定、递归/深度/次数预算和依赖证据校验，不另起无关 probe 冒充同轮观察。

待定：
1. 观察执行位于 CLI、regulation worker 或 Host 时，具体上下文由谁持有，消息如何路由？
2. 若上下文在客户端，HTTP RPC 如何传递 Host 发往客户端的依赖事件及其响应？
   内部 MessagePort 解决的是 Host/worker 通信，不自动提供外部 HTTP 双向业务通信。
3. 依赖证据必须在原作用域登记后才响应；字段、错误和响应次序如何定义？
4. 父请求取消、客户端失联、迟到消息或响应丢失时，如何停止子任务并清理上下文？

不预设 CLI 必须再启动 HTTP 服务，也不从 subject 接受任意回调 URL。
连接能力只允许本次观察的依赖操作，不授予任意程序启动或文件读取能力。

## Q04: 单个 check 的取消与故障隔离（机制待验证）

Host 的 HTTP/控制线程不执行 check 的同步 CPU 逻辑；业务任务进入工作线程，
每个工作线程同时只承载一个 check 请求。建议先协作取消，截止后终止该 worker，
等待其退出后再清理请求资源或补充新 worker；不主动取消其他线程的独立请求。

待验证：Node 线程终止、原生调用、check 启动的子进程及外部资源如何一起回收。
线程退出不自动证明外部副作用或子进程已结束。Host 整体崩溃会影响所有客户端，
必须明确在途结果未知和恢复边界，不以 HTTP 断开冒充取消成功。

## Q05: 托管范围与信任边界（本机优先，权限细节待定）

当前方向为同一 OS 用户下的本机 Host，显式 loopback HTTP 和调用能力验证；
不默认上传 subject、秘密值或输入视图到远端。不将远程服务部署列为本次必需交付。

待定：哪些已注册 worker 允许执行、来源授权、文件/网络/原生模块及环境变量的访问约束。
Worker Threads 不是安全沙箱，不承诺把恶意检查器隔离在 Host 之外；
检查代码也不能通过线程共享任意改写其他请求的输入或权限。

## Q06: 统一队列、线程复用与依赖等待（调度归 Host）

check 调用是最小并发单元，Host 统一管理有界队列、总体线程容量和公平调度。
同一 worker 可以连续执行不同 subject 的请求，但每次都必须建立和清理独立上下文。
优先评估按 Pilot 入口保持线程亲和性以摊薄加载成本；池规模与闲置策略未定。

有限线程全被等待子 check 的父任务占据时仍可能死锁。待定：如何挂起/释放实际执行容量、
保留依赖容量或明确拒绝不可调度请求，不能无限增加线程，也不能只调整计数而不释放线程。
控制面保持可响应，排队消耗请求/观察的剩余预算；业务层级顺序与递归检查不因并发改变。

## Q07: Pilot ID 唯一性与版本切换（唯一约束明确，冲突策略待定）

Host 内的 worker 注册以规范 Pilot ID 唯一定位当前执行版本，同一 ID 不允许不同版本
同时加载为可执行 worker。一个版本可以使用多个 worker 线程，但不能用版本后缀绕开唯一性。
subject、regulation object 和请求 ID 不作为重复注册新执行版本的理由。

准确 commit/tree/repositoryTree、协议和配置作为注册属性及证据校验条件。
请求明确要求另一版本时不能静默使用当前版本；建议显式冲突，
等待/授权切换的策略仍待讨论。切换须排空并卸载旧 worker，再装入新版本。
实例代际区分旧响应与新请求，不承诺跨 Host 重启延续 worker 状态。

## Q08: 请求身份、去重与重试（原则明确，保留策略待定）

requestId 绑定客户端、观察、Pilot 执行版本和 worker 代际；同 ID 不同内容拒绝，
重复提交不二次执行，状态查询和取消不能隐式变成重新执行。
超时/断线且结果未知时不透明重放；明确区分未受理、执行中、完成、确认取消和未知。

待定：有界去重记录的保留期、容量耗尽和查询方式。仍有效的身份不能被淘汰后当新请求执行。
首轮不承诺跨 Host 重启的持久 exactly-once；显式新尝试须新身份及独立证据。

## Q09: Host、worker 与来源/视图资源的所有权（寿命细节待定）

Host 持有注册入口所需的准确源码、模块和线程资源，不依赖最初启动 CLI 的临时 checkout。
输入视图和证据按客户端/观察/请求隔离，worker 不通过全局 cwd 或环境变量切换当前 subject。
客户端释放不能删除其他任务仍使用的资源。

待定：来源移交/持有、观察视图传递、文件权限、使用计数及异常回收的具体接口。
关闭须先停止受理、完成/取消任务并确认线程退出，再清理资源；Host 故障和启动者失联须可诊断，
不得仅凭旧 PID 终止进程或删除新代际记录。服务日志不能代替每次 check 的宿主证据。

## Q10: 外部 HTTP RPC 与 Host 发现（传输已明确，启动协议待定）

CLI 与共享 Host 通过本地 HTTP RPC 通信；用户级发现只记录 Host 地址及实例身份。
Host 内部维护 Pilot ID 到 worker 入口的注册，不为每个 Pilot 分配监听端口。
Host 与 Worker Threads 使用 MessagePort，不让 worker 再监听 HTTP。

待定：Host 启动锁、就绪握手、发现记录形状、访问凭据与失效清理。
建议 OS 动态分配 loopback 端口，ready 后原子登记到用户级运行态文件；
与稳定用户配置分开存储，端口/PID 不作为唯一身份。实际端口策略及生命周期参数尚未定稿。
HTTP 请求大小、响应大小、排队背压、取消和错误状态须明确；端口变化不改变 Pilot 注册身份。

## Q11: 统一 Node 的共享 Check Host（已选定）

所有检查器提供符合统一 Node 契约的 worker 模块入口，Host 统一加载并管理执行线程。
一个用户级 Host 面向多个独立 CLI、多个 Pilot 及多个 regulation object/subject。
此为当前唯一设计方向，具体 module API、支持的 Node 版本和依赖交付方式仍需设计。

Node worker 的模块初始化通常按线程发生；Host 加载一次 TypeScript 不等于各线程自动共享。
后续验证必须统计 Host/线程启动和每线程初始化，证明连续请求的加载成本被摊薄，
不能仅把逐次进程重启换成逐次线程重建。
