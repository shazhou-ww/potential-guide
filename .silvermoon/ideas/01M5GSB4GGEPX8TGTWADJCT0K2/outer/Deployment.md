# Deployment

固定版本消费、产物来源与尚未闭合的启动/退出边界见 [Consumption.md](./Consumption.md)。
当前只有 D-S01/D-AC01 的独立消费证据闭合；D-S02/D-AC02 未完成，
不提交部署门禁，不把实施验收当作部署验收或发布授权。

## Steps

### D-S01: 固定版本隔离消费

独立安装 CLI、Host 和自包含产物，经真实 HTTP 执行双客户端、根检查依赖结果/上层处理和连续复用；
覆盖全部内置迁移入口，记录准确来源、消息与结果，不借用实时工作区模块。
对照公开内核的当前 CheckState 与 HTTP 状态投影，验证 Subject 原样传递及重复观察不重新执行。
通过开始、取消、观察单项及当前集合的公开接口验证，不使用临时替代设计或注册流程。
Windows 消费环境须具备受信 Windows PowerShell/.NET 权限后端；
在生成/写入 bearer token 前验证当前 SID 专属的受保护目录和文件 ACL，
后端不可用或遗留权限过宽时明确失败，不自动改写用户既有目录权限。

### D-S02: 检验复用收益与故障回收

比较冷/热延迟、线程初始化和长期资源占用；验证重复提交防护、观察断线/重新观察、取消、清理、
目录直接加载/同版复用、内容校验、排空更新与在途版本冲突、退役和预热。
无需调用注册或卸载 API；没有租约、事件恢复或视图 CRUD 验收要求。
不执行未授权发布、远程或生产变更。

## Acceptance criteria

### D-AC01: 真实消费证明复用

多个 CLI 共用 Host endpoint，全部入口结果正确；依赖 check 完成后释放线程，
上层消费其业务要求、取得真实包级观察并重查，不经 Host 回调或跳过目标验证；
HTTP 从当前状态快照到后续变化正确反映同一执行，终态携带 CheckResult 或执行故障，
集合观察显示有权访问的活动任务及其离开，不重复执行或暴露其他任务的 Subject；
业务不通过（含依赖要求）不冒充调用故障，终态结果及证据正确保留；
目录/revision 的首次加载、连续复用和顺序更新均有真实证据；
线程复用减少初始化，跨 subject 证据不混淆，提供可复现的计数和时延比较。

### D-AC02: 失败与资源边界成立

实际观察连接中断不取消执行，重新观察同一 checkId 不透明重跑；
明确取消和单任务失败不误杀他人，终态有限保留及过期行为正确；
断流未收到终态时明确报告状态未知，不把连接断开写成远端 Cancelled；
清理完成后才复用，持续混合负载资源有界，退役/预热不突破额度；
旧协议明确拒绝，历史来源证据不重绑。
普通本机 Users/Authenticated Users/Everyone 不能读写 token 或替换 descriptor；
用实际 ACL/所有者与失败路径证明边界，不将 mode、umask 或当前用户可读当作隔离证明。
