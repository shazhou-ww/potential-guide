# 优先建立 pguide 本机自查，再供远程整备复用

## 问题

当前 setup 将本机就绪检查与远程整备混在同一个 Objective 中，缺少可独立复用的本机自查标准。安装或 ACP 握手成功也不能证明设备能执行真实任务。

## 结果

优先交付独立的本机自查 Objective，由设备上已安装的 pguide 验证自身安装、配置及真实执行闭环。后续 A 对 B 的整备以 B 运行该自查并通过为最终依据，不再维护另一套就绪标准。

分级、各级 checks 与职责边界见 [分级与检查说明](./Levels-and-checks.md)。

## 边界

- 本轮优先完成本机自查；远程整备接入该自查留作后续工作，保留现有 setup/bootstrap 行为，不新增 CLI 命令、不发布 npm。
- 自查只观测，不自动安装或改写用户配置；复用设备已有 ACP stdio 入口及认证，不复制秘密、不申请付费资源，本轮不扩展 AHP。
- 真实 sanity 需明确授权，只在隔离目标中有界执行并独立复查；没有可用 Agent 或真实执行失败时保留阻塞，不用测试替身或历史证据冒充通过。

## 验收标准

- 独立本机自查具有清晰的 initial、installed、configured 与隐式 terminal 分级；各级检查、通过条件和调用故障可观察，不依赖 SSH 或控制机。
- 设备上已安装的 pguide 能运行该自查；只有真实隔离任务经独立复查成功才达到 terminal，缺安装、错配置、不可用 ACP、未授权或执行失败都不能误报就绪。
- 自动回归及至少一次已授权真实本机验证证明闭环；文档明确后续远程整备必须使用 B 的 pguide 和 B 的自查结果，不能替用 A 的成功证据。
