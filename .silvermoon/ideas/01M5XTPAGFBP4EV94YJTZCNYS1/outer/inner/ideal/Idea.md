# 让状态树测试同时驱动自动验证与人工操作手册

## 问题

树形 E2E 已能表达状态与转移，但阅读自动化函数不足以指导人工复验，
另写手册又容易与测试路径脱节。

## 结果

以固定 YAML 统一描述 state、transition、检查条件及人工说明，
只指定一个 Binding TS 文件，按 state/检查 ID 与导出符号的固定规则关联实现；
同一数据既驱动自动测试，也生成可逐步执行的人工手册。

## 边界

- YAML 是结构与说明的唯一来源；不写逐项 use 映射，不维护第二棵手写 BDD 树或可执行脚本。
- transition 调用时进入状态并返回 after 负责收尾；文档生成不加载测试实现或启动服务。
- 先以 Check Host 验证；人工视图按 state tree 使用原始命令/API，不调用测试包装器；
  Node Test 只负责自动化适配，不新增依赖式调度，清理不是业务回滚。

## 验收标准

1. 同一 YAML 可生成或展开 Node Test 测试，并输出终端树、Markdown 及可离线查阅的 HTML。
2. 人工手册按状态展示进入操作、观察结果、后续状态及实际退出操作；不以 before/after/it 或测试函数名作为页面结构，包含故障路径及平台限制。
3. 非法数据及缺失约定函数导出明确失败；部分初始化或清理失败不跳过其他应执行的收尾、不掩盖原始错误，人工可依手册复验代表路径。
