# Implementation

本契约为准备阶段的实施初版；构想验收后再细化接口和文件布局。

## Steps

### I-S01: 建立双模式 BDD 封装

为 describe、it、beforeEach、afterEach 提供执行及收集两种模式。
正常模式保留 Node Test 的 hook 顺序、失败传播及 options；收集模式只遍历声明，
记录状态、函数引用和说明。梳理导入与声明阶段的副作用，必要时延迟初始化，
避免“没有执行 hook 却已创建目录或启动进程”。

### I-S02: 关联 YAML 说明并生成多种视图

通过命名空间与稳定键关联标题、Markdown 说明、命令示例和平台要求，
不在 YAML 重复定义树，也不执行 YAML 内容。验证缺失引用、重复键及无效字段。
提供文档入口以输出终端树、Markdown 和静态 HTML；支持定位节点、查阅说明
以及组合完整路径，清理按内到外展示，父层其他 it 不自动变成前置操作。

### I-S03: 以 Check Host 接通代表性路径

将已有或后续同步的 Check Host E2E 状态树接入封装，并补齐启动、执行、
取消清理及故障恢复的人工说明。沿用隔离环境与自有资源清理约束；
本 Idea 不顺带提交或重做其他工作分支中的 E2E 改动。

## Acceptance criteria

### I-AC01: 执行语义保持且收集模式无测试副作用

用最小嵌套用例证明父到子 setup、子到父 teardown、hook 与探针失败语义未变。
对收集入口设置计数及资源观测，证明测试函数和 hook 均未调用，
且导入、声明及输出过程没有创建测试 fixture 或启动 Host。

### I-AC02: 输出同源且文档错误明确可见

用固定树及故障输入验证三种输出的节点、顺序和稳定标识一致，
Markdown 命令块保留格式，HTML 不执行说明中的脚本。
缺失引用、重复键和无效字段返回明确诊断，而不是悄悄省略内容。

### I-AC03: Check Host 自动化与路径手册一致

运行接入后的代表性 E2E 路径和仓库既有相关检查；核对生成手册的前置操作、
探针及清理与树中注册顺序一致，命令和检查说明足以独立操作。
故障注入后的预期故障状态不被写成测试失败，平台不适用项明确标注。
