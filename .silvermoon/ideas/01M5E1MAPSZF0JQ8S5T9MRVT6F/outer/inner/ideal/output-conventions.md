# CLI 输出规范化方向

本文是 Ideal World 的规范方向，与[问题清单](./output-findings.md)共同说明预期结果，不预设渲染框架或详细实施任务。

## 统一但不抹平领域语义

| 输出类型 | 面向人的必要内容 | 保留的差异 |
| --- | --- | --- |
| 列表 | 查找范围、便于扫描的身份/描述/来源、显式空态 | Objectives 的 scope 和 legacy 语义不等同于 Agent profile 覆盖 |
| 详情 | 明确标题和所选身份、关键属性、来源、必要的长内容分区 | schema、表达式和配置可用代码块/原文 |
| 写入/迁移 | 实际动作结果、目标、范围、产物路径，必要的备份/后续步骤 | 原子保存、编辑器交互和迁移安全边界不变 |
| 观察 | Objective 身份、观察是否成功、当前位置、缺口、引用和适用下一步 | 观察成功不等于 terminal；局部指导来自 Pilot |
| 调节/继续 | 运行 ID、目标/当前位置、结束原因、关键额度或停滞信息、恢复入口 | 各类 stopReason 保持真实领域含义 |
| 监督 | 计划/执行模式、目标和队列摘要、待处理/失败原因、结束边界 | 周期正常结束不等于所有目标已达成 |
| 诊断 | 实际检查范围、关键来源、冲突或就绪结果、可执行定位方法 | 初始化、认证和真实修复能力是不同证明 |
| 帮助/错误 | 当前有效参数、互斥/必需约束、准确示例；问题对象、原因、恢复提示 | 不把外部调用失败自动归成内部崩溃 |

## 展示规则

- 默认仍面向人类，与显式 Markdown 使用同一内容规则。优先使用简明、稳定的标题和分区；列表可选表格或条目，不强制所有命令都用同一种布局。
- 同类动作、结果、来源、范围和退出原因使用一致术语；自然语言完整、单复数正确。只保留有内容的分区，统一空行和结尾换行。
- 关键失败、冲突和未完成状态在第一屏摘要中可见，不能要求切换 JSON 才能知道结果。长 schema、路径、表达式和配置不应挤占列表摘要。
- 空态是正常可识别结果，说明范围及适用下一步；不存在与歧义必须区分，不给无法奏效的 scope 建议。
- 帮助只推荐可执行的受支持命令；总帮助、操作帮助及 JSON help 的参数事实一致，默认值和互斥关系不能互相矛盾。
- 不新增隐式分页、TTY 自动改格式或交互 TUI。非 TTY 可读性、窄终端、Unicode、ANSI 和 Markdown 特殊字符应有独立验证，不假定已经覆盖。

## 机器与原文出口

- `--format json` 应输出可独立解析的结果；成功、空态和失败的边界均明确，不混入标题、进度或人类建议。解决 edit 静默分支，并明确编辑器/Agent 自有输出的处理。
- 既有管理、观察、调节、监督 envelope 的字段、schemaVersion 和含义默认保持；需要新增字段时说明消费者影响，需要破坏性改动时另定迁移方案。不同领域不强制统一 schema。
- stdout/stderr、退出码、错误类别和未知参数处理属于可消费契约；先定义并评估兼容性，不能借美化偷偷修改。现存不规范情况应显式决定保留、增补或迁移。
- 配置原值、补全脚本、命令发现元数据、Objective check/runtime envelope 和报告文件是有意的机器/原文出口，按各自契约保留。不向脚本或原值添加人类标题。
- 迁移器的输入类型与显示格式必须可区分，保留原参数；成功反馈与产物内容分离。输入不变、拒绝覆盖和 pinned evidence 不重写仍是安全边界。
- 保留脱敏，不因增加摘要、来源、错误原因、完整帮助或运行记录而暴露凭据或敏感会话正文。

## 可观察验收

以[421 次调用的矩阵](./output-coverage.md)和[24 项问题](./output-findings.md)为基线，逐项明确处理结果及回归证据；不以“加了一个 format 参数”或“输出不是 JSON”作为完成证明。

验证默认/Markdown/JSON、成功/空态/错误、主入口/独立入口；对随机 ID、时间、备份名和运行历史做明确定义的归一化。具体断言包括关键身份、状态、来源、原因、下一步和流归属；JSON 用解析器和字段契约断言，补全脚本与原值做不被污染的断言。

对本轮未覆盖的真实 Agent 权限、取消、认证、POSIX、交互 TTY 和安装产物，实施/交付阶段再提供针对性证据；准备阶段不把合成 fixture 冒充端到端生产验证。
