# Deployment

## Steps

### D-S01: 验证安装后的阅读与脚本体验

按现有分包安装方式在隔离目录使用候选包，验证 pguide 分派、独立命令和迁移器的人类结果、帮助、错误、非 TTY 重定向及 JSON 管道；固定协议入口按其契约验证。只使用安全 fixture，另行明确需要真实终端/Agent 的验证条件。

本次交付边界是已同步 primary 的候选 tarball 及其隔离安装结果，不是 npm 发布。先同步本契约及[使用说明](./Usage.md)，再从该候选源码构建、打包并安装到独立消费者；验证不借用 workspace 模块或全局 pguide。保留包摘要、实际输出、退出码和原文/协议例外的证据。

### D-S02: 说明兼容边界

向使用者说明输出规范、JSON 与原文/协议边界，以及经明确决定的任何流或行为迁移。若需要发布，遵循现有分包发布流程并另行获得发布授权，本 idea 不授权 npm 发布。

交付[使用说明](./Usage.md)，明确默认人类输出、普通 CLI 的 JSON 选项、迁移器的文档类型/回执选项、未知 validate 参数现在被拒绝，以及完整仓库仍存在的独立 Supervisor 测试失败；不把候选消费通过表述为真实 Agent、远程环境或 npm 发布通过。

## Acceptance criteria

### D-AC01: 安装产物行为符合约定

用候选安装产物复现实测矩阵中的代表性成功、空态、错误和写入场景，保留样例及执行结果，证明统一内容在主入口与独立命令均生效、JSON 可解析，协议出口未被人类展示污染。

### D-AC02: 使用者可识别兼容边界

可交付说明准确区分普通 CLI 的 `--format json`、迁移器类型参数、配置原值、补全脚本、命令元数据和固定协议。任何兼容性调整都有明确说明，以文档和安装验证记录为证据。

## Evidence

[候选包交付验证](./Deployment-verification.md)记录先同步的契约、打包源码、10 类隔离消费者、35 条 CLI 捕获、13 个私有协议包装器、21 个 tarball 摘要、验证器修正及实际输出。[使用说明](./Usage.md)已作为面向使用者的兼容边界说明同步。此证据不代表 npm 发布或完整仓库全绿。
