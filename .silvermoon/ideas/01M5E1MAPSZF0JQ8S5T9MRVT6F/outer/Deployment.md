# Deployment

## Steps

### D-S01: 验证安装后的阅读与脚本体验

按现有分包安装方式在隔离目录使用候选包，验证 pguide 分派、独立命令和迁移器的人类结果、帮助、错误、非 TTY 重定向及 JSON 管道；固定协议入口按其契约验证。只使用安全 fixture，另行明确需要真实终端/Agent 的验证条件。

### D-S02: 说明兼容边界

向使用者说明输出规范、JSON 与原文/协议边界，以及经明确决定的任何流或行为迁移。若需要发布，遵循现有分包发布流程并另行获得发布授权，本 idea 不授权 npm 发布。

## Acceptance criteria

### D-AC01: 安装产物行为符合约定

用候选安装产物复现实测矩阵中的代表性成功、空态、错误和写入场景，保留样例及执行结果，证明统一内容在主入口与独立命令均生效、JSON 可解析，协议出口未被人类展示污染。

### D-AC02: 使用者可识别兼容边界

可交付说明准确区分普通 CLI 的 `--format json`、迁移器类型参数、配置原值、补全脚本、命令元数据和固定协议。任何兼容性调整都有明确说明，以文档和安装验证记录为证据。
