# Implementation

本契约为准备阶段的轻量种子，细节在构想就绪后展开；不是实施已获批准的记录。

## Steps

### I-S01: 统一定义和引用契约

确定 URI 后更新定义结构、类型与校验，以及声明、Portfolio、嵌套快照和恢复记录中的目标引用；保留观察角色和来源证据职责。

### I-S02: 贯通入口和显式迁移

同步资源入口、作者文件、生成模板、运行时副本、工具和文档；普通读取拒绝旧格式，迁移保留原始数据并明确报告不支持的输入。

### I-S03: 验证观察与恢复行为

用有效、非法、旧格式及跨格式引用样例验证离线校验、观察和固定来源恢复；避免只验证字段替换而漏掉实际调用链。

## Acceptance criteria

### I-AC01: 新契约一致可消费

通过类型检查、结构/语义测试及生产者到消费者的集成测试，证明新定义及全部目标引用一致，不改变检查与推进语义。

### I-AC02: 旧格式拒绝且可迁移

反例覆盖旧入口与字段，迁移用例证明显式转换保留业务含义，失败时不损坏原始数据或替换来源。

### I-AC03: 包与定义保持一致

打包和独立消费测试证明 schema 随包可用，URI 标识映射一致；执行仓库要求的相关检查。
