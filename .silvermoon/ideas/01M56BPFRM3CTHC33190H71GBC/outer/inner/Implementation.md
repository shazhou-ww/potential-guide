# Implementation

## Steps

### I-S01: 核对 AHP 接入与能力边界

核对官方规范、目标 VS Code 版本及可用 Agent Host 入口，确定客户端连接、认证、会话与权限模型；明确 AHP 与现有 ACP 适配的差异和最低支持能力。

### I-S02: 接通配置与执行恢复链路

复用既有 Agent 接入边界，将 AHP 配置、完整观察上下文、执行结果、取消与会话恢复接入 Regulator 及其 CLI 调用链。仅在确有需要时调整共享配置和恢复记录，不让核心依赖 VS Code。

### I-S03: 补齐协议验证与使用说明

增加 AHP 协议交互和失败路径测试，覆盖共享调用链的 ACP 回归，并更新配置、恢复与支持范围文档。

## Acceptance criteria

### I-AC01: AHP 闭环可验证

自动测试证明 AHP Agent 收到完整修复上下文，执行结果映射正确，完成后必须重新观察而非直接相信 Agent 自报成功。

### I-AC02: 生命周期与故障明确

自动测试证明真实协议会话标识被保存和用于恢复，超时与取消传递到受控执行；断线、恢复失败、认证或能力不足明确报错，不静默降级。

### I-AC03: ACP 兼容且检查通过

既有 ACP 配置与执行恢复回归测试通过，新增 AHP 配置示例与限制说明完整；执行相关测试及仓库要求的 pnpm check 并保留结果。
