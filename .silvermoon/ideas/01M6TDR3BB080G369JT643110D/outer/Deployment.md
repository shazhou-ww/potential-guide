# Deployment

## Steps

### D-S01: 在隔离调用环境消费真实结果

使用实际构建并可读取的 Check Bundle，在独立调用方运行通过及未通过案例，观察节点上的文档引用。

以已接受实现 `5a1684d75ee92720a76daa3e0b0cf1e7abcb4c61` 为代码基线，隔离安装其打包产物，消费三个环境检查的真实 CAR。另用相同标准作者流水线生成双语言 text 检查的 A/B 两个文档版本。不使用内存文件映射替代外部读取：启动本次验证独占的离线 Kubo，导入 CAR，并由调用方通过实际 IPFS 读取接口或本地网关查阅文档。

### D-S02: 验证按需读取与不可用行为

让调用方仅凭单独传递的 result 或 problem，选择声明语言并读取对应文档；验证多语言、版本隔离及文档不可用时的显式错误。将可复核证据保存在本世界的支持文件中，不发布 npm 包或修改共享服务。

调用方不得读取文档索引或按 code 拼接引用；分别复制 result 与 problem 后消费其完整 URI。使用明确不可用的文档读取端点证明错误可见，并比较读取前后结果不变。所有运行数据、Kubo 配置和临时服务均归本次验证所有，结束后停止独占进程并清理临时输入，不改变现有共享 Kubo、全局命令或用户配置。

## Acceptance criteria

### D-AC01: 独立调用方能够直接查阅

以真实执行结果与读取记录证明，通过和未通过结果的检查文档、各 problem 的问题文档均可直接定位，且全部声明语言可选，无需查询 code 索引。

### D-AC02: 版本与故障可复核

以两个文档版本的隔离读取及不可用案例记录，证明旧结果仍定位原版本，文档读取错误明确可见且原检查结论不变。
