# Implementation

本契约为准备阶段的可调整初版，实施需在构想验收后开始。设计依据见 [上下文目标设计](./ideal/Context-objectives.md)。

## Steps

### I-S01: 定义声明与上下文绑定

实现严格声明校验、固定 revision 解析、技术栈无关的上下文与 JSONata subject 投影，明确 checkout 身份、路径与来源证据。

### I-S02: 接入 CLI 发现与运行入口

为目标列举、选择、probe 和 regulate 复用统一绑定逻辑；保留直接 Pilot 调用与别名注册行为，恢复使用原绑定而非重新发现。

### I-S03: 验证依赖组合与更新文档

结合依赖问题协议验证跨目录实例、版本和 Supervisor 交接，补齐普通仓库、子目录与 monorepo 示例及相关测试。

## Acceptance criteria

### I-AC01: 声明和实例绑定可验证

定向测试覆盖根目录、无包清单目录、多 checkout、JSONata 和 schema 错误；证明无隐式继承、技术栈假设或跨实例错误合并。

### I-AC02: CLI 行为一致且可恢复

集成测试证明发现不执行检查或 Agent、声明入口与直接入口绑定一致、输入和版本冲突显式报错、继续运行保持原始绑定。

### I-AC03: 依赖闭环与既有行为通过验证

依赖协议就绪后以集成测试证明多目标交接和重新观察；执行 pnpm check，保留直接调用及授权边界；协议尚未就绪时明确阻塞，不增加替代兼容链。
