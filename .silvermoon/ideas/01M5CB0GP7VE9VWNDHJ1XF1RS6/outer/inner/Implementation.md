# Implementation

## Steps

### I-S01: 确定命令与依赖边界

盘点七个待拆命令、已有 config、共享辅助代码及业务引擎的依赖，确定独立包归属和必要共包理由，并明确主包保留能力。

### I-S02: 拆分包并贯通分发与安装

迁移业务入口和相关代码，复用共享 CLI 协议，更新工作区、构建、测试、发布配置及安装迁移文档，避免经共享模块重新引入全部业务依赖。

### I-S03: 验证兼容性与安装组合

补充包边界、按需安装、缺失与冲突诊断及独立入口测试，验证 Windows 与 POSIX 分发路径，并执行仓库要求的检查。

## Acceptance criteria

### I-AC01: 包边界可核验

全部业务命令有明确归属；通过包清单、构建产物和依赖图证明主包不再强制安装全部业务能力。

### I-AC02: 命令兼容性有回归证据

通过现有及新增测试证明两种入口的参数、输出协议、退出码和缺失或冲突诊断符合约定，覆盖最小安装与组合安装。

### I-AC03: 仓库与文档保持一致

`pnpm check` 通过，包构建及打包检查通过；安装、迁移和包级发布文档与实际清单一致，并记录验证结果。
