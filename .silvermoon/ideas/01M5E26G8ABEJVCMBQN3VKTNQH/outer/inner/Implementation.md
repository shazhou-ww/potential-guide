# Implementation

## Steps

### I-S01: 落实设置存储与 package 描述

按最终准备结论实现文本解析、两级作用域、完整 ID 浅合并、来源展示和配置描述发现，复用现有配置入口，避免核心集中枚举扩展类型。

### I-S02: 接入配置消费者与显式迁移

接入核心和扩展命令的自有配置校验，明确 regulate、continue 和 supervise 的共享设置消费；更新读写、帮助、文档及旧格式拒绝诊断，提供旧 YAML v2 到新配置的手工迁移说明，不新增主配置自动迁移命令，不混回独立 Agent 或 Objective 资源。

### I-S03: 验证配置契约与行为保留

以定向测试覆盖覆盖规则、默认处理、扩展归属冲突、未知设置、错误隔离及授权边界，并运行 pnpm check。

## Acceptance criteria

### I-AC01: 扩展配置不依赖核心枚举

以独立扩展测试证明新增 namespace 和设置无需修改核心全局类型，归属冲突明确失败，普通配置编辑不会自动执行任意扩展。

### I-AC02: 覆盖与错误行为符合契约

通过测试证明项目同名值整体替换用户值，数组不拼接、对象不深合并，默认值不暗中恢复被替换的用户字段；消费的非法值明确报错，无关扩展的语义错误不阻断无关命令。

### I-AC03: 旧配置迁移与消费者行为可验证

通过按手工迁移说明构造的前后配置样例及消费测试验证既有值、独立资源及信任边界的保留，并测试旧格式拒绝和新旧并存诊断，特别核对 supervise 的共享设置；定向检查和 pnpm check 通过，不能以重跑通过掩盖未解释的失败。
