# 建立 package 自有的可扩展主配置契约

## 问题

当前 YAML v2 主配置由核心集中定义，独立扩展无法自行增加设置；复杂值的归属、覆盖和描述发现缺少统一契约。

## 结果

建立用户级、项目级的可扩展设置模型，由 package 独立声明和校验自身设置。配置规范见 [Configuration.md](./Configuration.md)，现状、字段映射和源码依据见 [Settings.md](./Settings.md)。

## 边界

- JSONC 为唯一新主配置格式；顶层完整 setting ID 按 key 浅合并，项目同名值整体替换；namespace 按 package 功能后缀约定并显式声明，冲突明确失败。
- Agent 定义和 Objective 声明保持独立；保留凭据、授权及跨组件消费边界，旧格式显式迁移，不发布 npm。
- 部署须全局安装本机迭代后的 pguide 本地 build，并手工迁移本机用户级配置；准备阶段不操作设备配置。

## 验收标准

- 独立扩展可增加自有设置，无需修改核心全局配置类型；归属、发现及诊断有明确规范。
- 作用域覆盖、默认值、校验和旧格式处理无歧义，既有配置行为的保留或变化可验证。
- 本机全局命令可使用新配置，迁移保留原有效值及独立资源，且不扩大授权。
