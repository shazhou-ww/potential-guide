# Deployment

## Steps

### D-S01: 安装迭代后的本机全局构建

部署阶段确认准确的已验收实现 revision，使用当前隔离 worktree 的本地 build 全局安装 pguide 及其命令入口。核验入口实际解析到该构建，不读取或复制原工作目录的未提交文件，不发布 npm。

### D-S02: 手工迁移本机用户级配置

先在设备本地备份并核对实际用户配置，再按已确认的旧格式迁移规则手工迁移；只操作明确的用户级配置，不默认迁移项目配置或重建已独立的 agents.yaml、objectives.yaml。核对默认 Agent、模型、工具权限、执行及 probe 预算等原有效值，禁止隐式授权扩大。备份和秘密值不得进入仓库或证据文档。

### D-S03: 验证全局入口与迁移结果

从全局入口运行配置校验、诊断及必要的非破坏性消费验证，对迁移前后有效值与来源逐字段比较；确认独立 Agent、Objective 资源仍可使用，记录脱敏证据及可恢复条件。

## Acceptance criteria

### D-AC01: 全局命令使用目标本地构建

通过全局入口解析位置与构建 revision 的核对证明 pguide 及其命令包装使用已迭代的目标构建，不依赖原工作目录的并发修改，也没有 npm 发布。

### D-AC02: 本机配置手工迁移保持有效行为

以本机校验、逐字段比较和独立资源检查证明用户级配置按新契约生效，默认 Agent、模型、权限及各类预算保留；本次未批准的配置变化明确失败或停止，不静默采用新默认。

### D-AC03: 部署证据脱敏且可恢复

以非破坏性全局命令验证、来源检查与本地备份存在性证明部署结果和恢复条件，不提交设备秘密或配置原文。
