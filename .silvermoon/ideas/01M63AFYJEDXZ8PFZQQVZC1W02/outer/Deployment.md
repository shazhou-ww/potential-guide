# Deployment

本阶段验证已验收 Inner `51adbc160975b8287373ddc8eca0e27abb74a95a` 的独立交付，
不发布 npm、不迁移业务、不修改已验收源码。先同步本合同和 `verify/` 脚本并观测准确
deploymentRevision，再运行该版本的证明；结果保存到本世界的 verification-result.json
及 verification.md。未完成的场景不借用源码单测冒充外部通过。

## Steps

### D-S01: 验证独立进程内消费者

在仓库外安装打包产物，用独立的非制品任务类型装配引擎，
不启动 HTTP 也能完成提交、观察、结果读取与取消。
`verify/run.ps1` 在仓库同级创建随机、带独占 marker 的实际消费者安装目录，
安装四个本地 tarball（仅 file: 依赖，离线、禁用安装脚本、独立 store）。
`core.mjs` 先只导入安装后的核心/协议，通过包名解析；禁止 NODE_PATH、loader、
源码及 workspace 链接。断言所有模块 realpath 位于该消费者目录而不在仓库内，
并验证无 TCP listener。保存四包 SHA-256、版本和解析路径。

### D-S02: 验证宿主挂载与恢复

由测试宿主自行监听端口并挂载适配器，使用公开协议调用；
验证身份隔离、错误、订阅断连和真实进程重启下的查询/取消/递归语义。
使用真实本地 SQLite 文件跨进程恢复，不以复用同一内存实例代替持久交付验证。
`host.mjs` 显式在 loopback 随机端口监听，把 Node request/response 桥接到 Web handler。
仅用本次生成的认证令牌，不读设备配置；就绪通过 IPC 地址与真实 HTTP 响应双重确认。
虚拟 Clock、Promise 闸门与 Worker ready/exit 握手控制业务时间及回收，不靠 sleep 猜测。
`suite.mjs` 经真实 HTTP/SSE 验证固定水位、断连续读、权限、结果及进程中断；
有 Execution final 但尚无 Task 裁决、未知已启动、未来未启动三组数据在同一真实库重启。
另一个进程尝试 claim 同库，重启时保留原版解释器，并单独验证移除原版明确失败。

### D-S03: 形成可复核交付证据

保存产物摘要、场景输入与脱敏结果，说明未覆盖限制；
停止操作拥有的服务并清理临时资源，不发布、不合并、不标记来源 idea 已完成适配。
脚本保存断言结果、子进程退出、Worker 物理退出和端口不可再连接的证明。
finally 只删除 marker 与本次随机 identity 一致的明确消费者目录，不扫描/清理其他目录，
不修改全局配置。发现生产缺陷立即保留脱敏失败证据并向父代理报告，不自行改 Inner。

## Acceptance criteria

### D-AC01: 核心可独立嵌入

安装消费者无需引用仓库源码或具体制品业务，即可运行公开 API；
报告可证明不存在自动监听端口或强制 HTTP 往返。

### D-AC02: 外部行为与契约一致

独立客户端复核内驱 stage、canceledAt 与时间条件的独立投影、类型冲突、共享需求隔离、
原节拍递归、历史读取与重启边界，结果与进程内语义一致。
验证时间到点不虚构阶段转移；调用方到期放弃等待后仍可查询未取消任务的迟到完成，
结果同时保持超时判断，不把时间失约等同于没有结果。

### D-AC03: 证据完整且资源收束

摘要与已安装产物一致，故障和限制如实记录；
验证后进程退出、端口释放，不遗留凭据或未授权发布动作。

## 验证场景清单

这些是本轮外部证明计划；实际执行结果另记。完整的事务故障注入、不可用清理隔离及
所有排列的同时替换竞态仍以已验收 Inner evidence.md 为深入证明，不把它们计为
本轮外部场景。外部独立验证下面每类业务结果、恢复和资源边界。

| 归属 | 外部场景 | 需保存的证据 |
|---|---|---|
| D-AC01 | 仓库外安装准确 tarball，宿主注册非制品类型并直接运行 | 产物摘要、模块解析路径、输入/结果；无源码链接、HTTP 或制品业务前提 |
| D-AC02 | 宿主挂载标准 Web handler，经 Node 连接层请求及 SSE 订阅 | 实际 HTTP 请求/响应与关闭记录；认证、挂载路径、断连不取消任务成立 |
| D-AC02 | 控制执行结束在 deadline 前后，继续查询与接收通知 | 按时与迟到结果都真实可见，超时可与 completed 并存 |
| D-AC02 | Executor 前置判断快速返回未执行，随后业务显式再请求 | 首次正常结束且未做重业务，无等待解锁/自动重试；新请求独立处理 |
| D-AC02 | 同 Series 多项已 eligible、一个未来 Task，旧轮超时后迟到终结 | 唯一 Pending 而非唯一 Active；每轮前后继关联不重复，原节拍保留 |
| D-AC02 | 真实进程中断并重启，持久记录分别有结果和无结果 | 有结果不丢，未知执行以专用码失败且未透明重跑，未开始任务恢复原期限 |
| D-AC02 | 重开同一 SQLite 数据库并重发已提交 Request | 幂等身份、事件及后继关联一致；数据库不可用明确失败，不静默使用空内存库 |
| D-AC02 | 取消共享 owner、历史读取与分页/重连 | 作用域隔离、取消冻结、其他 owner 不受影响；按已收敛游标契约续读 |
| D-AC03 | 停止宿主、客户端与操作拥有的执行资源 | 进程退出和端口释放，报告未确认清理/未覆盖项，不以发送停止信号冒充已回收 |
| D-AC02 | 单引擎注册多种 TaskType，编排任务等待子任务 | 类型正确分派，子任务资源可用，无自 HTTP 递归调度；实际回收与 Task 结局分别可复核 |
| D-AC02 | execute 耗尽 Pool 后排队、撤销等待、共享执行 | 等待期间无虚假 running，共享不重复启动，撤销不丢 tracking，清理确认后才复用 |
| D-AC02 | 注入 TaskType，分别提交两种 executionMatch 和非法业务输入 | 同一引擎分组与时间匹配一致；非法输入不占 Executor，策略只在 Request 保留 |
| D-AC01 | 恒等 prepare 与有实际准备工作的非制品 TaskType | 均调用必需 prepare 并返回合法 Prepared，纯 Validator/Equals 不强制 Schema 库 |
| D-AC02 | 未注册 Check 的宿主，Executor 前置判断抛错或正常不满足 | 无内置检查依赖；正常业务结果和 execution_failed 可区分，Pool 清理并恢复容量 |
| D-AC02 | 保存旧类型版本数据，升级宿主后重开 SQLite 并查询/重放 | 使用原契约解释历史；原版解释器缺失明确报错，原始数据不被改写 |
| D-AC02 | 第二进程试图对同库启动引擎，随后客户端历史分页及 SSE 断线续订 | 主动所有者唯一，固定水位分页和续读无丢失；过期位置明确报错 |
| D-AC02 | Pool 被占用直到等待 Task 超时后才释放 | 过期请求不新启动；开始竞争中 tracking 不丢失，其他有效请求仍可运行 |
| D-AC02 | 独立消费者以旧 executionId 授权替换无有效需求的失控执行 | 确认旧进程/隔离单元退出再启动新 ID；有空闲不回收，受保护或无用候选不被误杀 |
