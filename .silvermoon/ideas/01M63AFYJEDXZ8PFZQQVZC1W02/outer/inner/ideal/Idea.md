# 构建类型无关的任务调度与执行生命周期引擎

## 问题

任务生命周期与 Check、Probe、Regulate 业务语义混杂，扩展任务类型容易复制调度逻辑。
从[来源 idea](../../../../01M61G3GCGWGHGA8VHG16WCNZ5/outer/inner/ideal/Idea.md)派生本 idea，
作为其业务适配与集成的前置依赖；该关联是设计来源，不是 Silvermoon 的新增生命周期事件。

## 结果

交付可嵌入进程的通用引擎库及可选挂载的 HTTP 适配器，使业务类型共享一致的调度、取消、
事件与恢复语义。定义分见[系统边界与模块](./system-boundaries.md)、
[关键概念与生命周期](./concepts.md)、[接口与数据示例](./interfaces.md)。

## 边界

- 引擎不依赖 Checker/Objective 或 Coordinator；宿主提供任务类型、权限策略、执行器和存储。
- HTTP 适配与核心分离，不自行监听端口；持久恢复不等于任意副作用 exactly-once。
- 本 idea 拥有通用契约，来源 idea 拥有业务适配；不包含独立服务器产品、分布式集群、制品业务迁移或正式发布。

## 验收标准

- 无网络、无制品依赖的测试任务可通过核心 API 完成调度与取消，新增测试类型无需改动内核分支。
- 事件重放与时间投影一致，取消冻结、期限、原节拍递归、需求隔离和持久恢复可用确定性场景验证。
- 进程内与 HTTP 调用遵守同一契约，类型/权限/载荷错误显式可见，独立消费者可复核结果。
