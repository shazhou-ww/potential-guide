# 关键概念与生命周期

本文定义[通用任务引擎](./Idea.md)的概念、约束与待决问题。
它是新设计的直接定义，不是现有运行时已具备这些能力的声明。

## 1. 对象与身份

| 概念 | 定义 |
|---|---|
| Request | 不可变的调用意图，必含 requestId 与类型判别字段 type；解析或准入失败可不产生 Task |
| Task | 一次已受理需求，独立 taskId，拥有有效时间约束、过程事实与取消/终结裁决 |
| Execution | 实际工作及其结果，一个执行可服务多个被允许共享的 Task |
| Series | 递归需求的关联身份；默认首个 Task ID，后继继承；不是一个永不终结的 Task |
| 任务类型 | 宿主注册的具体输入和行为契约；type 字段是通用的，字面值集合属于应用组合层 |
| 条件 | 调用方声明的启动前提；被求值的业务谓词，不是某个 Task 结束的默认别名 |
| 事件事实 | 已发生且可审计的事实，有固定归属与稳定读取位置 |
| Snapshot | 事件事实的一致视图按技术时间投影出的有界读取结果，不是可独立修改的存储真相 |

公共生成型身份使用规范 ULID，类型名与业务名称可读，digest 不充当 ULID。
HTTP 的 Idempotency-Key 表达 requestId；进程内 API 直接接收完整实体。
幂等比较包含 type 和实际意图；同一幂等身份换 type 是冲突，不新建另一类 Task。
类型、调用作用域及原始省略语义应可恢复；请求查询不把默认值反写到原始输入。

## 2. 三个推动力：设计原则

Task 的变化由三个相互独立的推动力解释，不把它们压成一个互斥状态枚举：

| 推动力 | 来源 | 表达方式 |
|---|---|---|
| 第一推动力 | 引擎自身推进 | preparation、readiness、allocation、execution 的过程事实与内驱 stage |
| 第二推动力 | 外界信号 | 例如取消生效事实 canceledAt；不作为内驱 stage |
| 第三推动力 | 时间流逝 | eligibleAt、deadlineAt 与观察/有效完成时间的比较；不是到点事件或内驱 stage |

第一推动力的状态树只描述引擎过程，不包含 pending、cancelled 或 timed_out。
三个维度平行记录、组合解释：时间条件可以约束引擎动作，外界信号可以停止推进，
但到点本身不是引擎已经开始或结束工作的证据。对时间/信号采取清理等动作要另有事实，
不能把“应该停止”“已发送停止信号”或“已过期限”当成实际停止。

超时仅表示引擎不再承诺按期限满足需求，不代表必然没有结果。允许超时后继续观察到
正常完成；completed 与 timedOut 可以同时成立。调用方到期可以放弃等待并按超时处理，
也可以继续接收迟到完成通知；如何接受或忽略迟到结果由调用方决定。引擎不能保证会有
迟到结果，但不能仅因超时丢弃真实完成事实或把它冒充按时完成。

UI 状态标签和公共查询辅助函数应基于这些维度投影，不反过来定义持久事实。
不能用一个 isFailed/isTerminated 或优先级枚举混淆执行失败、期限失约与实际结束。
具体函数形状仍需收敛；本原则不意味着新增重复持久化的 pending/timedOut 布尔值。

## 3. 时间约束与内驱推进

Task 受理时形成 receivedAt、有效 eligibleAt、deadlineAt。
eligibleAt 默认等于 receivedAt，也允许早于或晚于它；timeoutMs 的锚点是 eligibleAt：

```text
deadlineAt = eligibleAt + timeoutMs
时间条件满足 = t >= eligibleAt
```

到点不要求单独的 eligibility 过程或事件。时间可改变投影，不可伪造工作开始事实。
时长必须有限且满足协议约束，时间运算溢出须显式拒绝，不能退回无限预算。
等待准备、条件和资源都消耗同一预算；重试、恢复或取消不能刷新旧 Task 期限。
pending 是时间上的派生值，而非 stage：观察时刻尚未到 eligibleAt。调度槽位还须
排除已取消或实际结束的需求，不能只比较时间就认定它仍需要推进。

尚无有效完成事实时，以服务端观察时间判断是否超期；已有有效完成事实时，以完成时间
和 deadlineAt 比较，后续查询时间不能把按时完成变成超时。完成晚于 deadlineAt 可同时
被认为已完成且超时。有效时间来自引擎可靠记录、经校验且适用于本 Task 的结果事实，
不是执行器任意回填的时间，也不是内部稍后处理到该结果或返回 HTTP 的时刻。
其他实际结束原因及取消的时间组合、恰好等于 deadlineAt 的边界仍列入实施前决策。

### 内驱判定树

```text
preparation
├─ 未准备好 → preparing
├─ 最终失败 → preparation_failed
└─ 可用
   └─ readiness
      ├─ 未满足/求值中 → blocked
      ├─ 最终失败 → readiness_failed
      └─ 满足
         └─ allocation
            ├─ 等待资源或执行机会 → queued
            ├─ 最终失败 → allocation_failed
            └─ 实际执行
               ├─ 进行中 → running
               ├─ 执行故障 → execution_failed
               └─ 正常完成 → completed
```

树只解释无外部控制时的内驱位置 stage，不是所有实际转移组成的严格树。
各过程允许重叠；已满足的门限可跳过，不伪造过程开始/通过事件。
条件 false 是等待，不是求值故障；正常业务结果“不满足”仍是 completed。
类型适配器的临时失败是否重试由明确政策决定，不能直接把所有异常转成最终失败。
空条件集合直接满足，不强造 readiness.satisfiedAt。
尚未进入内驱过程时显式为 stage:initial，不省略 stage。initial 只表示引擎尚未推进，
与是否到达 eligibleAt 无关；到点后若仍未推进就仍为 initial，不能自动写出 preparing。
initial 是非终结内驱位置，可与时间等待、超时或 canceledAt 分别组合；初始取消后
冻结为 initial，不伪造准备事实。引擎实际推进后才进入由事实支持的后续位置。

### stage 与多维投影

Snapshot 不输出独立 state；内驱位置、外部取消及时间边界分别保留：

```text
内驱位置 = 引擎事实所支持的 stage（尚未开始时为 initial）
外部取消 = canceledAt 所记录的事实
时间等待 = 观察时间尚未到 eligibleAt
期限判定 = 有效完成时间（未完成时为观察时间）与 deadlineAt 的比较
```

initial/preparing/blocked/queued/running 是非终结内驱位置，completed 和四种过程失败表示内驱结局。
pending、cancelled、timed_out 都不是 stage。未知 stage 或非法组合明确报错。
超时不产生互斥内驱结局、不自动设置 canceledAt 或 timedOutAt；允许 running 且超时，
随后 completed 且超时。按时完成的 Task 在未来查询仍是按时完成。
是否停止逾期工作、如何释放执行需求及结果保留窗口是独立政策，未在本轮定案；
任何政策都不能将已产生的迟到结果虚构为未发生或按时发生。

### 前置条件是减少无效尝试的门槛

前置检查由业务方派发，重试及何时重查也由业务方负责。引擎不自动创建条件 Check
Task、不轮询或重试检查、不派发治理；业务提交 Check Request 后由引擎内置 Check
支持执行，从可追溯 Task/Execution 结果中校验并采用证据，不接受任意 passed 写入。
证据须对应当前 Request/Task 的条件，并来自本 Task eligibleAt 之后发生的检查；
不能直接沿用前一递归轮次的通过结果。采用一次符合约束的检查通过即可解锁。

不定义 TTL、排队失效或执行前强制重查；时间流逝本身不撤销通过证据。条件不成立
时保持等待，检查故障不得冒充通过，业务方可自行决定再检查。Executor 不得假设
执行时条件仍成立；条件不是锁、租约或资源保证。空条件直接满足，不生成虚假的通过事实。
已解锁后不回退 stage，后续检查不通过不撤销已采用的通过事实。检查关联接口、
顺序判定与权限仍需收敛；执行能力注入和 allocation 见
[执行与宿主组装](./execution-and-host-composition.md)。

## 4. 取消与实际执行

全部非终态 Task 可取消，不限于 pending 或 eligibleAt 之前。
取消请求到达不等于取消生效：核心以一致事实边界原子裁决，成功后记录 task.canceled。
canceledAt 是生效时间；stage 按当时的内驱事实计算并冻结，不沿用客户端旧快照。
未到 eligibleAt 也能取消，此时不能为了记录取消而补造 pending 或准备过程。

取消后：

- Task 投影保留取消边界已有的过程和执行事实，stage 不再随时间或执行结果变化。
- timestamp 仍表示本次读取的技术时间；不复制 termination.terminatedAt/lastStage。
- pending 取消后不占 pending 槽位，running 取消后不再作为活跃执行需求 owner。
- 共享 Execution 可继续服务其他 Task；最后 owner 释放时尽力停止，不保证可中断或回滚外部副作用。
- 迟到的执行完成只进入 Execution 历史，不让取消 Task 得到成功 result。
- 重复取消返回原事实；已由其他原因终结则明确冲突，不覆盖结局。

完成、过程失败与取消的互斥裁决仍需一致的事实边界。超时从这一互斥集合中移除：
它本身不是 task.terminated，不禁止后来完成。完成/取消同刻如何仲裁仍待确认，
不能仅按客户端时间或事件名称排序。外部控制在判定树之外，但在事实模型之内。
Task 取消不是取消整个 Series；治理依赖的取消传播由业务所有权规则决定，不靠进展字段自动推导。

## 5. 递归系列

recurrence 使用正周期 periodMs 及显式 anchor；本草案示例不依赖尚未决定的默认锚点。

| anchor | 规划时机 | 后继 eligibleAt |
|---|---|---|
| eligible | 本轮资格被处理时消费一次规划权，不等准备或业务成功 | 原节拍上严格晚于本次规划时刻的第一个点 |
| terminated | 本轮正常完成、过程失败或超时触发续作；取消不触发 | 正常终结为 terminatedAt + periodMs；超时锚点时间及延迟处理选点仍待明确 |

eligible 模式设本轮 e、周期 P、规划时刻 t >= e：

```text
nextEligibleAt = e + (floor((t - e) / P) + 1) * P
```

错过多轮不补历史 Task、不重置旧轮预算；e=10:00、P=60 秒、t=10:05:20 时取 10:06，
恰好在 10:06 规划则取 10:07。已规划过后继不因旧轮后来超时重新选点。
后继是新的 Request，经正常准入产生独立的新 Task；二者分别有新 requestId/taskId，
继承类型、seriesId、合法业务输入及递归策略，不修改旧 Request。条件声明可继承，
通过证据必须重新满足后继自己的 eligibleAt 约束。

同系列最多一个尚未到 eligibleAt、未取消且未实际结束的 Task，即有效时间等待槽位。
此条件按同一事实边界和观察时刻计算，不再检查 stage 或互斥 state=pending。已有该项时保留旧项，
冗余新项记录取消事实。原子规划不能先覆盖旧项再回滚。
Pending 仅指上述派生时间等待概念，不是 stage，也不是 Active 的同义词。
到 eligibleAt 后退出该槽位，即使 Task 仍在 initial、preparing、blocked、queued 或 running。
因此同 Series 可有多个已 eligible 的未完成 Task；不采用“同 Series 最多一个 Active”
约束。并发执行和已 eligible 积压由独立容量政策控制。
eligible 锚点仍可在本轮到点被处理时安排后继，不等待当前轮退出 Active 或实际完成。
取消撤销尚未消费的规划权，不因取消再生后继，也不回溯取消已建立的后继。
读取/reduce 重放不执行规划副作用，命令重试与恢复不能重复生成同一轮。
超时已确认触发 terminated 模式的后继规划，但不会因此产生实际 task.terminated 事实。
每个前驱轮次最多规划一次后继，以持久化的前驱/后继 Request/Task 关联或等价唯一记录
保证；“规划权”只是此约束的称呼，不要求引入另一种公共实体。
规划决定、准确后继 Request 身份及幂等准入必须具有可恢复的原子关联；中途崩溃后
继续同一后继，不新建另一轮。若命中已有 Pending 槽位，保留旧项并记录本次去重处置。

只看最新结果时间戳或当前 Pending 槽位都不足以证明已规划：例如 A 超时后生成 B，
B 已到 eligible 而释放 Pending 槽位，此时 A 迟到完成/失败不能生成 C。
迟到事实仍正常记录和通知，但不会再次消费同一轮的规划。取消不续作，且不撤回
已经建立的后继。Pending 槽位负责限量，已规划关联负责去重。

## 6. 事件、投影与所有权

```text
F(W) = reduce(一致边界 W 内的必要事件)
Snapshot(W, t) = project(F(W), t)
```

W 包括目标 Task 和它引用的必要 Execution 事实，不是按 occurredAt <= t 随意拼装。
同一前缀、投影规则及 t 产生相同结果；允许 checkpoint 加后缀替代全量重放。
reducer 不运行任务、不访问网络、不读取当前可变配置、不创建新 Request。
stage 是内驱事实的投影，canceledAt 是固定事实；时间条件用同一 W 与 t 派生。
纯时间流逝不产生 stage 转移或伪造终结事件；取消时使用当时边界而非最新共享执行结果。

通用事件目录：

| 事件 | 所有者与事实 |
|---|---|
| task.created | 有效身份、时间与必要的不可变请求引用 |
| task.preparation.started / completed / failed | 准备过程事实；完成记录可包含类型定义的内部准备结果 |
| task.readiness.evaluated / satisfied / failed | 外部条件证据的校验/采用或最终故障，不表示引擎派发了检查 |
| task.allocation.bound / failed | 正式绑定执行或最终分配故障 |
| execution.started / progress / completed / failed | 实际执行生命周期及业务载荷 |
| task.terminated | 非取消的实际终结裁决，成功引用 Execution 结果；不代表 deadline 到点 |
| task.canceled | 外部取消生效及冻结位置 |
| task.updated | 派生快照通知，不是 reducer 输入事实 |

类型业务载荷由协议校验，引擎限制有限 JSON、序列化字节数、资源和可见范围。
业务字段不能覆盖外层身份/时间/type，不因出现 childTaskId 或 requirements 就自动治理。
共享执行结果只存一份；Task 的 result 由执行事实与本 Task 的成功终结裁决投影。
事件身份/位置用于重复投递处理，不按相同时间戳或相同 payload 去重。
分页、订阅交接和历史保留必须显式定义；历史缺失不得伪装为空结果。
迟到完成仍进入 Execution 事实，并可投影为未取消 Task 的超时完成及通知。
时间到点的派生通知也不是 reducer 事实；若已实际采取停止/清理动作，须记录该动作
而非把时间条件冒充执行故障。先前查询的超时不被后来的正常完成“撤销”。

## 7. 一致性、权限与恢复

准入幂等、终结裁决、系列占槽和规划权消费需要存储端口提供明确的原子边界。
类型代码只能报告事实/结果，不能直接修改 snapshot 或任意提交终结事件。
存储承诺的成功受理必须可在其声明的持久范围内恢复；内存模式须显式说明不能跨进程恢复。
业务回放和调度恢复分开：先重建事实，再由协调器按已确认政策恢复工作。
本地持久参考 Store 采用 SQLite，核心仍仅依赖抽象 Store 端口。需要共同生效的事件、
幂等记录和后继关联以数据库事务原子提交；提交失败不能报告成功受理。
内存 Store 用于测试及显式非持久模式，不能静默代替不可用的 SQLite。

第一版在 start 时自动恢复事实和未开始执行的调度，不对所有任务新增“恢复等待”状态。
已可靠记录 Execution 完成/失败、仅 Task 尚未处理到结果时，按已有事实补齐，
不能误报中断。已记录 started 而无可靠结束结果的 Execution 则以专用错误码
execution_interrupted 记录不可恢复故障，并让其尚未终结或取消的相关 Task
进入 execution_failed；共享 owner 基于同一中断事实处理，恢复重试不得重复失败或规划。
既有结束/取消事实不改写，尚未实际开始的任务按原身份和时间约束继续调度。

该错误表示无法可靠交付本次结果，不证明业务操作没发生或外部进程已停止。
不自动重跑、不提供本轮必须实现的外部执行重新关联协议。业务方决定是否显式创建
新的重试请求，并承担重复副作用的判断；已声明 recurrence 的后继仍按原系列政策
独立规划，不把后继冒充对旧 Execution 的透明重跑。

同进程身份也必须经核心授权，不以“内部调用”为理由绕过访问边界。
共享兼容至少受类型、执行版本、业务输入/上下文与权限域约束；
未声明支持共享的类型不能仅因相同输入复用带副作用的执行。
大载荷、错误详情、关联 Task 查询都遵守来源作用域，业务 ID 不是访问凭据。

### 实施前决策

1. **三维边界：** 恰好等于 deadlineAt 的期限判定、完成/取消同刻仲裁、失败/取消的时间
   投影，以及替代单一 deriveState/isFailed/isTerminated 的查询接口。
   初始位置为 initial、pending/timed_out 不属于 stage、超时可完成已确定，不重新开放。
2. **前置 Check 接入：** 内置检查契约、条件与 Check Task 的可信关联、顺序/时间边界。
   业务触发和重试、引擎执行、eligible 后通过解锁、不回退 stage、不设 TTL 已确定。
3. **恢复实现边界：** 未知执行以 execution_interrupted 失败、不自动重跑已确定；
   开始调用与持久事实的崩溃窗口、未开始过程的恢复和清理/资源隔离仍需落实。
4. **存储与流：** SQLite 已确定；驱动/事务与耐久配置、跨 Task/Execution 读取边界、
   保留、分页水位与 SSE 续读仍需落实。
5. **类型演进与资源：** 类型契约版本、准备结果保留、共享兼容标识、容量满时的明确处置。
