# Implementation

实施候选计划；范围见[构想](ideal/Idea.md)、[讨论与授权](ideal/Discussion.md)及[已收敛约束](ideal/Research.md)。由主 Agent 完成准确 Ideal 修订的门限后，委派一个子代理实施；遇到实质阻塞再请求用户决定。

## Steps

### I-S01: 收敛声明与迁移契约

核对全部注册类型与历史绑定，在共享协议层实现有资源边界的 Schema 编译、校验和独立结构投影判等；用自由对象、字典、引用、重叠分支和非法形状证明明确语义。区分进入 prepare 的业务一致性检查及必须保留的提交前边界。

### I-S02: 接入共享机制与发现协议

接入引擎与 HTTP 的受控类型发现、契约修订前置条件和历史身份检查；迁移内置类型、服务启动校验、夹具、打包消费者、例子和文档。Check/Probe 使用新版本，不保留作者 validate/equals 双轨接口，不实现 UI 或资产管理。

### I-S03: 验证兼容与行为边界

补充直接相关的协议、Schema、授权、历史和执行共享回归测试，运行 pnpm check；主 Agent 检查等价关系、敏感数据拒绝和版本竞态的实证，不把不支持的旧契约当成功。

## Acceptance criteria

### I-AC01: 声明与生成行为一致

以代表性有效/无效输入、对象与数组判等、默认值和复杂 Schema 测试证明唯一输入契约及明确错误；分别验证 Validate 的合法性检查与 Equals 的结构比较，覆盖额外字段和不符合 Schema 的比较输入，资源限制不被绕过。

### I-AC02: 发现结果可信且受控

以 HTTP 与注册配置测试证明实际类型、版本与 Schema 对应，授权隔离有效，不泄露凭据或依赖浏览器硬编码；普通 object 输入不要求资产查询来补足契约，类型发现不解析或下载业务 URL。

### I-AC03: 执行语义与迁移可复核

以幂等、历史恢复、Prepared 共享、取消和版本差异回归证明保留不变项及显式迁移行为；以摘要冲突场景证明已确认的准备失败时机，并验证提交前敏感数据边界未被延后；pnpm check 通过，文档对应候选。
