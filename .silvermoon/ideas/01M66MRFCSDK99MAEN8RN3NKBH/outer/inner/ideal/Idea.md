# 声明 Task 输入 Schema 并公开类型发现能力

## 问题

Task 类型目前通过 validate、equals 函数描述输入校验与判等，外部工具无法发现输入结构，自动表单和其他契约消费者缺少可信依据。

## 结果

在 Task 类型定义层以声明式输入 Schema 替代作者提供的 validate、equals，由共享机制生成校验与约定的判等能力，并通过受控公开协议发现服务注册的类型及输入契约。来源、既定方向与待定规则见[讨论依据](Discussion.md)。

## 边界

1. Equals 按 Schema 结构生成比较逻辑，不承担 Validate 的合法性校验，也不推导任意业务等价关系；完整比较规则与历史兼容须明确，不静默改变幂等或执行共享语义。
2. 不削弱 Prepared、环境、scope、资格时间及制品授权约束；不以静态输入 Schema 替代制品 subject 校验或运行时检查。
3. 不实现 Web UI、资产管理或全局资源遥测；通用消费者只依赖公开输入 Schema，不以前置资产查询或自动解析业务 URL 补足字段。只记录准备材料，不构成实施或发布授权。

## 验收标准

1. 类型作者只维护一份输入 Schema，生成的校验与判等具有可验证的一致语义，非法或不支持的契约明确失败。
2. 获授权消费者能发现实际可提交类型及相应版本的输入 Schema，无需硬编码业务类型，也不暴露服务端实现或凭据。
3. 以代表性类型、历史绑定及共享/取消回归场景证明迁移边界清楚，UI 表单能力不反向缩减任务契约。

## 下一步

依据[迁移调研](Research.md)收敛剩余比较规则与兼容边界；已确认职责分离及业务一致性检查进入 prepare，仍不开始实施或提交验收。
