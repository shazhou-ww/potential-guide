# Deployment

## Steps

### D-S01: 独立消费迁移后的检查制品

在作者源码之外的隔离消费环境，通过标准流程检查 CAR，导入调用方管理的 IPFS 节点并固定 CID，向运行中的 Task Engine 提交三个检查。记录实际使用的提交、工具版本、CID 和可用环境；不发布 npm 或代管生产服务。

### D-S02: 验证实际结果与结束状态

使用受控工具、目录与本地网络端点分别观察通过和不满足要求的结果，验证取消和故障不伪造检查结果，并确认资源释放；记录消费者操作证据。

## Acceptance criteria

### D-AC01: 独立环境可按 CID 执行

三个 CAR 无需作者源码或旧 Host 即可被独立 Engine 消费；用实际请求、Run 身份、CID 和最终状态证明，不能仅以构建成功替代。

### D-AC02: 消费者结果与资源行为符合契约

实际结果保持 `{pass:true}` 或非空问题列表，执行异常进入失败，取消不会生成业务失败结果；以观察记录和物理释放证据验证，无可用环境时明确报告阻塞而非声称通过。
