# 将环境检查迁移到最新 Task Bundle 脚手架

## 问题

`check-environment` 已交付 Task Engine 可执行的三个 Bundle，但仍手动生成声明并调用低层构建接口，未采用最新 `task-bundle init` 作者流程。检查结果共性也仍局限在包内，缺少是否值得共享的明确结论。

## 结果

先让环境检查使用标准脚手架、类型化契约和显式 `runTask` 入口构建交付，保持现有检查行为；基于实际迁移调研共享结果契约与回调工厂的必要性。

## 边界

- 保留 tools、directories、network 三个独立 Bundle、现有库 API 与结果格式。
- 不恢复旧 Check Host，不修改通用 Engine 协议，不增加另一套专属构建流程。
- 共享 Check 封装只做调研，不预设新包或将其实施纳入本次迁移。

## 验收标准

- 三个检查可通过最新作者流程构建 CAR，并由 Task Engine 按 CID 执行。
- 通过、发现问题、执行故障和取消行为保持兼容，现有 Objective 库消费者不受影响。
- 有基于迁移证据的共性封装建议，明确共享契约、回调职责与非目标。
