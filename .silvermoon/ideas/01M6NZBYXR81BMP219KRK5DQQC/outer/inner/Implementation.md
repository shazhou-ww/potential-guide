# Implementation

## Steps

### I-S01: 核对标准脚手架与迁移边界

实际调用 `task-bundle init` 检查最新模板，对照环境检查的构建、契约、库消费者与回归测试，确定三个独立 Bundle 的作者文件布局。参考 [作者流程](../../../../../packages/pguide-task-bundle/README.md) 和 [环境检查](../../../../../packages/check-environment/README.md)。

### I-S02: 迁移环境检查作者入口

使用标准构建配置、TypeBox 契约和显式 `runTask` 入口取代手动声明生成；保留现有库导出与交付引用需求，同步直接相关文档和测试。

### I-S03: 验证兼容性并调研共享封装

验证业务结果、故障、取消与清理边界，记录统一结果契约和回调工厂的收益、类型推导及依赖方向。仅形成建议，不新增共享 Check 包。

## Acceptance criteria

### I-AC01: 标准作者流程交付三个 Bundle

使用标准命令构建并检查三个 CAR，验证各自 CID 与目录树一致；不依赖包内第二套声明生成器。

### I-AC02: 检查与库消费者行为兼容

用环境检查库测试、Engine 集成测试和相关消费者检查证明原结果格式、超时失败、取消及物理资源回收未退化；提交前运行 `pnpm check`。

### I-AC03: 共享封装结论可追溯

在主体世界记录基于实际代码的建议，明确结果契约、回调输入输出、错误与取消传播、日志及清理责任；不以新增 SDK 作为本次验收前提。
