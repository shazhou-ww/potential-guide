# Implementation

## Steps

### I-S01: 核对标准脚手架与迁移边界

实际调用 `task-bundle init` 检查最新模板，对照环境检查的构建、契约、库消费者与回归测试，核对 [分包结构草案](./Package-structure.md) 中的三个独立 Bundle 作者布局、共享包公共 API 和依赖方向。参考 [作者流程](../../../../../packages/pguide-task-bundle/README.md) 和 [环境检查](../../../../../packages/check-environment/README.md)。

### I-S02: 提取共享 Check 包并迁移环境检查

提取独立可复用包 `@potential-guide/check-sdk`，统一结果类型与 Schema、结果组装及传给 `runTask` 的回调工厂，并维护公共 Reference。共享作者校验器按唯一的语言与问题码声明，对每种语言的 Check 定义页和全部问题页执行构建硬门禁，并检查最终 CAR。环境检查消费共享包，使用标准构建配置、TypeBox 契约和显式入口取代手动声明生成；为三个检查维护多语言说明和问题码 Reference，以标准 include 打入各自 Bundle。保留现有库导出与交付引用需求，同步直接相关文档、包分层和测试。

### I-S03: 验证兼容性与新检查复用

验证业务结果、故障、取消与清理边界，并以不同于环境检查的最小作者示例证明新检查可复用公共契约和回调。共享包不得将执行故障或取消转为普通问题；日志仍走 Task Context，具体资源由业务实现清理。

## Acceptance criteria

### I-AC01: 标准作者流程交付三个 Bundle

使用标准流程构建并检查三个 CAR，验证各自 CID 与目录树一致；核对声明语言与各语言的 Reference 定义页、完整问题码覆盖和制品内相对链接，不混入其他检查文档。以缺语言页、缺问题页、空文档、未知问题码、坏链接及 CAR 漏选的负例证明构建失败，完整单语言、多语言和零问题码声明通过；不依赖包内第二套声明生成器。

### I-AC02: 检查与库消费者行为兼容

用环境检查库测试、Engine 集成测试和相关消费者检查证明原结果格式、超时失败、取消及物理资源回收未退化；提交前运行 `pnpm check`。

### I-AC03: 独立共享包可被新检查复用

环境检查与最小新检查均从独立共享包引用契约和回调适配，不复制结果 Schema 或组装逻辑。以类型检查、共享包单测和标准脚手架构建执行测试证明；共享包不依赖具体检查包，通用 Task SDK 不引入 Check 业务规则。
