# Deployment

用户已明确启动端到端推进。本契约在实现同步并由父会话接受后执行；不授权发布、
付费 Agent、生产或真实设备变更。各阶段验收由父会话独立决定，本会话只提交候选。

## Steps

### D-S01: 准备版本确定的独立消费环境

固定源码与交付产物，准备不依赖开发工作树隐含文件的环境，按各 Pilot 的实际加载方式验证资源和运行时供应。

使用完整 commit 固定的 Git 源及打包安装的 pguide 消费端；目标 Pilot snapshot 不安装
依赖、不执行构建。验证四个 package 的 manifest、References、协议入口与生成资源完整。

### D-S02: 逐个验证真实 Pilot 入口

经真实 pguide 加载、发现和 process probes 验证各正式 Pilot 的正反例及适用的修复闭环；涉及远程设备、Agent、费用或权限时先满足既有授权条件。

monorepo 验证隔离正反例、层次阻塞与修复到 terminal，subject 不提供 checkerModule。
setup/self-check 只使用无凭据、无模型费用的受控 ACP fixture，验证真实 marker 修复及
失败/授权/清理边界；不把 fixture 当作真实账户或远程机器验证。health 在本次独占的
本地 Linux Docker 容器验证真实五层检查、四栈编译与失败恢复，复用已有验证器。

### D-S03: 核验入口迁移与外部证据

核验历史入口兼容或迁移说明可执行，记录准确版本、结果与限制；不得因 package 化宣称线上部署、npm 发布或真实身份资源已经验证。

## Acceptance criteria

### D-AC01: 交付单元可以独立消费

每个 Pilot 在声明的消费方式下可定位正确 manifest、References、执行入口和依赖；以隔离消费实测证明不借用旧 Objectives 主体或开发机偶然路径。

### D-AC02: 各 Pilot 的真实行为保持

真实调用证据覆盖各 Pilot 的有效与无效输入、检查顺序和适用终态；有副作用的行为须遵守原有同意、权限、预算及清理边界，未授权验证不得记为通过。

### D-AC03: 迁移与限制可复查

准确版本、调用路径、兼容/迁移结果和未验证边界均可复查；观察操作不产生合同以外的目标修改，不执行未经授权的发布、部署或设备整备。

持久证据记录源码 commit、消费包版本、运行方式、逐项真实结果、清理结果及明确未验证项；
Windows 上的 Linux 前提拒绝不是 health 终态证明，单元测试通过也不替代真实入口证据。
