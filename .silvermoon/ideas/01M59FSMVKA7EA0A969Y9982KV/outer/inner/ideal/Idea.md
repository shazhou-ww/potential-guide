# 将现有 Objectives 迁移为完整 Pilot packages

## 问题

目前 Objectives 的定义、检查实现、共享运行时和构建接线分散，部分检查集中在大脚本中，难以作为一致、可独立验证的交付单元维护。

## 结果

本项目全部现有正式 Objectives 均以完整 workspace package 组织，统一其架构规范，并保持现有功能、检查语义和信任边界。具体范围与规范见 [architecture.md](./architecture.md)。

## 边界

- 一份 Pilot 对应一个 package；内部按检查职责模块化，不把每个 check 独立成包，不要求公开 npm 发布。
- 本次是架构迁移，不扩展检查业务范围、不削弱失败与授权条件；不默认建立 examples 目录。
- 当前仅准备并记录方案，未经后续明确指示不开始实施。

## 验收标准

1. 全部现有正式 Objectives 均完成 package 化，无旧目录中并行维护的第二套主体；内嵌测试 Pilot 有明确归属。
2. 统一规范覆盖资源与代码归属、模块职责、依赖、构建与运行交付边界，并落实到各 Pilot。
3. 经真实入口验证迁移后的资源加载、检查结果及适用的终态/失败行为；历史入口有明确兼容或迁移说明，不能以单元测试替代交付验证。
