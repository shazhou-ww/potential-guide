# Implementation

以下为规范评审材料的准备初版，不授权产品运行时改造、数据迁移或发布。
历史 Schema/HTML 作为来源留存，当前活动目录与未决项分别维护。

## Steps

### I-S01: 刷新活动格式与规范来源

按当前源码、机器 Schema、Axis 和独立子 IDEA 核对活动格式，列出生产/消费方、开放范围、所属规范及已有决定；旧 Portfolio/Host 和历史 HTML 明确归档，不恢复旧入口。

### I-S02: 记录剩余承诺与验证边界

逐项收敛尚未明确的稳定性、离线读取、旧/未知格式和诊断输出承诺；已经实现的 URI、配置和扩展所有权只引用当前规范。记录待决事项、负责人和验证方式，不由本次评审自动修改运行时或发布定义。

## Acceptance criteria

### I-AC01: 契约与归属一致

通过目录/来源及链接对照，证明活动格式均有归属，公共契约、配置、内部存储与诊断分开；配置扩展不被主程序全局枚举，历史子项接受不冒充本 IDEA 整体完成。

### I-AC02: 当前承诺与待决问题可区分

以规范对照和现有样例审阅证明 URI、冻结、离线及旧/未知格式规则有明确来源；未决项不会成为默认兼容、自动迁移或新的公共承诺，不同时维护冲突的当前规范。
