# 规范化公共数据契约与 schema 边界

## 问题

历史格式目录仍混有已退役 Host/Portfolio、已落实的配置与 Schema 决定，以及尚待分类的输出；旧目录容易被误读为当前协议或新的兼容承诺。

## 结果

刷新活动数据格式目录，分开记录当前规范、已退役历史和真正待决项，明确公共格式、配置、内部持久化及诊断的归属与承诺；当前目录与历史讨论见 [Schemas.md](./Schemas.md)。

## 边界

- 不因数据可见或带有版本字段，就将其归入 Pilot 核心协议。
- 公共格式沿用已确定的项目 Schema URI 和 `$schema`，不重开已落实的域名/发布位置；Axis 契约按显式 frozen 标记判断冻结，版本号、已发布或 IDEA 接受均不等于冻结。其他格式按其所属规范分别确认，不一律套用 Task 协议。
- 本轮仅做目录和规范评审，不据此迁移数据、发布 Schema 或修改运行时。旧 Task 域按当前契约明确拒绝并原样保留，不自动清空、转换或重演；显式迁移必须另有具体授权。

## 验收标准

- 活动目录中的格式均有生产/消费方、分类、规范来源及稳定性边界，退役对象与历史 HTML 不冒充现状；配置保留独立扩展所有权。
- Schema URI、离线校验、旧/未知输入和冻结规则按所属格式明确，内部存储、生命周期 revision 与日志 sequence 不被混成一个版本。
- 未决项说明需要的具体决定和验证方式；已实现子项引用其规范与证据，不因子 IDEA 接受推导本总 IDEA 完成。
