# 单次执行授权与正常阻塞

## 职责和信任边界

用户授权主会话指挥子会话并裁决三个门禁。实现分为协议无关领域与调度、ACP/CLI 接入两条子会话；主会话整合并执行安装和真实有限验证。

管理员通过可信配置规定权限上限，coordinator 在此范围内选择本次授权并形成不可变 run 快照。planner 只接收需求和结果，不得生成、修改或批准授权。Agent 请求也不是凭证。

MVP 默认拒绝。优先采用明确的权限规则标识引用，不把请求自带规则当成有效 grant；执行型规则必须明确授权确切操作，不把 shell 前缀或 cwd 当成隔离保证。文件规则应拒绝歧义、越界、符号链接逃逸及多路径请求中的未授权目标。

ACP 只能裁决 Agent 发出的请求。Agent 启动参数可能预先授权操作，而任意恶意进程也不受 ACP 机制约束；本功能不能宣称为操作系统沙箱。验证不得使用 allow-all-tools、allow-all-paths 等选项绕过请求。

## 状态与恢复

quota 与 permissions 分离。正常返回新增 authorization-required，携带已规范化的授权需求和最后可信观测；原有 exhausted、prerequisite-unmet 和 target-reached 保留。

一次拒绝后 Agent 仍可尝试授权内的替代路径。完成本次调用后重新观测，已达标或有真实推进不能直接误报授权受阻；无法推进且仍有未满足授权需求时，才以授权受阻结束。取消和真实执行故障保留独立通道。

即使本次调用恰好达到 maxAgentRuns 或 maxStallRuns，重新观测确认的无进展授权阻塞也优先返回 authorization-required；只有时间中断等无法完成正常观测的情况仍可返回 exhausted 并保留未解决申请。真实 Copilot 验证中发现的这一优先级已补入回归。

coordinator 的阻塞判定使用实际授权与执行计划身份，不以新队列序号或普通优先级变化当成重新许可。有效授权变化或明确计划更新可以重新排队并先观测。权限撤销必须影响后续执行，不能由持久化旧 ceiling 重新授予。

请求应答有时间边界；只选择 Agent 提供的有效选项，默认允许一次而非永久授权。日志和结果保留原因，不记录凭据，且不能依赖解析模型错误文本猜测授权。

## 接入与验证

库、进程 worker、单次 CLI、continue 和 supervisor 使用一致的授权语义，旧配置默认不增加权限。ACP handler 的既有底层机制复用，不另造并行协议。

安装验证使用严格 ACP 测试进程：无 grants 时拒绝并返回 authorization-required，增加 ceiling 内的限定 grant 后可修复，撤销后不可由旧记录恢复授权。

真实验证使用本机已有认证、当前实际可用 Copilot 运行时，创建独占目录和临时显式配置，取消启动参数中的预授权，验证真实请求的拒绝和有限授权后的执行。保留检查结果，清理资源，不改变用户默认权限。不修改旧 setup Objective 的无换行验收定义来掩盖失败。

真实 Copilot 的 apply_patch 权限请求不是同一工具调用事件的原样复制：请求中 rawInput 可为 fileName 与 unified diff，locations 单独列出路径。适配器必须解析并交叉验证这些目标，不能仅信任 fileName 而忽略差异中其他文件。
