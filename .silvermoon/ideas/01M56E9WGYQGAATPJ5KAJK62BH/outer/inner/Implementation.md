# Implementation

## Steps

### I-S01: 定义执行授权与正常阻塞契约

在现有 regulation 输入与结果模型中定义权限上限、本次授权和结构化授权需求。保持额度耗尽、前置不满足、执行异常、取消与授权受阻的独立语义；明确如何识别无法继续，而非将每次拒绝直接终止。

### I-S02: 接通 ACP 与调度反馈

复用已有 ACP permission handler，接入明确、默认拒绝的策略及安全事件；coordinator 根据授权和执行计划的有效变化恢复调度，planner 接收申请但无审批权。联动配置、持久化、continue 与进程边界。

### I-S03: 验证迁移与真实接入

补齐拒绝、允许一次、替代路径、等待超时、取消、重复请求、旧结果隔离及恢复测试；更新直接使用、无人值守策略和旧配置迁移文档。

## Acceptance criteria

### I-AC01: 权限范围不能被自行扩大

自动测试证明未知请求默认拒绝、批准选项受原请求与本次范围约束、Agent/planner 不能扩大管理员上限，事件不暴露秘密。

### I-AC02: 授权受阻与续跑正确区分

测试证明 authorization-required 携带结构化需求与可信观测，同授权同计划不反复执行；有效变化可恢复。允许现有授权内的替代路径，不破坏 exhausted 的正常续跑。

### I-AC03: 所有执行入口行为一致

库、CLI、持久恢复、coordinator 和进程运行器遵循同一约定，pnpm check 通过。ACP 严格测试替身证明请求应答，不把模型文本猜测为授权凭证。
