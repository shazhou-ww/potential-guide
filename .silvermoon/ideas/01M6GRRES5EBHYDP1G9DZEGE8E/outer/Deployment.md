# Deployment

准备阶段的外部验证种子。实施验收后使用本地产物、隔离用户配置目录和新数据库验证，
不覆盖真实全局配置，不发布 npm，不接管用户已有 Kubo。

## Steps

### D-S01: 验证独立 CLI 配置使用

从仓库外的消费目录以纯参数、指定 YAML/JSON 和隔离用户全局配置启动服务，
用覆盖参数及不同工作目录检查实际 RPC、端口和数据库定位。

### D-S02: 验证运行与失败后清理

连接独立管理的受控 IPFS 节点，经公开接口执行非敏感测试 Bundle；
验证错误配置、全局隔离和退出行为，关闭本次服务并确认节点未被 Server 停止。

## Acceptance criteria

### D-AC01: 无 JavaScript 配置也可消费

记录独立环境启动命令及公开响应，证明参数、文件、全局及覆盖路径均无需作者编写配置模块，
实际监听和数据位置符合约定。

### D-AC02: 配置隔离与生命周期可核验

以错误退出、Task 成功结果及关闭后的节点探测证明失败明确、服务可停止且 IPFS 独立，
确认真实用户配置与旧数据库未被改动。
