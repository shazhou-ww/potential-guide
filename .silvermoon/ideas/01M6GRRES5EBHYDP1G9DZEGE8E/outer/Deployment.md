# Deployment

准备阶段的外部验证种子。实施验收后使用本地产物、隔离用户配置目录和新数据库验证，
不覆盖真实全局配置，不发布 npm，不接管用户已有 Kubo。

## Steps

### D-S01: 验证独立发现与服务配置

从仓库外消费本地扩展产物，验证 pguide 发现和独立 binary；
以纯参数、指定 YAML/JSON、隔离 pguide 用户 JSONC 及冲突项目文件检查四层规则、
全局禁用、实际 RPC 与数据定位，使用随机端口和新数据库。

### D-S02: 验证可选 UI 与隔离生命周期

分别仅启动 Engine 和带 UI 启动，连接独立管理的受控 IPFS 节点，
经公开 HTTP 执行已有非敏感测试 Bundle；验证本机访问限制、错误配置和退出清理，
关闭本次服务并确认独立节点未被停止，不接管父会话的 Server/UI/Kubo。

## Acceptance criteria

### D-AC01: 扩展服务无需 JavaScript 配置

记录独立安装发现、两种入口启动及公开响应，证明参数、文件、共享用户设置和覆盖均无需配置模块，
无第二套全局目录，项目服务值不参与；实际监听和数据位置符合约定。

### D-AC02: 可选 UI 与资源隔离可核验

以两种启动模式、UI 的 HTTP 消费、非法覆盖值退出、Task 成功结果和关闭后探测证明
服务可停止、失败明确、IPFS 独立；真实用户配置、旧数据库和非本次服务未被改动。
