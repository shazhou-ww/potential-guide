# Implementation

准备阶段的轻量实施种子，尚未开始实现。范围与已确认规则见[配置边界](ideal/Configuration.md)。

## Steps

### I-S01: 定义统一配置与解析规则

核对已有 CLI 配置工具，确定声明字段、全局路径和覆盖细则，
落实参数/YAML/JSON/全局配置的统一校验与来源路径解析，不执行配置代码。

### I-S02: 接入 Server 装配并迁移直接调用方

由有效配置创建 IPFS client 和必要的内置适配，保留程序化注入接口；
更新 help、示例、文档及依赖旧 CLI 的直接测试和验证脚本，旧模块入口明确拒绝。

### I-S03: 验证启动与配置隔离

增加优先级、全局配置禁用、错误配置、路径锚点及真实 CLI 生命周期测试，
执行相关构建测试与 `pnpm check`，区分既有基线问题。

## Acceptance criteria

### I-AC01: 多来源配置可预测

以纯参数、YAML、JSON、全局和混合覆盖矩阵证明优先级与各自路径锚点正确，
配置错误明确拒绝，禁用全局后不会读取其内容。

### I-AC02: 装配不执行配置代码

以带副作用的旧模块拒绝测试证明不执行配置代码；
验证 RPC 地址实际生效，程序化 client/回调注入回归保持，启动失败不遗留服务。

### I-AC03: 直接入口与文档一致

以 CLI/help、示例消费和相关测试证明使用方式一致，保存 `pnpm check` 结果；
不更改用户配置或数据库，不引入 daemon 或 IPFS 生命周期所有权。
