# 配置边界与改造范围

本文件服务于 [Idea](Idea.md)，记录已确认的用户目标及实现需要覆盖的表面，
不表示代码已实现，也不把所有内部回调变成配置字段。
当前核对基线为 `893532280b46e5ac0e2a7c5b9b3bd452b0b0c8c4`。

## 当前问题

- [CLI 入口][cli]仅接受 `--config <trusted-local-module.mjs>`，
  动态导入模块并执行默认 factory，再把返回值交给 `startTaskServer`。
- [ServerOptions][server]要求 `ipfsClient`，并支持授权、Caller 解析、Store、
  gateway 策略、资源关闭等程序化注入。CLI 目前没有声明式装配层。
- [示例配置][example]在 JavaScript 中读取 `IPFS_API` 并调用
  [createIpfsClient][ipfs]；环境变量约定属于该示例，不是 CLI 的统一配置协议。
- Web UI 已有独立 JSON 配置，但本 Idea 不顺带改变 UI 配置或启动它。
  服务连接独立 Kubo RPC，不需要知道 Kubo 可执行文件和数据仓库位置。

## 已确认的行为

### 多种输入与统一优先级

同时支持命令行参数、`--config` 指定的 YAML/JSON，以及自动读取的当前用户全局配置：

```text
命令行显式参数 > --config 指定文件 > 用户级全局配置 > 内置默认值
```

允许仅使用参数启动，或使用文件并覆盖个别字段。解析器的默认值不能伪装成显式参数，
覆盖文件中用户已经设置的值。各来源统一进入配置校验，不保留四套不同合法性规则。

以下表达目标使用方式；完整字段及 flag 映射在实施时统一定义：

```powershell
task-engine-server --config server.yaml --port 3001
task-engine-server --host 127.0.0.1 --port 3000 --database .\tasks.sqlite --ipfs-rpc-url http://127.0.0.1:5001
```

```yaml
host: 127.0.0.1
port: 3000
database: ./tasks.sqlite
ipfs:
  rpcUrl: http://127.0.0.1:5001
```

配置仅描述数据，不执行 JavaScript、模块导入或安装钩子。
旧 `.mjs` 配置必须明确拒绝并给出迁移提示，不能作为隐式回退继续执行。
该变更不取消程序化 API：嵌入者和测试仍可直接传入 client 与回调。

### 路径和用户级全局配置

- `--config` 参数的相对文件路径按调用进程当前目录解析。
- 每个配置文件里的相对路径按该文件自身目录解析；
  命令行里直接提供的相对路径按当前工作目录解析。
  混合覆盖不得把来自全局文件的数据库路径重新锚定到指定文件目录或 CWD。
- “全局”限定当前用户，不是机器所有用户共享，也不是仓库内的默认配置。
- 默认自动读取全局配置；文件不存在可继续使用其他来源和默认值。
  已存在但无效、不可读取的全局配置必须明确失败，不静默忽略。
  显式指定的配置文件不存在同样应报错，不当作可选文件。
- 提供 `--no-global-config` 完全禁用全局配置读取，供测试及隔离启动使用。
- `--help` 说明优先级、路径规则、默认全局配置路径和隔离开关；
  帮助显示不应依赖成功连接 Kubo 或执行用户配置。

全局配置在各平台的准确路径、同时存在 YAML/JSON 时的唯一选择规则，
以及嵌套对象/数组的覆盖粒度需在实施时明确并测试，不能依赖文件枚举顺序或猜测。
不新增未经约定的仓库自动配置层或任意环境变量覆盖层。

### 装配与失败边界

- CLI 读取并校验最终配置，再根据 RPC 地址创建 IPFS client，传入 Server。
  程序化 `startTaskServer({ipfsClient, ...})` 继续保持资源注入方式；
  不要求 Engine 自行寻找节点、读取 Kubo 数据仓库或启动 daemon。
- 未知字段、非法类型/值和配置解析错误明确报错，不返回成功形默认值。
  配置校验应在开放监听、接管数据库等启动副作用前完成。
- 声明式配置不直接序列化 `authorize`、`resolveCaller`、`fetchIpfs`、
  `closeResources` 等函数。实现须核对现有 CLI 必需的认证/Caller 和资源装配，
  选择明确的数据配置与内置适配方案，不用默认为全部允许来掩盖缺失。
  这一项是现有程序化入口到 CLI 的适配要求，不要求扩建新的权限产品。
- 不在版本库保存本机凭据或用户配置；错误、帮助和诊断不能泄漏敏感字段。
- 原示例环境变量如何转换为新的参数或文件配置，必须在文档中交代，
  不把示例历史行为悄悄提升为高于显式 CLI 的隐式优先级。

## 调整表面与证明

| 表面 | 需要调整 | 证明方式 |
| --- | --- | --- |
| Server CLI | 参数解析、文件/全局读取、统一校验与装配；退役执行模块配置入口 | 参数/文件启动与非法输入进程测试，证明旧模块不会被执行 |
| IPFS 装配 | RPC 地址由有效配置确定，CLI 创建 client；程序化注入保持 | 受控 RPC 地址覆盖测试和真实节点消费测试 |
| Server 参数 | 显式映射可声明字段与必要内置适配，保留程序化回调边界 | 对比程序化启动回归；不漏掉已有监听、数据库和资源关闭约束 |
| 全局配置 | 用户级默认路径、禁用选项、存在但无效的错误语义 | 隔离用户目录测试；缺失、损坏、禁用及多来源相对路径矩阵 |
| 覆盖规则 | CLI > 指定文件 > 全局 > 默认；区分省略与显式值 | 同一字段四层取值、嵌套叶子与非法值测试，不将 CLI 默认值当覆盖 |
| 文档与消费者 | README、task-server 指南、CLI help、例子和使用旧 CLI 的验证脚本 | 链接及命令验证，真实独立启动；不能只更新示例而留下模块加载入口 |

实施前核对直接引用旧 CLI 的测试、打包消费和验证脚本，更新必要调用方，
但不改写其他 Idea 的历史证据。优先复用仓库已存在的声明式解析和 CLI 配置机制，
不为本任务引入不必要的配置框架。实现细节不能增加全局配置写入或自动迁移的隐含副作用。

## 非目标与当前状态

不实现统一 daemon、托盘、开机自启、热重载或 Web UI 配置合并；
不管理 Kubo 的启动/停止、IPFS_PATH、pin 或 GC；不改变 Task/Run/Bundle 领域语义。
当前仅准备构想和下游种子，不操作本机已经运行的服务，不修改现有本地配置。
发布命令、安装级配置定位和独立验证可以使用本地产物，不构成 npm 发布授权。
