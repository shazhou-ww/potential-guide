# 声明式配置 Task Engine Server

## 问题

当前 CLI 要求用户提供可执行配置模块并自行创建 IPFS client，把程序化装配变成了普通启动的门槛，
也缺少统一的命令行、配置文件及用户级默认配置机制。

## 结果

让用户通过命令行参数、YAML/JSON 文件和用户级全局配置启动服务，
由 CLI 校验并装配 IPFS client；规则与影响范围见[配置边界](Configuration.md)。

## 边界

1. 优先级为显式 CLI 参数 > 指定配置文件 > 用户级全局配置 > 默认值；路径按各自来源解析。
2. CLI 不执行配置代码；程序化 API 保留 client 和资源注入能力，不把函数塞入声明文件。
3. 不实现 Web UI + Engine daemon、开机自启或 Kubo 生命周期管理，不自动改写用户数据或发布 npm。

## 验收标准

1. 纯参数、纯文件、全局配置及混合覆盖均能以同一校验规则启动，RPC 地址无需手写 JavaScript。
2. 缺失可选全局配置可用默认值，损坏配置和非法字段明确失败；支持隔离全局配置及帮助中定位配置路径。
3. 原程序化装配仍可用，声明式 CLI 的真实启动、停止和错误行为有可重复验证及更新后的示例。
