# Implementation

## Steps

### I-S01: 明确契约与迁移边界

依据[讨论结论](./ideal/Design-notes.md)细化可序列化规格、观测与信封类型，确定 FRP 所有权及旧 API、包和 CLI 的迁移方式；本初版不预选引擎。

### I-S02: 实现观测与收敛效应

实现统一探针、Pilot 评估和 Regulator 修复效应，接通配置变更、取消与日志旁路，保持检查、修复和调度职责分离。

### I-S03: 接通消费入口并验证

按已确认的迁移方案接通相关导出、CLI 和文档，添加协议、生命周期及闭环测试，不扩展 Supervisor 的职责。

## Acceptance criteria

### I-AC01: 协议与职责可验证

通过类型检查及进程、HTTP、内存探针对照测试证明规格可序列化、业务失败不等于调用错误，且 Pilot 不调用 Agent。

### I-AC02: 闭环与生命周期可验证

通过可控时间与可观测 Agent 调用测试证明正常观测不修复、故障不误修复、修复后重探测，以及已确认的热更新、TTL 和取消行为。

### I-AC03: 迁移入口保持一致

通过相关消费者测试及 pnpm check 证明公开 API、CLI、文档遵循迁移约定，未改造的 Supervisor 不被静默破坏。
