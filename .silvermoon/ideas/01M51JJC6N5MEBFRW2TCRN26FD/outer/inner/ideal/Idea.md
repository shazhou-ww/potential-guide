# 将观测与收敛改造为 Pilot / Regulator 函数式模型

## 问题

现有 Guide 实例与命令式调节循环尚不能直接表达可序列化配方、异构探针和可组合观测流。需要在保留目标分级能力的同时，明确纯评估、效应执行及调度引擎的边界。

## 结果

以静态 Spec 与本地运行实例分离为基础，让 Pilot 仅观测，让 Regulator 按观测驱动 Agent 修复；支持统一探针协议、取消传播及运行配置演化。详细理解和待讨论语义见[设计理解](./Design-notes.md)。

## 边界

- 本次只定义 Pilot / Regulator；不重设计 Supervisor，也不在讨论阶段修改运行代码或发布包。
- 业务不合格与调用故障分离；主状态流与旁路日志分离；资源清理由探针负责。
- 保留层级、单前置依赖及多语言文档能力；旧 API、包名与 CLI 的迁移方式待讨论确认。

## 验收标准

- Pilot 不调用修复 Agent；同一业务结果在进程、HTTP 与内存探针下具有相同的观测语义。
- Regulator 的修复闭环、轻重配置切换及取消边界可通过明确场景验证，不由其自行承担 FRP 订阅调度。
- 序列化、版本身份及迁移边界明确；讨论中的关键疑问形成结论后才进入实施。
