# 将观测与收敛改造为 Pilot / Regulator 函数式模型

## 问题

现有 Guide 实例与命令式调节循环尚不能直接表达可序列化配方、异构探针和可组合观测流。需要在保留目标分级能力的同时，明确纯评估、效应执行及调度引擎的边界。

## 结果

以静态 Spec 与本地运行实例分离为基础，让 Pilot 仅观测，让 Regulator 按观测驱动 Agent 修复；支持统一探针协议、取消传播及运行配置演化。详见[设计理解](./Design-notes.md)、[Haskell 概念关系](./Functional-model.md)与[包结构及重点导出](./Package-structure.md)。

## 边界

- 本次只定义 Pilot / Regulator；不重设计 Supervisor，也不在讨论阶段修改运行代码或发布包。
- Check 的业务不合格与调用故障分离；Pilot 汇报当前层级及晋级障碍。资源清理由探针负责，执行冲突与修复任务组织由 Agent 负责。
- 保留层级、单前置依赖及多语言文档能力；允许破坏性迁移，不保留旧接口兼容层，提供 Silvermoon 迁移指导。

## 验收标准

- Pilot 不调用修复 Agent；同一业务结果在进程、HTTP 与内存探针下具有相同的观测语义。
- Regulator 整体汇报观测，按规格限定 Agent 单次执行；按依赖替换效应、先投递取消，不自行承担 FRP 订阅调度或 Agent 任务管理。
- 序列化与版本身份明确，仓库内消费入口同步迁移，并交付可供 Silvermoon 参考的迁移指导。
