# 收敛 latest 发布的 P0 就绪缺口

## 问题

当前完整检查失败，已发布 RC 落后于产品代码，且真实 npm 消费验证拒绝稳定版本；
已有打包成功和旧 RC 证据不能证明当前候选可进入 latest。

## 结果

使当前候选具备可靠的质量门禁、按实际变更选择的版本和覆盖稳定版的消费验证，
明确区分本地候选交付与尚未执行的 npm 发布。

## 边界

- 由 subsession 实施，主会话独立执行所有阶段的检查并按用户委托决定门限。
- 不跳过失败测试、不放宽授权、不扩展 AHP 或 SSH 能力，不改其他 Idea 的契约。
- 不发布 npm、不创建发布 tag、不移动 latest；既有发版暂缓约束保留，真实 registry 发布不冒充已完成。

## 验收标准

- 受支持 Node 环境的完整检查通过，已知超时、调度和测试生命周期失败有可靠回归。
- 当前候选版本及内部依赖与旧 RC 的实际差异一致，逐包分类和发布顺序可追溯。
- 验证支持稳定和 RC，并覆盖只安装入口包的消费者路径；独立安装证明本地候选，
  尚未执行的真实发布及 latest 验收保持明确待办。
