# Implementation

实现决策、精确验证命令与环境恢复记录见 [Evidence.md](Evidence.md)。

## Steps

### I-S01: 明确多来源配置与迁移边界

梳理现有单 Gateway 服务配置、程序化 client 与授权 hint 机制，定义操作者有序多来源配置、
单来源迁移规则及配置优先级；同步 CLI、用户设置、显式文件和关联契约，避免双轨含义冲突。

采用 `ipfsGatewayUrls` 有序完整替换列表（最多 16 项），保留旧 `ipfsGatewayUrl`
作为单项别名；同层同时提供两者报错，较高层任一形式替换较低层全部来源。
`ipfsGatewayTimeoutMs` 是每个缺失块全部来源共享的总预算，默认 30000 ms；
`ipfsGatewayAttemptTimeoutMs` 是单来源预算，默认 5000 ms，实际不超过剩余总预算。
程序化 `createIpfsGatewayClient(string | readonly string[], options)` 保留旧字符串调用，
使用 `timeoutMs` / `attemptTimeoutMs` 表达同一语义。沿用 Helia 的根路径 Gateway 边界，
修正文档曾承诺但运行时不支持的路径前缀；不自动裁剪或改写来源路径。
旧单来源别名同样应用新的单来源预算默认值；需要旧的最长 30 秒单源等待时，
显式把单来源预算设为 30000 ms。总预算仍覆盖读取、内容校验和取消等待。

### I-S02: 实现有界且可观察的来源切换

复用已有 raw-block 获取与内容校验机制，明确来源故障分类、预算、取消和逐块校验边界。
来源选择不改变 CID、缓存身份或历史；错误能说明失败来源，不授权任意 Request URL。

每块按配置顺序尝试，每来源最多一次，不记健康状态、不洗牌；CID 校验失败也可切换。
保留显式 `allowGateway` 授权后的 Request hint 回退，但与可信来源共享同一总预算；
没有策略时完全忽略 hint，不对其发起探测或访问。取消立即终止，失败诊断保留来源与
超时/读取或校验失败分类；不把原始响应正文带入公开错误。

### I-S03: 更新消费走查与回归验证

消费主路径以 Node/npm、精确包组合和预交付 CID/Gateway 为前提，
本地 Kubo 单列可选路径；覆盖不同 shell，不限定发布通道，补齐配置及故障切换回归。

## Acceptance criteria

### I-AC01: 所有配置入口具有一致语义

通过配置/CLI 定向测试证明优先级、URL 校验和迁移规则明确；未授权 hint 不发起网络请求。
证明同时覆盖旧单项覆盖新列表、新列表覆盖旧单项、同层冲突、重复来源和超时参数。

### I-AC02: 故障切换不破坏内容与时间边界

通过可控 Gateway 测试证明首选失败备用成功、全失败、坏块、取消及总预算；
有效内容仍按 CID 验证，错误有来源依据，不用无限重试或成功形状回退。

### I-AC03: 文档和发布包消费者可复现

仓库要求的检查及相关隔离消费者通过；文档明确设备/服务/交付方三类前提，
不以源码工作区依赖或 Kubo 安装掩盖消费所需能力。
隔离 service 消费者通过 npm 安装本地 tarball 精确闭包，再用与三平台文档相同的
纯 Node 验证脚本运行两种命令入口及 user/file/CLI/禁用 user 的故障切换组合。
本地实现证据不替代外部 Pinboard、Linux/macOS 实机或发布版本的 Deployment 证据。
